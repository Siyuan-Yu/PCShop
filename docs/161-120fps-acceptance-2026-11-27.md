# 120 FPS 实测验收与优先修复项状态

后续修复与新一轮测量见 [162 性能续修记录](162-performance-followup-2026-11-27.md)。本文件保留当轮原始结论，不回写为通过。

## 结论

用户明确要求本次实测验收，并核实上一轮优先问题是否已经修复。已执行针对性回归、完整 Game View 巡检及公园／花园 CPU 分段诊断。**验收不通过：尚未达到整个游戏稳定 120 FPS，上一轮的优先事项也没有全部修完。**

分帧睡眠、晕倒和住院的最终存档一致性、重复操作与异常写档保护通过；实际睡眠期间持续出帧，消除了原来的多秒一次性阻塞。但单分钟／跨日峰值仍大，读档仍同步，室外 UI 周期刷新是本次新确认的重要慢帧来源。

继续使用 `art/experiment` 工作区，没有切换分支，没有打包、提交或上传；没有降低建筑、材质、光照、阴影或绿化质量。保留用户原有 Unity 编辑器。

## 实测条件

- Unity 2022.3.6f1 Editor Game View，NVIDIA GeForce RTX 3070，1920×1080，正常镜头；测量时解除帧率上限与 VSync。
- 普通样本使用内部速度 2，即玩家界面的正常 1×；花园加速使用内部速度 8，即界面 4×。与 159 报告的旧速度口径不同，不能直接比较并计算优化百分比。
- 每个普通场景预热 4 秒、采样 60 秒；普通样本各推进约 360 个游戏分钟，4× 样本推进 1,440 分钟；没有混入暂停帧。每例从同一初始存档重新恢复，测试不使用玩家存档。
- 这是固定正常镜头、指定点位的验证；没有完成全地图连续走动、所有天气、满店／多店后期经营和发布包验收。原有编辑器保留，不宣称这是独占硬件实验。
- 普通场景的第一个门槛为平均 FPS ≥120、P99 ≤8.33 毫秒；同时记录超预算比例、最慢 1% 帧平均 FPS 和最长帧。P99 通过不意味着完全没有长帧。

## 睡眠和读档

真实控制器会话在家启动睡到次日 08:00，分帧推进 1,296 个游戏分钟，**约 6.26 秒内持续渲染 755 帧，正常完成**。结算期间平均约 121 FPS，P99 约 36.19 毫秒，最长帧约 156.93 毫秒。因此只确认解决了“整段数秒不出帧”，没有解决结算期间所有慢帧。该结果单列，不混入普通场景 FPS 验收。

读档样本总转换约 **430.67 毫秒**，其中 JSON 解析与 `GameSession.Load` 约 **378.44 毫秒**，`StartSession` 接入已有世界约 **1.46 毫秒**，其余为测试场景位置、视图等准备。其他样本核心恢复约 0.37–0.44 秒。测试使用内存 JSON，不含磁盘读取；与 159 中包含额外序列化的样本不完全同口径，不能声称读档因本轮修复提升了某个百分比。

本轮额外修正 `GameController.Step`：分帧任务完成后只刷新视图和 UI 并返回，与正式 `Update` 路径一致，避免测试驱动在完成帧又推进一次普通时间。真实睡眠样本确认结束时仍为 08:00。

## 公园、花园的 CPU 分段诊断

在完整巡检结束后单独启动诊断，避免回归测试争用 CPU。公园和花园正常速度各采样 30 秒，花园 4× 采样 60 秒以覆盖跨日。使用现有 `PCShop.Simulation`、`PCShop.Views`、`PCShop.UI` ProfilerMarker，记录器有效；这一轮用于定位，不替代上面的完整一分钟验收数据。

4× 样本同时有约 143 毫秒的模拟峰值、75 毫秒的画面同步峰值；需要继续分解跨日结算和人物／场景变化。分帧休息当前以单分钟为原子步骤，无法消除这类单分钟内部的长计算。
