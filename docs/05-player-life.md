# 玩家角色与生活模拟 v0.1

> 状态：草案。数值全部是占位，等有可玩的原型再平衡。标注 `[建议]` 的是我推荐但未明确确认的。
> 来源：用户要求目标/失败"参考东京股神"，并要求有智力、魅力、衣着、精神、饥饿、居住环境这类生活模拟指数。

## 1. 参考：东京股神怎么做目标和失败

信息来自 Steam 页面、媒体介绍和玩家社区，**我没有试玩，细节以实际游戏为准**。

- **目标：** 约 7 年内赚到 800 亿日元；未达成也可以继续玩，但影响结局评价。
- **失败来源：** 资金耗尽、负债过高会被强制清算；压力满了会被送医，生病期间不能交易；做太多坏事会被禁止交易一段时间。
- **结局：** 与财富、声望、道德和选择相关，有"股神"、"隐形赢家"、失败离场等。
- **生活层：** 有压力、健康、饥饿体力这类状态，影响能不能出门、能不能交易；周末可去酒吧、赛马、打牌，结识人脉。

## 2. 我们的目标与失败 `[建议，数值待平衡]`

### 2.1 目标
- 设定一个**限期目标**：N 年内建成电脑乐园（园区落成）。N 先暂定 8 年（360 天为一年），原型阶段再调。
- 未达成可以继续自由经营，不强制结束，但结局评价会降低。

### 2.2 失败
- **资不抵债，无力偿还：** 先有预警阶段（银行催收、停止放贷、被迫变卖资产），给玩家翻身机会；预警后仍无法偿还，进入强制清算，触发失败结局。
- **长期无法行动：** 严重生病住院期间不能行动，此时店铺若无人值守就停摆；住院本身不算失败，但会连带拖垮现金流。
- 没有"死亡"，失败的形式是破产、清算、离场。
- 失败结局后可读档，也可以带着少量继承（成就、图鉴）重开一局。

### 2.3 结局
按多条线索评价，而不是单一财富：
- **首富线：** 资产规模、园区规模。
- **口碑线：** 商誉、员工和客户评价、是否诚信经营。
- **情感线：** 关系网和亲密关系的状态。
- **失败线：** 破产离场。

### 2.4 主线与随机性（用户已同意我的建议）
- 轻量主线：导师、对手、家人几个固定角色，加上随机事件。
- 行情：宏观因子随机 + 少量历史事件模板。

## 3. 角色属性

### 3.1 能力属性（缓慢成长）
| 属性 | 影响 | 提升方式 |
|---|---|---|
| 智力 | 行情研判的信息精度（能读到多深的情报）、学习速度、谈判时识破对方的几率 | 读书、培训课程、阅历（消耗时间和钱） |
| 魅力 | 谈判让价、主播和 NPC 好感、恋爱成功率、客流小幅加成 | 衣着、社交、保养、阅历 |
| 装机技术 | 手操的耗时、失误率、可装配件档次 | 反复手操，由熟练度累积 |

### 3.2 状态值（随世界时钟实时变化）
| 状态 | 变化规律 | 影响 |
|---|---|---|
| 饥饿 | 随世界时间自然下降；吃饭恢复，吃得好恢复多 | 低则效率下降，很低则生病、昏倒，精神也会掉 |
| 精神 | 熬夜、过劳、亏钱、争吵、居住环境差会下降；睡觉、休息、娱乐、社交、好天气会回升 | 低则装机失误率上升、谈判变差、情绪化决策事件增多 |
| 健康 | 饥饿过低、精神过低、居住环境差、过劳会增加生病概率 | 生病要静养，静养期间世界时间照常流逝，不能自由行动 |

- 是否把"精神"拆成"心情"和"压力"两个值：先合并成一个，原型玩出问题再拆。`[建议]`

### 3.3 形象与地位
- **魅力 = 基础魅力 + 衣着加成 + 状态修正**（精神差、饥饿、生病会降低）。
- **衣着：** 衣服有档次和场合属性（日常、谈生意、约会、主播活动）。穿对场合有加成，穿错有惩罚。
- **衣着的美术成本：** 3D 角色真换装需要素材包支持，成本高。1.0 先做"若干套装预设 + 换色 + 配饰数值"，外观套数有限。`[建议]`
- **地位：** 由资产、座驾、住所、衣着档次共同决定，影响谈判和与高人气主播的关系匹配（之前已定）。

## 4. 居住环境

| 档次 | 示例 | 影响 |
|---|---|---|
| 差 | 地下室、合租隔间 | 房租极低；睡觉恢复效率低，精神每天缓慢下降，更容易生病，魅力和地位有负面修正 |
| 一般 | 普通出租屋 | 基本持平 |
| 好 | 小公寓、大平层 | 睡眠恢复更好，精神每日小幅回升，带客户或恋人回家有加成 |
| 极好 | 别墅 | 大幅加成，可举办活动，有维护成本 |

- 居住环境太差会"一直掉"：精神和健康的缓慢下降，是推动玩家改善住所的动力。
- 住所是地产系统的一部分：可租可买，住所的升级和搬家都是明确的阶段性目标。

## 5. 饮食与日常开销

- 饥饿随世界时间自然下降，吃饭会消耗世界时间和钱。
- **吃饭方式：**
  - 便宜的快餐或盒饭：省钱省时，但恢复少、可能影响精神。
  - 小店或餐馆：贵一点，恢复多，吃饭时可能遇到人脉和事件。
  - 外卖（UI 下单）：随时可点，贵一点。
  - 请客：用于社交，提升好感，消费更高。
  - 后期自家餐饮店或自家厨房：便宜或免费。
- **日常开销：** 吃、住、行统一入账，归入"生活"类，和房租、水电一起构成每月固定支出。

## 6. 生存机制不能变成负担 `[重要]`

生活模拟最大的风险是玩家觉得"天天喂角色吃饭很烦"。对策：

- 提供**自动计划**：玩家可设置"每天三餐的标准方式"，到点自动吃，只在想优化时手动介入。
- 睡觉默认自动（夜间回家睡到次日早晨），玩家只在想熬夜时才干预。
- 状态值的惩罚循序渐进，有明显的预警提示，不会无预警突然把玩家送进医院。
- 它的作用是提供"取舍"（时间、钱、精神之间），不是提供"打卡任务"。

## 7. 与其他系统的联动

| 系统 | 联动 |
|---|---|
| 世界时钟 | 饥饿、精神随时间变化；吃饭、睡觉、静养、培训都消耗世界时间 |
| 营业 | 玩家忙着吃饭、睡觉、住院时，无人值守的店照常打烊 |
| 账本 | 生活开销、医疗、培训、衣服统一入账 |
| 关系网 | 魅力、衣着、精神影响好感事件；饭局是社交场景 |
| 事件系统 | 生病、情绪、居住环境、饮食会触发事件 |
| 手操 | 精神和技术影响装机失误率 |
| 地产 | 住所就是一处物业 |

## 8. 技术实现计划（Core，纯 C#，可测试）

- `Stat`：带上下限、变化速率、修正项的数值。
- `Modifier`：来源、数值、持续时间，统一用于衣着、居住、饮食、状态等修正。
- `CharacterState`：智力、魅力、饥饿、精神、健康等，接入 `GameClock` 的 `TimeAdvanced` 区间推进，保证不依赖帧率。
- `Meal`、`Outfit`、`Housing`：数据驱动的定义。
- `LifeEvents`：生病、昏倒、情绪事件的触发条件（接事件系统）。
- 先写测试：时间推进下的饥饿衰减、吃饭恢复、状态组合对魅力的影响、生病触发。
