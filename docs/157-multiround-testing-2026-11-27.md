## 本次范围与结论口径

用户明确授权“根据合适的流程进行多轮测试”。本次在两个隔离镜像中运行测试，保留主项目原有未提交内容和用户正在运行的 Unity 编辑器。没有切分支、打发布包、提交或上传。

执行顺序：全项目基线 → 新功能边界与交叉流程 → 真实 JSON 存读档和多种子模拟 → 实机 UI 回调及截图 → 修复 → 定向复测 → 同一生产脚本快照的第二轮广覆盖回归。摄影邀约测试的等待窗口后来单独按现行规则修订并补测，测试源码指纹与生产源码指纹分开记录。结果不以“重跑到绿色”为准，每一次失败、超时和复测均归档。

## 已确认并修复的问题

1. **班次结束边界的调薪兑现**：新工资原先要等下一次时间推进才生效。现在在旧班次结束的确切时刻更新工资，已开始班次的工资快照仍保留，存读档不会改变本班结算。
2. **采购人员已返回但货物尚未交接时的休假**：原检查只看人员在途记录，可能忽略仍有待交接货物。改用完整交接状态阻止提前休假。
3. **增发稀释后残留董事权限**：持股比例跌破 5% 时清除不再符合条件的董事席位，权限查询和读档恢复也检查实际比例；过半控制权仍按原规则计算。
4. **教练无法开始自己的课程**：篮球／高尔夫教练在本场预约中变为等候状态后，被普通营业值班检查排除，课程因此无法开始。现在只允许实际在场、仍处工作时段、参与本场授课的对应教练提供本场服务；普通约球、未到场以及无预约服务仍不能绕过无人值班限制。
5. **公司页面零持股仍显示“股东”**：改为“未持股”。布局和美术样式保持原方案。

对应生产代码：`GameSession.EmployeeWellbeing.cs`、`GameSession.CompanyBoard.cs`、`GameSession.CompanyGovernance.cs`、`GameSession.VenueBusiness.cs`、`GameSession.OnsitePlay.cs`、`GameSession.CityActivities.cs`、`GameUi.CompanyGovernance.cs`。这些文件还包含本轮之前的实现，不能把整个文件差异都算成本次测试修复。

## 旧测试前提修正

这些修正只使测试遵守现在的规则，没有把生产逻辑退回旧玩法：

- 证券买入测试准备已解锁花园的状态；交易单位按 1 股计算，非法数量改测 0。
- 电动车移动测试先完成初次骑行教学，存读档速度比较显式使用相同倍速；教学暂停不应被判成移动故障。
- 需要玩家主动结束的就餐测试调用正式结束动作，不能只无限等待世界时间。
- 工作台测试中的第二套住宅显式位于测试中介负责的街道；否则购房应当被拒绝。
- 自动保存已经生成 `.bak`，备份恢复测试删除主文件后检查现有备份，不再把主文件移动到已存在的备份路径。
- 现场活动测试在跳转日期后实际推进世界，让场所人员通勤；必要时在到场窗口内等待工作人员，不直接把 NPC 改成“上班”。社区运动场同时有足球和篮球，篮球时长票测试按服务类型筛选。

旧测试中其余失败仍保留。尤其是 UI 按旧按钮文案查找、历史地图数量、日结工资与旧周薪领取断言、模型随行情定价与旧固定售价断言等，需要按当前产品规则逐项复核，不能仅为了降低失败数批量改期待值。

## 长期模拟与边界

- 城市经济机器人：种子 7／41／914，分别包含关闭事件、开启事件和低积极度策略的短期运行，每周真实 JSON 重载。这套旧机器人含直接购置升级等简化，不能替代真实玩家从新档通关。
- 账务／员工／证券压力：30 天、90 天、365 天、1095 天。使用小测试地图、充足现金和受控健康，检验长期状态及读档，不宣称覆盖全部场景、所有公司运营策略或随机剧情。
- 原 365 天用例触及单例六分钟预算；整组又触及十分钟进程预算。原失败与中断保留。之后读取实际检查点续跑到目标，每 30 天保存并重新加载。续跑使用按天确定的交易随机种子，因此不是原随机序列的位级连续重播。
- 游戏采用每年 **360 天** 的日历。365 天超过一游戏年，1095 天超过三游戏年；三年结局边界是 1080 天。报告按实际到达天数表述。
- 不把停留在某天的检查点当作到达目标，不把超时当作已证明卡死。进度、实际终点、存档大小、是否产生结局均保留在证据中。
- 1095 天终点另外核对：结局 `star`，存档 2,168,948 字节，账目 1,735 条，其中工资 1,095 条、对应 1,095 个不同日期，总工资支出 13,140,000 分。没有因反复重载重复记同一天工资。该检查只针对这一个受控场景，不代表所有排班组合均已穷尽。
- 本轮没有形成帧率、GC 或内存泄漏专项的验收结论；存档大小增长记录不能替代运行内存分析。

## 复跑方法

仅在获得当次测试指示后运行。主项目外的测试镜像可重用，但不能与已打开的 Unity 工程冲突。

```powershell
# 常规全项目分批；使用独立结果目录，重跑不覆盖历史。
pwsh -NoProfile -File tools/run-qa-baseline.ps1 -Round regression -ResultsRoot D:/tmp/pcshop-qa-regression-20261127

# 定向回归示例
pwsh -NoProfile -File tools/run-tests.ps1 -Mirror D:/tmp/PCShop-main-build-5f4a412c -ResultsRoot D:/tmp/pcshop-qa-focused-20261127 -Tag company-final -Filter 'CompanyWellbeingRegressionTests' -TimeoutSeconds 240

# UI 实机回调与截图；不生成发布包。
pwsh -NoProfile -File tools/qa/run-visual.ps1
```

`run-tests.ps1` 会检查镜像路径、拒绝占用中的镜像、隔离应用标识及存档目录、只终止自己启动的超时进程。每轮独立保存 NUnit XML、失败详情和摘要；第二轮还保存脚本、配置的 SHA-256 清单。`RegressionProgress` 即时记录用例完成状态，即使进程超时也能保留已完成用例。

本轮常规批次最初采用 240 秒整批预算，其中第 4 批和第 12 批需要拆出剩余用例补测。以后总入口默认每批 600 秒，仍排除已列明的独立长模拟，并提供 `-BatchTimeoutSeconds` 调整；当前工具配置不改写本次历史运行的真实预算。

总入口额外修复了失败批次未向上返回失败退出码的问题。使用模拟子批结果分别核对：全通过返回 0，子批失败返回 1；这两项属于测试工具自检，不混入游戏测试数量。归档工具把超时日志中的已完成记录和最后一个未完成用例转为小型记录，汇总数量与原始目录对照一致，不因省略大日志而丢掉失败。

原始目录：`D:/tmp/pcshop-qa-20261127`、`D:/tmp/pcshop-qa-focused-20261127`、`D:/tmp/pcshop-qa-regression-20261127`、`D:/tmp/pcshop-qa-visual-20261127`。完整 Unity 日志和大型检查点保留在这些目录，项目内归档 XML、摘要、逐用例历史、进度和关键截图。
