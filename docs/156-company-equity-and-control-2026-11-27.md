## 最新范围约束：公司玩法深度收敛

用户在本轮实现后明确：地图没有大量可供继续扩张的实体门店，公司部分只需要与《东京股神》相近的游玩深度。此前建议继续做公司直接开店、完整门店处置与更细经理授权，超出了当前目标，不再作为下一批必做内容。

- 现有有限门店作为公司经营基础，不为公司成长继续增加地图商铺，也不新增依赖更多实体店数量的成长要求。后续成长优先利用研发、推广、部门效率、经营规模和业绩反馈表达。
- 保留已接入的员工与部门、经营项目、上市、持股、董事会、增发分红、双向控股与必要的门店交接。日常经营尽量自动，只在关键经营选择、人事问题和股权变化时要求玩家决策。
- NPC 公司继续使用轻量经营模型，不逐店展开收银、库存、装修和员工排班。玩家管理已有实体门店的玩法继续保留。
- 门店退出或归属变化只需必要的后果确认和业务交接，不再扩成复杂估值、资产清算、产权交易和多级审批系统。
- 不继续添加逐级招聘额度、逐笔采购授权等权限矩阵。总经理、留任店长及股东／董事的基本权限已经能承接当前玩法。
- 实体总部暂不列为下一步必做。以后若制作，优先作为现有管理和人物交互入口，不再叠加办公楼模拟。

从功能范围看，本轮公司核心已经覆盖当前目标的主要部分。后续优先让已有决策的经营后果、月报和股价反馈更清楚，减少重复操作；不以继续堆公司子系统作为默认路线。本次范围修订只更新文档，没有改动已实现规则、注册门槛、代码或存档，也没有运行验收。

## 股本与真实资金

- 每个公司记录总股本和逐个股东的股份，股东股份之和须等于总股本。玩家、具名机构和公众分别记录。**公众是汇总账户，不作为一个可以接管公司的大股东。**
- 未上市自有公司初始 100 万股，玩家持有 100%。IPO 新发 25 万股，实际由有资金的机构认购，公司收到认购款，玩家初始持有 80%。此后比例随交易和增发变化。
- 创始股份已并入普通玩家持仓，能按数量实际出售。原有固定额外创始持股不再重复加到持仓或市值上。旧档首次迁移时只补入一次原先那 100 万创始股。
- 现有 NPC 上市公司使用原目录股本。首次建立名册时，保留玩家旧持仓，从其余股份划出创始人、两家机构和公众持股；没有玩家旧仓时分别为 45%、15%、10%、30%。原经理在尚无过半股东时继续经营。
- 晴川资本、兴华实业投资、星桥成长基金有跨公司共用且保存的现金，初始分别为 ¥120,000,000、¥100,000,000、¥80,000,000。创始人和各公司公众资金池有各自的初始资金，不随报价刷新或打开页面补钱。
- 普通买入从公众账户转出股份，付款扣个人现金、卖方收到成交款；普通卖出反向处理。报价可成交量与实际公众可卖股份都要满足，不能不断刷新报价凭空得到股份。公众买盘也受现金限制。
- 大宗交易向具名股东或机构洽谈。受让按现价溢价 10%，转让按现价的 95%，沿用证券手续费。没有卖方股份或买方现金就不能成交。确认前显示款项、费用和成交后比例，可能失控时明确显示公司门店交接后果。
- 股份买卖的钱归卖方；IPO／增发认购款进公司；现金分红从公司流出。三类资金分开，不把卖股收入当作公司融资。

上述数值是 PCShop 本轮采用的首版参数，不是对《东京股神》隐藏计算公式的复刻声明。

## NPC 增持与流通股份

花园开放后的工作日，机构按固定、可保存的市场状态参与交易。每家公司每天最多一笔自动市场交易，买入上限为总股本约 1%，受公众可卖数量、机构现金和手续费限制。公众流通比例低于 5% 时，有股份的机构可以向有资金的公众账户挂出约 0.5% 股份，形成实际流通。

自动交易只买卖公众或机构已经持有的股份，**不会替玩家强卖创始股**。玩家主动出售旧股或通过增发稀释后，机构才可能继续集中股份并超过 50%。具名股东跨过 5% 的整档持股比例会披露新闻；产生过半新股东时另发控制权变更预告。

## 会议、董事会与议案

| 身份 | 首版规则 |
| --- | --- |
| 普通股东 | 可看公开行情、股东分布和经营披露，按实际股份收取分红。 |
| 持股至少 1% | 可参与股东会议和投票。 |
| 持股至少 5%，公司信任至少 60 | 可提出董事提名；仍须支持票超过总股本 50% 才取得董事权限。 |
| 已任董事 | 可查内部现金、预算与管理摘要，提出经营议案；出售后持股低于 5% 撤销该席位。 |
| 持股超过 50% | 具有明确的控股表决权，可主动发起改组。刚好 50% 不构成控股。 |
| 总经理 | 管理公司日常经营、公司人事和部门。控股人与总经理分别记录，玩家可委托经理，也可自己上任。 |

公司信任初始 60，与员工满意度和 NPC 个人好感分开。每日按经营盈亏、周转是否充足和是否存在低满意度员工，向目标值变化最多 1 点；盈利基础目标为 70、亏损为 45，周转不足再减 15，存在低满意度员工再减 10。NPC 投票按当前信任、议案是否保护周转资金、增发是否用于资金不足的公司以及自身认购利益计算。界面展示当前投票意向，结束时读取实际持股重新计票，不能用原先的股数重复投票。

每家公司同时最多一项未结束议案，表决期为一个游戏日；保留最近十二项记录。投票可选支持、反对或弃权，支持票必须超过全部已发行股份的一半。结算保存当时的总股本，增发后的历史表决百分比不会改用新股本。议案通过后再检查资金、认购人和标的，条件已变化时公布未执行原因。

| 议案 | 实际作用 |
| --- | --- |
| 董事提名 | 表决通过后记录席位，独立于雇佣、门店岗位及经理职务。 |
| 任免总经理 | 保留原经理、委派机构管理代表，或由玩家上任；权限跟随经理任命变化。 |
| 经营预算 | 设置每日自主开支预算。工资、租金、已经承诺的业务仍按原合同执行，不能靠调低预算取消账单。 |
| 经营扩张 | NPC 公司投入现金扩大现有经营规模模型。实体自有公司则选择一间同业个人店，由公司按库存成本和押金报价受让业务；资金不足或库存报价变化时不强行交割。 |
| 推广投入 | 支付公司资金。自有公司所属门店得到 30 天 15% 客流加成，与原市场部同类加成不重复叠加；NPC 公司在现有规模模型中逐日体现推广。 |
| 现金分红 | 限于可分配利润及保留七天周转后的现金，至少每股 1 分，按名册实际股份发放并除息。自有公司的同一盈利月记录已分配金额，避免重复用一份利润派息。 |
| 增发股份 | 单次不超过当前股本的 50%，选择玩家或机构认购，预览新股本、认购款及稀释后持股。采用提案时价格，结算再次核对认购现金，成功后才增加股本。 |

持股交易、增发与分红共用证券持仓和公司治理状态。分红事件有保存的唯一键和结算记录，重复恢复同一事件不应再次扣公司现金或重复发给股东。多年分配和异常恢复仍需后续运行验证。

## 玩家接管 NPC 公司

取得过半表决权后，从控制权页主动发起接管。确认页可以保留原经理、选机构管理代表或自己上任，并设置每日自主开支预算。管理权在下一个营业结算点，即次日 00:00 生效，避免成交时直接清掉正在运行的业务。

NPC 同行首版沿用现有上市公司的轻量经营规模、利润、公司现金和报价模型。接管后，预算、扩张、推广、经理任免和分红都对这些实际状态生效；本轮没有把每个同行展开为玩家可逐货架操作的实体分店，也没有新增总部场景。该范围沿用此前设计稿确认的首版接管深度。

## NPC 接管玩家公司与门店交接

交易先改变股份。具名 NPC 股东超过 50% 后，发出预告并在次日 00:00 改组管理层。玩家可以在交接前接受一间指定公司门店的店长留任，日薪 ¥200，或交接全部公司门店。首版提供公司现有门店中最早经营的一间作为留任邀请。公司改变控股比例、原新控股人不再过半时，尚未执行的交接会撤回。

| 资产或业务 | 交接结果 |
| --- | --- |
| 个人门店 | 继续由玩家经营，不因同名品牌或其他公司被收购而交出去。 |
| 公司门店，玩家被留任 | 仅指定门店保留经营、排班、补货和定价操作，公司现金结算，按日领取留任工资。可以主动结束留任。 |
| 公司门店，玩家未留任 | 新管理层接手；原记录不删除，玩家可以查看业务交接摘要，但不能再改价、装修、取货、解雇或调走该店员工。 |
| 员工 | 保留员工 ID、经验、满意度、精力、班次、待执行薪资、请求和公司岗位，原采购任务继续。NPC 经理按资金处理请求，缺少基本值守且未超编时安排值班员工，不自动裁员。 |
| 库存、在途采购和订单 | 留在原门店和公司，原付款、运单、订单、待交付任务继续，不退租、不重建、不清空库存。 |
| 公司合同和归属 | 控股改变不改变公司 ID，因此原合同、应付账、部门项目及历史经营账仍属于原公司。 |

日常经营权限与股东／董事权限分别判断。失去控制后，玩家可以继续持股、收分红、争取董事席位或重新买到过半；只有重新取得过半后并完成改组，才恢复相应控制权。委托 NPC 当总经理时，玩家保留控股表决权，可通过经理议案重新上任。

实体门店业务划入公司时，按确认报价支付给个人卖方，先结清此前已发生的员工工资；保存新公司营业起始记录，后续营收和费用归新经营主体。房屋产权不随业务划入转走。公司股权交接本身不会再次触发门店买卖或重复支付库存费用。

## 公司账户、个人现金与估值

本轮在统一账本增加现金账户归属：带有公司门店或公司雇主归属的营收、工资、房租、采购及其退款使用公司周转金，账目仍保留。玩家个人现金不会再接收这部分公司收入，也不会为已交给 NPC 的公司店持续垫付日常工资。个人购物、股份交易、主动注资和领取分红仍走个人现金。

每条账目保存当时的 `CashAccountId`，加载不重新按当前控股人归账。旧公司财报在迁移日之前按原历史门店关联保留，之后按实际公司账户归属读取。公司门店后来划入，不把当天此前的个人收入追算成公司收入。

个人预留资金排除公司工资、租金与公司货款；公司采购预检读取公司可用现金。上市公司库存、押金、公司周转金和公司货款负债不再同时完整叠加到个人净资产，上市权益以实际所持股份市值计入，避免公司经营资产与股份价值双算。房屋和其他原有个人资产仍沿用原产权记录。

公司固定账单可以让公司现金为负，个人银行卡不因此直接变负。首版没有破产清算、公司债务重组、换股合并、强制挤出其他股东或独立的公司贷款产品。

## 复拍方法

[CompanyGovernanceCapture.cs](../tools/company-governance/CompanyGovernanceCapture.cs)仅放在仓库 `tools`，不进入发布游戏。复制到隔离工程 `Assets/Editor`，同步最新源码，设置绝对路径环境变量 `PCSHOP_GOVERNANCE_OUTPUT`，用 Unity 参数 `-batchmode -projectPath <隔离工程> -executeMethod CompanyGovernanceCapture.Run -logFile <日志>` 启动。入口需等待进入 Play Mode，不带 `-quit`。

成功标记为 `COMPANY_GOVERNANCE_UI_CAPTURE_DONE`，输出 1920×1080 原始 PNG 与活跃 UI 文字。入口仅准备状态和拍摄，不运行成交模拟、时钟跨日或测试框架，保存目录被重定向到临时目录。正式存档和主项目中原有的 Unity 编辑器不参与复拍。
