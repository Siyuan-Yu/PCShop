# 决策记录

记录已经拍板的事、原因，以及被否决的方案，避免以后重复讨论。日期为 2026-10-28（立项讨论日）。

## 一、已确定

### 产品定位
- **电脑城创业故事**：从商业街最偏的一间小电脑店起家，手装机赚第一桶金，靠行情、人脉和签约主播做大，最后建成电脑乐园（园区）。
- 开局固定为这间小电脑店，不做"开局任选行业"。
- 宣传不使用"创业模拟器"作为核心卖点。
- 原因：通用创业/开店模拟竞品密集（Big Ambitions、Street Vendor's Journey、长安首富模拟器等）；电脑硬件为根 + 主播反噬机制 + 园区终局，是目前没找到明确竞品的组合。

### 玩法
- 成长阶梯：L1 手操 → L2 雇人 → L3 管理 → L4 帝国 → L5 园区。**手操永远保留**，前期自己装机省钱、赚钱效率高，后期可雇人。
- 手装机做成轻量 2D 小游戏（拖拽配件、兼容性检查、计时），不做 3D 拆装。
- **世界时间是一条连续的时间线**（用户澄清，取代早期的"每日时间预算"）：走路、做事、睡觉、店铺营业都消耗同一条时钟，没有"免费移动/免费逛街"；玩家忙着时别处生意照常运转，顾客进店实时可见；可暂停和倍速。
- "自己干 vs 雇人"靠"同一时刻只能在一个地方"成立：**只有玩家一个人时，离开小店就关门；雇人后小店可以持续营业**（已确认）。
- 玩家**不扮演主播**；签约主播后可"资源投入"提升人气。
- 主播核心属性：人气、好感/忠诚、野心。人气越高 → 身价、野心、挖角风险越高，好感衰减越快，代言费越贵；也与恋爱/关系挂钩。
- 玩家有"地位/形象"属性；车影响通勤效率和谈判效率，也影响与高人气主播的关系匹配。
- 价格由虚构宏观因子驱动（币圈热度、AI 需求、新品周期、库存缺货、政策/汇率、股市情绪）。要"可读的因果"，不是纯随机。
- 终局为园区（电脑乐园：电脑、电竞、餐饮、住宿、车辆区），1.0 做成"布局 + 招商 + 运营指标"的轻量版。
- 1.0 业态总数不超过 6 个，其余作为后续更新。

### L1 核心循环（2026-10-28 第二轮确认）
- **守店画面：** 守店时切到小店的室内固定镜头场景；离开小店才回到世界层。小店室内同样由代码生成。
- **散件销售：** 顾客在室内自己挑货，然后到柜台找玩家结账，结账需要玩家点击确认（手动动作）。
- **装机订单：** 订单进入队列，由玩家手动装机（2D 覆盖层小游戏）。
- **支付升级线：** 前期只收现金，玩家只有按键手机；之后可买智能手机，解锁收款码（移动支付）；再往后解锁自助结账平台。每一级让"不带现金的顾客"也能成交、结账更快、排队流失更少。
- **自助结账不能代替人值守：** 没人在小店时照样关门，自助结账只让结账更快、不用排队。
- **配件：** 5~6 个品类、每类 3 档，兼容规则只保留几条关键的。
- **行情可读：** 按"新闻（原因）→ 宏观指标 → 品类价格"展示因果链。
- **装机小游戏：** 拖配件装进主板，限时，装错返工并增加耗时。
- **存档：** 每天自动存一次，另外可随时手动存档。

### 时间与节奏（2026-10-28 第二轮确认）
- **1× 节奏：** 一个游戏日约 3~5 分钟真实时间（1 游戏分钟约 0.2~0.3 秒），做成可调参数，原型后再定具体值。取代早期的"1 游戏分钟约 0.5 秒"。
- **限期目标：** 从 8 年缩短为约 3 年；一局（开局到园区落成）目标时长 40~60 小时。
- **星期：** 加入 7 天一周。周末商业街客流更大、批发商休息、适合社交。
- **营业时间：** 店主自己决定，夜里几乎没有客人。

### 商业街与起始地图（2026-10-28 第三轮确认）
- **不做多层商场**（一栋楼多层、每层不同业态太复杂）。改为**一条商业街，约 20 家店，每家店一个业态**。
- 玩家的电脑店是**最小、位置最差**的一家：**离地铁站最远**，客流少；之后靠打出知名度提升客流。
- 店铺分**大、中、小**三种规格，玩家开局只租得起小的。`[建议]` 面积：小约 12㎡（3m × 4m）、中约 36㎡（6m × 6m）、大约 96㎡（8m × 12m）；20 家店按 4 大、8 中、8 小配置。
- 客流 = 街道基础客流 × 位置系数（离地铁站越远越低，最远约为最近的 40%）× 规格系数 × 知名度系数。`[建议]`
- 有公共交通：地铁站在商业街一端，是客流来源，后期也是去其他区域的交通方式。
- 玩家住在 **5 条街之外的城中村**（便宜的出租屋）。
- 线下进货的档口在约 2 公里外的电子配件批发市场（见下文）；店铺只开在街的一侧，因为固定镜头只能看到建筑的 −Z、−X 两个面。

### 进货渠道与载具（2026-10-28 第四轮确认）
- **三种进货渠道：**
  1. **线下档口（开局可用）：** 肉身跑到专门卖某类配件的地方（如"CPU 档口"），找老板进货。价格中等，能砍价，有现货，能攒人脉和情报；消耗世界时间，一个人时店要关门。
  2. **"1788"批发平台（虚构，网上下单）：** 找对店铺最便宜；找错会更贵或买到次品；到货要等。考验玩家能不能找到正确的进货渠道。
  3. **大老板直供（后期）：** 通过社交认识上游大老板，一起打球、踢球、去 KTV、去酒吧刷好感，好感够了可以直接找他拿货。价格最低，还能赊账。
- **载具（VS1 就有）：** 开局没车，只能步行或打车（花钱、省时间）；可以买**小电驴**（快、便宜、拉货少）或**三轮车**（拉货多，但理论上不能进城，会被交警查）。载具影响移动耗时和一次能拉多少货。
- **交警：** 骑三轮车时，路上按概率出现交警。交警有**看得见的视线范围**，被看到就会追，追上了罚款。玩家靠选路线绕开交警的视线。`[建议]` 被追时自动切回 1×，方便反应；被抓除了罚款，还可能扣车。
- 这是"世界层没有实时动作"原则的**唯一例外**：只靠选路线躲开，不需要手速。
- **档口位置（第五轮确认）：** 单独一片"电子配件批发市场"，离商业街约 2 公里，里面有几家专营档口（CPU、显卡、内存/硬盘、主板/电源等）。步行约半小时；打车、小电驴、三轮车、地铁各有取舍。取代早期"批发商在地铁站附近"的建议。
- **1788 找对店铺（第五轮确认）：** 看评价、先下小单试货（花时间和小钱试错）；同行或人脉也会推荐靠谱的店。

### 库存与包装（2026-10-28 第六轮确认）
- **店铺就是仓库**：大、中、小三种规格都有库存容量，配件放在店里要占空间，库存不能超过容量。
- **散件与盒装：**
  - 拆掉包装放成散件：占的空间少，能放更多，但卖价低一些。
  - 保留包装（盒装）：卖价高一些，顾客也更信任（成交率更高），但占的空间多。
- `[建议]` 默认数值：
  - 容量以"格"计：小店 40 格、中店 120 格、大店 300 格。
  - 占用空间：盒装 1 格，散件 0.4 格（显卡、机箱这类大件按 2 倍计）。
  - 卖价：盒装比散件高约 12%；盒装让顾客犹豫离开的概率降低约 15%。
  - 拆包装不可逆，拆了就不能再装回去。
- 后期可以租仓库扩容（地产系统里的"仓库"物业）；载具的载货量也用同样的"格"计算。

### 实现约定（开工时补充）`[建议]`
- **移动的画面速度与时钟：** 时钟按一天 3~5 分钟流动时，人走路的画面速度会快到看不清，交警也追不上。所以**移动时画面按固定速度播放**（步行约 12 米/秒，载具更快，倍速同样生效），世界时钟按"这段路实际要花的游戏分钟"同步推进。耗时规则不变，只是播放节奏不同。
- **远距离连接路段在画面上压缩：** 商业街按真实尺寸，去城中村和批发市场的路在画面上缩短，但路径图里按真实长度（约 500 米、约 2 公里）计算耗时。
- **1788 在店里的电脑上下单：** 开局只有按键手机，所以网上进货只能在自己店里用电脑下单。
- **载具跟着玩家：** 灰盒阶段不做停车，载具始终跟着玩家；坐地铁时载具也视为跟着（以后再细化）。
- **地铁：** 商业街站 ↔ 电子市场站，¥3，约 12 分钟（含候车）。
- **第一个月目标：** 第 30 天结束时，净资产（现金 + 库存按市价九折）≥ ¥8,000 且雇了第一位员工。未达成可继续玩。
- **破产：** 现金连续 3 天为负，触发清算（失败结局）。
- **雇人：** 在店里贴招聘启事（¥50），第二天 9:00 出现 2 位候选人；员工 9:00~21:00 值班、帮忙结账，不会装机；工资每天结算。

### 空间与 3C（2026-10-28 追加，详见 `04-3c-and-world.md`）
- 游戏不是纯 UI 模拟：玩家要能**走上街**，**看到自己的多家店、家业、地产**。
- 三层结构：世界 3C（街道）+ 店内 3C（固定镜头室内，手操）+ UI 面板（进货、定价、行情、签约、员工、账本；**不单独做成 3C**）。
- **视角与美术形式（用户决定改为 3D）：** 3D 低多边形 + 固定斜俯视正交相机（画面效果为 2.5D），可做昼夜、夜景灯光、天气。URP 14.0.8 已安装。
- **模型来源（已更新，详见 `06-art-and-rendering.md`）：** 当前阶段不买素材包，环境全部程序生成；人物、车辆暂用简化几何占位，核心循环验证后再决定买单品包、外包还是保持极简（倾向买单品包）。不使用 AI 生成 3D 模型（用户不会 Blender，无法清理，侵权风险也不比 2D 低）；AI 只做 2D（图标、UI、招牌、海报、贴图）。所有品牌虚构。
- 店内为固定镜头的室内场景，不能在店里走动（已采纳建议）。
- **进货渠道：** 见下文"进货渠道与载具"（第四轮确认，取代早期"线上稍贵、线下便宜"的写法）。
- 面板里"看和想"不耗时，"做"才耗时；手操完成后一次性推进标准耗时（已采纳建议）。
- 时间控制暂停/1×/2×/4×/8×；1× 节奏见下文"时间与节奏"；不强制睡觉（见下文）；暂不加体力系统（改为状态系统中的"精神/饥饿"，见 `05-player-life.md`）。
- **城市布局（已确认）：** 固定设计，布局和路径图由数据文件描述，外观由代码生成；做成一张连续的大地图（不按区域拆场景）。
- **世界层定位（用户澄清）：家业的展示与成就层**。没有实时动作要素；玩家可以逛，能看到顾客小人走进店里消费；价值是"建立商业帝国后的成就感"。表现层只读经营结果，不反向影响数值。
- 世界层实现：3D 模块 + 建筑插槽 + 路径图（路径图和寻路的 Core 代码不变，平面坐标映射到 3D 地面）。
- 所有移动都推进世界时钟，车降低耗时；后期解锁"快速前往"（自动走完并加速播放，世界时间照常消耗）。
- 地产（租/买/出租、地价、政策事件）作为 L3 以后的重要玩法。

### 目标、失败与角色生活（2026-10-28 追加，详见 `05-player-life.md`）
- 目标与失败**参考东京股神**：限期目标（约 3 年内园区落成，见"时间与节奏"），未达成可继续但影响结局；资不抵债先预警再强制清算触发失败结局；严重生病住院期间不能行动；没有死亡。
- 结局按首富、口碑、情感、失败多条线索评价。
- 轻量主线（导师、对手、家人）+ 随机事件；宏观因子随机 + 少量历史事件模板（已采纳建议）。
- **角色属性与生活模拟（用户要求）：** 智力、魅力、装机技术；状态值饥饿、精神、健康；衣着影响魅力和场合；居住环境太差会让精神和健康持续下降；每天吃饭消耗世界时间和钱；生活开销入账。
- 生存机制必须可自动化（自动三餐、自动睡觉），不做成"打卡"负担。
- VS1 先做"一个月的流程"验证核心循环：小店、装机、进货、第一次雇人、一次行情波动。

### 技术
- 引擎：**Unity 2022.3.6f1**（`D:\UnityEditor\2022.3.6f1`）。不使用 `F:\Unity2021\...` 的公司定制引擎。
- 3D 低多边形 + 固定斜俯视相机；场景布局由数据文件和编辑器脚本生成，尽量少依赖手工在编辑器里拖拽（AI 协作时无法操作编辑器 GUI）。素材包导入和摆放需要用户在 Unity 里做少量操作。
- 代码分层：`Core`（纯 C#，不引用 UnityEngine，带单元测试）、`Game`（Unity 层）、`Tests/EditMode`。
- **技术选型（已确认）：** UI 用 uGUI + TextMeshPro，中文字体用思源黑体（可商用）；配置数据用 JSON；保留 Unity 旧 Input Manager，暂不切换新 Input System；Core 中的随机（营业、行情、事件）用带种子的随机数，读档后结果可复现。
- 平台：Steam（Windows）为主，横屏；**微信小游戏不做**（用户决定）；手游（iOS/Android）后续再考虑，目前只预留接口（存档、成就、支付等做接口隔离，UI 不依赖悬停/右键，资源按需加载，3D 资源控制面数和贴图尺寸）。

- **美术路线（用户决定）：先不买素材包**，用代码程序生成的极简几何风 + URP 打光做世界层，核心玩法验证后再决定买包改造、外包关键资产或保持极简。音效音乐由用户的朋友制作。
- 已用程序生成做过街区预览（`docs/previews/`，由 `PCShopSell/Render Preview Images` 生成）：白天/黄昏/夜晚三种光照，证明"零素材 + 打光"能达到可看的效果；仍缺的是人物动画和细节变化。
- URP 14.0.8 已加入，资产在 `Assets/Settings/`，色彩空间改为 Linear。
- **光影升级已完成（2026-10-28）：** 霓虹点光、夜景雾、SSAO、湿润路面加反射探针、色差/胶片颗粒/分色等，参数见 `06-art-and-rendering.md`。
- **用户反馈：** "画风还可以，略简约"；人物建模和车辆建模不够精细，光影对赛博朋克来说不够精细。结论：光影已升级；人物和车辆需要真实模型，用几何拼接到不了。用户同意大致可以，先开工，美术放到核心循环验证之后再升级。
- **美术可替换性（已确认）：** 逻辑与外观分离，人物用外观组件，车辆用预制体，店铺用带挂点的模块预制体，统一尺寸与朝向约定，以后换美术不改 Core。难度：车辆最易，店铺中等，人物（要动画）最难。
- **开工顺序（已确认）：** 世界层灰盒 → Core 业务（顾客、属性、生活、目标）→ 店内手操与 UI → 核心循环验证 → 美术升级。

### 美术与合规
- 没有美术，使用 AI 生成素材。Steam 允许，需在内容调查中如实披露预生成 AI 内容；不使用实时生成 AI 内容。
- 所有 AI 素材登记到 `docs/asset-log.md`（工具、套餐、日期、提示词、人工修改）。

- 品牌、型号、平台、人物全部虚构/原创；不影射真人；不照搬竞品 UI、角色、文案。
- 首批 3~5 位原创主播/恋爱角色，立绘半身加表情，不做动态。
- 恋爱和主播内容尺度克制；国内发行合规另行核实。

## 二、已否决的方案

| 方案 | 否决原因 |
|---|---|
| Godot | 用户不熟，且本机未安装 |
| TypeScript + Web 技术栈（Tauri/Electron） | 用户最终选择 Unity，且考虑多平台（含微信小游戏）可用官方转换方案 |
| 3D 货架/店铺模拟（货架摆放玩法） | 与现有货架模拟器同质化；核心乐趣不在这里（注意：这条否决的是玩法，不是 3D 视角，视角后来改为 3D） |
| AI 生成 3D 模型作为主要来源 | 用户不会 Blender，模型需减面、清理、统一材质；授权和侵权风险不比 2D 低；改为程序生成，美术升级放到核心循环验证之后 |
| 电脑城做成多层商场（每层不同业态） | 太复杂；改为一条商业街，每家店一个业态 |
| 按区域拆成多个场景 | 改为一张连续大地图，布局由数据文件固定 |
| 强制睡觉 | 改为只提醒，没按时睡由第二天精神下降来惩罚 |
| 线上进货一律比线下贵 | 改为 1788 平台找对店铺最便宜、找错吃亏，奖励"找对渠道" |
| 交警只做概率罚款 | 用户要求可见视线 + 追逐，玩家靠选路线躲开 |
| 自助结账代替人值守 | 会削弱"自己干 vs 雇人"的取舍；自助结账只加快结账 |
| 纯 2D 世界层 / 2.5D 手绘 | AI 难以保证视角、比例一致，人物没有低成本的走动动画；改为 3D 固定斜俯视 |
| 微信小游戏 | 用户决定不做 |
| 纯 UI 驱动（东京股神式，无空间） | 用户希望能走上街、看到家业和地产；纯 UI 也让商店页截图单调。改为"世界层 + 面板层 + 手操层" |
| 货架式零售店 | 竞品密集，近年跟风作评价偏低 |
| 玩家扮演主播 | 与榜一模拟器、主播养成类撞车；用户明确要玩家作为老板/经纪人 |
| 开局任选行业 | 稀释卖点，增加内容量；改为固定小电脑店起步 |
| 小吃摊起步 | Street Vendor's Journey、长安首富等已占据 |
| 二手车作为独立核心玩法 | Real Life Simulator 以此为核心；降级为园区车辆区业态 |
| 恋爱/主播作为"唯一卖点" | 纯 MCN/主播赛道拥挤（榜一模拟器、Idol Manager 等）；改为"成长引擎"之一 |

## 三补、2026-10-29 新增的决定（用户授权“按推荐方式做完整”）
- **长线目标**：三年（1095 天）路线，检查点失败只涨租、不结束游戏；破产仍是唯一失败。基调定为“经营为主、保留破产风险”，结局分四档，结局后可继续玩。
- **店面**：VS1 内用“原地扩建”（中型 / 大型）当作长期资金出口；**真正的“搬到别的街”仍放 VS2**，因为需要新店内场景和美术。
- **人物**：5 个固定人物，用交情值和事件驱动，全部是文字 + 数值，不需要新美术。
- **数值**：用“机器人玩三年”的跑分当校准依据（见 09-campaign-and-balance.md）；门槛是占位，真人试玩后再调。
- **美术顺序**：不变，先验证核心循环，再单独替换人物和车辆模型。

## 三补二、2026-10-29 用户新提的规则（取代“自动三餐”）
- **吃饭**：每天饿两次（12:00、18:30），只能吃自己做的：在家吃锅里的，出门吃背包里的饭盒；没有就饿着，不再自动花钱在外面吃。饭盒从电饭锅装，进背包算负重。
- **买东西统一规则**：所有线下购买，买了要么装进背包自己带，要么叫车送回去（配件送店里，其他送家里），叫车按路程收费，同一家店拼一车。
- **背包不自动清空**：东西只在自己的地盘（店、家）由玩家打开背包一键放下。
- **送礼都要先买**：包括店员，礼品从背包里拿，不能在对话里直接扣钱。
- **店内镜头**能看到门外的街和路人，顾客从街上走进来；能从店门走出去。

## 三补三、2026-10-30 用户新提的规则
- **叫车有载重**：一辆车装不下所有东西。界面要显示当前这辆车能装多少、还剩多少，不够就叫下一辆，每辆各收一次运费（实现：面包车每辆 200 公斤，运费 = 打车计价 + ¥20）。取代上一条里的“同一家店拼一车”。
- **家具城和农贸市场同一种交互**：选“装进背包 / 叫车送到家”，背包装不下必须叫车。去掉购物车和寄存。
- **离店二次确认**：出门、在门口按 F、点“离开店铺”都要先确认；没人看店写明会关门，店员在班写明不关门。
- **1788 只是手机 app**：买智能手机并下载 1788 后才能用，不在店里的面板上；在哪都能下单。自动补货也放进这个 app，并用大白话解释。
- **全游戏只用 WASD 移动**，不能鼠标点哪走到哪。
- **顾客头顶对话气泡**：说想买什么、店里有没有货，挑中后说拿了哪件。
