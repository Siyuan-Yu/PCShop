# 美术与渲染方案 v0.1（2026-10-28）

本文汇总到目前为止关于美术路线、光影、可替换性的所有结论。与其他文档冲突时，以本文的美术部分为准。

## 当前采用：暖色微缩街区 / 复古电脑店（2026-10-30）

本节是当前方向，优先于下方早期灰盒和赛博朋克方案。目标是让电脑城像一座可生活、可经营的微缩街区：安静的材质、大块清晰的轮廓、小而具体的生活细节。

参考：[Dorfromantik](https://www.toukana.com/dorfromantik) 的微缩场景阅读方式；[Mini Motorways](https://dinopoloclub.com/games/) 的克制配色与信息层级。只参考美术组织原则，没有下载或引入两款游戏的素材。

### 色彩与材质

| 角色 | 色值 | 用途 |
|---|---|---|
| 奶油 | `#E5DDCA` | 墙、搪瓷台面、窗框、纸标签 |
| 烟灰绿 | `#758A7D` | 金属货架、柜体、护墙板 |
| 深墨绿 | `#293E3D` | 结构框、玻璃、工作台 |
| 胡桃木 | `#977457` | 层板、桌面、木家具 |
| 黄铜 | `#C7A36B` | 五金、类别识别、少量重点 |
| 陶土 | `#AD6C55` | 衣着、部分招牌、暖色点缀 |
| 灰蓝 | `#6D8896` | 类别识别和街区配色变化 |

避免高饱和彩虹灯条和大块纯黑。类别仍保留不同颜色和文字，不能只依赖颜色识别。玻璃、漆面与木材的高光保持克制。

### 已接入的 3D 内容

- 小物件共享缓存倒角网格，原碰撞体及经营占地不变。大建筑和超薄物体不强制倒角，避免增加无效几何。
- 人物用独立躯干、双腿、鞋、袖子、手、头发和五官替代胶囊；新增肩、髋、膝、脚关节，按实际位移播放交替迈步、屈膝抬脚、反向摆臂和轻微身体起伏。腿部求解保持支撑脚落地，松开方向键或被家具挡住后收步。街道、出租屋、店内主角及顾客、路人、交警、维修师傅共用这套动作；换装同步上衣、袖子和两段裤腿。
- 动作只改变外观子节点，不改变人物根节点、碰撞、寻路或经营时间。进出场景及传送重置动作采样，骑车不播放步行，暂停窗口冻结动作；室内转向按帧时间平滑。这里是程序关节动画，尚未制作美术烘焙的骨骼动作、专属角色模型及完整操作动作。
- 收银台采用奶油台面、烟灰绿柜体、竖向分缝和黄铜铭牌；终端增加屏幕与字行；工作台增加木台面和维修垫。
- 装修预览保留家具的原始材质，只在实际轮廓外叠加绿色（可放）或红色（不可放）柔光；地面占地提示为空心细框。`PlacementOutline.cs` 和 `Resources/Shaders/PlacementOutline.shader` 使用独立网格及遮罩，不修改家具共享材质；旋转、挪动、改选及取消时同步更新或清除，临时资源随预览释放。
- 货架取消霓虹式类别灯条，使用色牌与类别文字；展示桌增加“整机现货”标识。
- 店内采用细瓷砖、绿护墙板和细黄铜压条；出租屋统一墙面色，保留破损和贫困开局特征。
- 商铺增加布棚条纹、垂边、窗框和实际店名文字；店名随租赁状态更新。
- 街边停放车辆有车舱、车窗、轮胎、轮毂、灯和车牌；树冠改为错落的多团簇轮廓。
- 日间提高环境补光、收敛饱和度；室内使用更高角度的柔和主光；夜晚使用蓝绿色环境光和克制暖灯。降低 bloom、暗角、颗粒，取消旧配置的色散。

### 已接入的 2D 内容

- UI 统一为墨绿底、米白字、黄铜重点；按钮与主要卡片采用细边框和轻圆角，标题与正文区分。
- 新手任务、提示、通知、人物卡框和富文本状态色使用同一套色彩。通知最多同时显示三条，置于模态窗口之后；操作提示增加深色衬底，避免白字落在亮地面上。
- 装机界面绘制 CPU 引脚、内存颗粒、显卡风扇、主板线路、硬盘/电源机壳的图形示意，仍沿用原来的拖拽区域和规则。
- 既有九张人物立绘没有重绘；只统一展示框与周边 UI。以后重绘时应采用自然表情、克制色彩和生活化衣着，保持人物身份可辨。
- 中介选址使用真实街区的独立鸟瞰相机，保留店铺、道路、地铁和住宅的位置关系；叠加报价牌、选中楼体线框和右侧户型/费用。缩放、拖动和夜间看房均与主场景镜头、角色及光照隔离，关闭窗口释放相机和渲染纹理。

### 资源与后续边界

新增内容均为项目代码生成的网格、材质、世界空间文字和 UI 图形；没有新增第三方模型、纹理或字体包。字体继续使用原有系统字体回退。

已通过真实游戏批处理冒烟并检查店内、街道、夜晚、对话、装机截图。程序行走动作已接入；还没有完成专项性能基准测试、美术烘焙的骨骼动作、立绘重绘和整套成品资产替换。

## 1. 视觉形态
- 3D 低多边形，固定斜俯视正交相机：俯仰 35°，水平旋转 45°，画面效果为 2.5D。
- 视角下只能看到每栋建筑的 −Z 面和 −X 面，所以窗户、招牌、门只做在这两个面上。
- 渲染管线 URP 14.0.8，Linear 色彩空间，HDR + Bloom + 后期。
- 平台：Steam（Windows）先行；微信小游戏不做；手游以后再评估。

## 2. 美术来源路线
- **当前阶段：不买素材包。** 环境（街道、建筑、店面、街道设施、树、路灯、红绿灯等）全部由 `ProceduralCityBuilder` 用代码生成，靠 URP 打光出效果。
  - 好处：成本为零，不会和别的游戏撞素材，不会被"素材包同款"评价。
  - 限制：建模精度有天花板（见第 4 节）。
  - 店铺室内（守店的主场景，固定镜头，按大/中/小规格生成）同样由代码生成；城市布局由数据文件固定，随机只用于外观细节。
  - 镜头只看得到 −Z、−X 两个面，所以商业街的店铺只开在街的一侧（门脸朝 −Z），对面放人行道、树、公交站和地铁口。
- **人物与车辆：** 当前用简化几何体作为占位（胶囊身体加球头、方块车身加轮子）。不再继续往上堆几何细节。
- **AI 只用于 2D：** 图标、UI、招牌、海报、头像、立绘。AI 不生成 3D 模型（用户不会 Blender，清理和减面做不了，授权风险也不比 2D 低）。
- **音效音乐：** 由用户的朋友制作。
- **品牌：** 全部虚构。
- **后续再定：** 核心循环（VS1）验证后，再决定下面三条中的哪条或组合：
  1. 购买单品模型包（现代汽车 4~6 辆，低模风格人物 1 套）；
  2. 外包关键资产（人物、车辆、主角电脑城）；
  3. 保持当前极简风格。
  - 当前倾向 1。不做 AI 生成 3D 再人工修的方案（需要修模能力）。

## 3. 光影方案（已实现，见 `docs/previews/`）
由 `Assets/Scripts/Game/Procedural/CityLookProfile.cs` 的 Day / Dusk / Night 三套参数驱动，渲染设置由 `Assets/Editor/UrpSetup.cs` 与 `PreviewRenderer.cs` 配置。

| 项目 | 做法 |
|---|---|
| 主光 | 平行光，软阴影，主光阴影贴图 4096，阴影距离 160 |
| 霓虹 | 招牌/灯带用自发光材质，亮度乘 `NeonBoost`，配合 Bloom；夜景 `NeonBoost = 1.5`（调大会发白） |
| 霓虹光照 | 每家店前一盏招牌颜色点光（最多 12 盏）；电脑城有青、洋红、黄三盏大点光（强度由 `NeonLightIntensity` 决定） |
| 路灯 | 真实点光（场景内最多约 18 盏，范围 ±45） |
| 路面 | 湿润路面：`RoadSmoothness` 夜景 0.92；烘焙反射探针让路面和玻璃反射出霓虹 |
| 环境遮蔽 | SSAO（`UrpSetup.EnsureSsao`，URP 14 中该类是 internal，只能反射创建） |
| 雾 | 夜景线性雾，紫蓝色，150~330 米 |
| 后期 | Bloom、ACES 色调映射、色彩调整、暗角、色差、胶片颗粒、阴影/高光分色（暗部偏蓝紫、亮部偏粉） |
| 反射探针 | 渲染前对城市物体标记 `ReflectionProbeStatic`，在城市中央 (0, 6, 0) 放一个 190×60×190 的盒投影探针，用 `Lightmapping.BakeReflectionProbe` 烘焙 |

批处理渲染命令：

```
"D:\UnityEditor\2022.3.6f1\Editor\Unity.exe" -batchmode -projectPath D:\UnityProjects\PCShop\PCShop ^
  -executeMethod PCShopSell.EditorTools.PreviewRenderer.RenderFromBatch -logFile %TEMP%\preview.log
```

注意：批处理渲染不能加 `-nographics`；必须关闭异步着色器编译；`Camera.Render()` 要调用两次预热。

## 4. 已知差距（光影与模型）
- **人物和车辆不够精细**（用户反馈）：几何拼接不可能达到赛博朋克级精度，需要真实模型。这是美术升级的第一优先级。
- **路面反射**：URP 没有实时屏幕空间反射，目前只有烘焙探针的模糊倒影，没有《赛博朋克 2077》那种清晰的水面倒影。要做需要额外平面反射，或以后换 HDRP。
- **窗户**偏白偏平，层次可以再加。
- **人物动画**：已接入程序关节行走；尚无完整的坐下、收银、装机和交谈动作集。

## 5. 可替换性约定（让以后换美术不难）
目标：以后把占位模型换成精细模型，不改动 Core 逻辑，只改外观层。

1. **逻辑与外观分离：** `PCShopSell.Core` 保持纯 C#，不引用 UnityEngine；所有画面表现在 `Game` 层。
2. **人物外观组件：** 人物只通过一个"外观组件"接收状态（走、停、坐下、操作电脑、说话等），换成带骨骼动画的模型时只改这个组件。
3. **车辆预制体：** 车辆做成独立预制体，只暴露位置、朝向、车灯开关等接口，换车只替换预制体。
4. **店铺模块：** 每个店面是一个"模块预制体"，带固定挂点（门、柜台、顾客位、招牌位），逐家替换，不需要整体重做。
5. **统一约定：** 1 Unity 单位 = 1 米；模型朝向 +Z 为前；物体原点在底部中心；命名规则写进文档。
6. **预览工具保留：** 换完美术后用 `PCShopSell/Render Preview Images` 一键出昼/黄昏/夜对比图。
7. **难度预估：** 车辆最容易换；店铺模块中等；人物需要动画，最麻烦；逻辑层不受影响。

## 6. 接下来的实现顺序（已确认）
1. 世界层灰盒：数据驱动的城市布局，玩家在街上沿路径走动并推进世界时钟，进入小店切室内（顾客挑货、柜台结账），时间控制条（暂停/1×/2×/4×/8×）。
2. 营业模拟与顾客事件（CustomerVisit）、角色属性与生活系统、目标与结局（Core + 测试）。
3. 店内手操层与 UI 面板（进货、定价、行情、签约、员工、账本）。
4. 核心循环（VS1：一个月流程）验证后，再决定美术升级方案并做替换。
