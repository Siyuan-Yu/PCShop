# 持续采购频率：每天或每三天

2026-11-01 归档更新：当前采购支持鲜花、生鲜、食品等货源；单项失败跳过并继续，受额度、现金、容量约束时尽量部分采购，结果保存未购原因。最新规则和编译验证边界见 [第 30 篇](30-update-2026-11-01.md)；本篇既有测试数字属于历史版本。

更新日期：2026-11-01。

采购安排不是一次性任务。采购页新增“采购频率”：**每天一次 / 每三天一次**，默认每天。点击“完成”保存后，从次日起在员工上班时持续按所选周期尝试，无需反复安排，直到暂停、清空或修改计划。

- 首次从保存的次日开始。之后按最近一次尝试日加1天或3天计算下次最早采购日。
- 例：第2天首次采购，选择每天则第3天、第4天继续；选择每三天则第5天、第8天继续。
- 到期但未上班或上一趟仍在途时，等员工符合条件再尝试，不会同时派出多趟。
- 一次尝试失败也计入周期，资金或车辆不足时，不会每天或每分钟反复刷失败；等下个周期再尝试。界面明确提示。
- 当天保存不扣钱、实际出发才取款、按清单顺序部分购买、返店退零钱等规则不变。

采购窗口标题改为“定期采购清单”，暂停按钮改为“暂停定期采购”。员工列表显示当前频率和下次最早尝试日。

计划保存 `IntervalDays`，复制与存档均保留。旧档缺少频率或值为0时按每天一次处理；原有 `Daily` 字段保留为自动采购开关，不再作为频率名称。

验证：EditMode共566项通过，新增覆盖每三天持续执行、间隔两天不出发、失败后等下个周期、频率和下次日期跨JSON存档、旧档每天默认。无截图场景入口 `PCShopSell.EditorTools.GameSceneBuilder.InteractionRevisionFromBatch` 验证两档频率按钮和保存结果，并回归原有采购、定价、工作和睡眠流程。
