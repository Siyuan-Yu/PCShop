# 3C 与世界层设计 v0.3

> 状态：草案，待与用户对齐。标注 `[建议]` 的是我推荐但尚未确认的选择。
> v0.2：世界层定位为家业的展示与成就层，没有实时动作要素。
> v0.3 变更（用户澄清）：**世界时间是连续的**。走路、做事、睡觉、店铺营业都消耗同一条时间线，顾客进店是实时看得见的；不存在"逛街不耗时"的模式，也取消"每日时间预算"和"营业回放"，改为统一的世界时钟。

## 1. 结论先行

游戏由三层组成：

| 层 | 玩家在做什么 | 性质 |
|---|---|---|
| **世界层** | 在城市里走动，看到自己的店、地产、车队，实时看到顾客走进店里消费；点击建筑进入经营 | 展示 + 成就感 + 入口 |
| **面板层** | 进货、定价、签约、谈判、看行情、读事件、管理员工 | 经营决策（东京股神式） |
| **手操层** | 装机等小游戏 | 技巧操作 |

### 原则
1. **一条世界时间线。** 玩家无论走路、装机、谈判还是睡觉，都在推进同一个世界时钟；玩家忙着的时候，别处的生意照常运转。
2. **表现层服从模拟层。** 街上顾客是经营模拟的可视化，数字是真的，画面是它的演出；世界层不反向影响数值。
3. **没有实时动作要素。** 世界时间在流动，但不需要手速：没有躲避、抢时间、战斗。玩家可以随时暂停。
4. **规模随家业成长。** 起点是冷清的摊位，终局是车水马龙的商业帝国，这个对比本身就是奖励。
5. 仍然不做 3D，不做店内自由走动（进店切到面板层）。

## 2. 时间模型

### 2.1 世界时钟
- 分钟级连续时钟（已实现：`GameClock`、`GameTimestamp`）。每天 1440 分钟，每月 30 天，每年 360 天。
- 时间推进事件按"左闭右开区间"通知订阅者，跨过午夜自动拆成两段，保证营业模拟和顾客生成不会看到跨天的区间；午夜后另有"跨日"事件用于结算房租、工资、账单。

### 2.2 时间控制 `[建议]`
- 暂停 / 1× / 2× / 4× / 8×，类似东京股神的时间条。
- 1× 的参考节奏：1 个游戏分钟约 0.5 秒真实时间（可调）。此时步行 800 米（10 分钟）约 5 秒，一整天（16 小时清醒时间）约 8 分钟，可通过倍速和睡眠跳过压缩。
- 暂停时世界不流动，但玩家可以点击查看、规划和打开面板。

### 2.3 什么消耗时间
| 行为 | 耗时 |
|---|---|
| 在世界层行走/乘车 | 按路径距离和交通工具折算分钟，时钟随行走实时推进 |
| 手操（装机等小游戏） | 小游戏本身不让世界时钟实时走表；完成后按"标准耗时 × 熟练系数"一次性推进世界时间，期间其他店照常营业 |
| 面板里的"看和想"（看行情、读研报、对比价格） | **不耗时**（等于暂停） |
| 面板里的"做"（谈判、面试、拜访、进货验货等） | 明确标注耗时，执行时推进世界时钟 `[建议]` |
| 睡觉 | 睡到指定时刻（如次日 8:00）；夜间自动回家，路程耗时同样计入 `[建议]` |
| "快速前往"（后期解锁） | 自动走完全程，并以较高倍速播放；**世界时间照常消耗**，只是省去手动点击和等待 |

### 2.4 "自己干 vs 雇人"的取舍如何成立（取代原"每日时间预算"）
- **营业依赖在场** `[建议]`：早期摊位只有玩家在时才营业；离开就等于关门，客流流失。
- 玩家做别的事（跑货、谈判、睡觉）时，摊位如果没人就不赚钱，因此：
  - L1：自己守摊赚钱，但进货、社交都要离开摊位。
  - L2：雇第一位员工后摊位持续营业，玩家去做采购、行情、社交。
  - 之后每多一家店，都需要人手。
- 这样"时间稀缺"不再靠一个额度，而是靠"同一时刻你只能在一个地方"来体现，更直观，也让世界层的位置有意义。

### 2.5 营业与顾客
- 每家店有营业时间和营业状态（营业/打烊/缺货/忙碌/无人值守）。
- **营业模拟**（待做）在每个时间区间内，根据店铺条件（地段、口碑、价格、缺货、天气、时段、是否有人）生成顾客到店事件：`CustomerVisit { shop, timestamp, spend }`，消费**实时入账**。
- 账本按事件实时记账；0 点跨日时结算房租、工资等并出日结账单。

## 3. 3C 定义

### 3.1 Character（角色）
- **玩家角色**：创业者，1.0 提供少量外观预设（性别、发型、服装主色），不做捏脸。外观随地位变化；座驾（步行 → 电动车 → 汽车 → 豪车）显示在世界层。
- **顾客小人**（表现用）：
  - 订阅"顾客到店"事件，在店门口附近的人行道淡入，走进店里并消失；偶尔拎着购物袋出来。
  - 外观从少量通用素材随机组合，不具备个体逻辑，不参与关系系统，不存档。
  - 门口人群、排队直观反映客流。
- **员工**：站在自己的店面（门口/橱窗），雇人后店面有人气。
- **主播/关键 NPC**：出现在固定地点，点击进入对话/事件。
- **路人**：氛围用，数量受控。
- 不做全城 NPC 日程模拟。`[建议]`

### 3.2 Camera（镜头）
- **默认**：2D 正交相机，跟随玩家，平滑移动，可滚轮缩放。
- **自由查看**：可拖拽相机查看任意区域（时间仍在流动，或者玩家暂停后查看）。
- **家业总览**：一键缩到全图，叠加图层——产权、收入、客流热力、地价、异常提示（缺货、欠租、无人值守）。
- **里程碑镜头**：开业、扩张、买下重要地块、园区落成等时刻，镜头自动巡游展示成果（可跳过）。
- **进入建筑**：点击店面，镜头推近淡入，切到面板层或手操层；返回后回到原位置。
- **拍照模式**：隐藏界面、自由取景、保存截图（暂停世界时间）。`[建议]`
- 白天/傍晚/夜晚色调与天气作为低成本氛围。

### 3.3 Control（操作）
- **鼠标为主**：点击地面/建筑/NPC 即移动并交互；不依赖悬停和右键，保持触屏可移植。
- **键盘**：WASD 可选，快捷键只做补充（空格暂停、数字键调速）。
- **移动方式**：沿道路路径行走，无碰撞。所有移动耗时一致规则，**没有免费移动**。

## 4. 成就感设计（世界层的核心目的）

| 手段 | 说明 |
|---|---|
| 街景演变 | 家业越大，街景越繁荣：招牌更多、装修档次提升、门口排队、车队、绿化与灯光 |
| 顾客演出 | 实时看到顾客走进自己的店：进店高峰、门口人群、拎袋出店 |
| 收入飘字 | 每笔消费在店面上方飘字，高倍速下合并为汇总 |
| 家业总览 | 一张图看到所有店、地产、车、园区，叠加收入/客流 |
| 里程碑镜头 | 重要事件触发的巡游镜头 |
| 拍照模式 | 玩家可以保存和分享自己的帝国 |
| 对比 | 开局的冷清摊位与终局繁华街区形成强烈对照 |

## 5. 世界层设计

### 5.1 地图
- 一张城市地图，约 6~8 个区域。`[建议]`

| 区域 | 内容 |
|---|---|
| 电脑城 | 起点；摊位、店铺、供应商、同行、装机生态 |
| 老街/美食街 | 餐饮铺位，人流大 |
| 商业中心/写字楼 | MCN 办公室、企业客户、高端商铺 |
| 居住区 | 玩家的家、朋友、恋人、民宿用地 |
| 电竞/娱乐区 | 网吧/电竞馆、直播基地 |
| 汽车城/二手车市场 | 车辆交易、车行 |
| 城郊/新区 | 低价地块，终局园区用地 |
| 银行/政务 | 贷款、证照、规划信息（事件入口） |

### 5.2 实现方式 `[建议]`
**一张底图 + 建筑插槽 + 路径图**：
- 底图：每个区域一张（或分块）街景图。
- 建筑插槽：底图上预留固定位置，运行时叠加店面图、招牌、装修档次、营业状态。
- 路径图：道路节点与边；玩家与顾客小人沿边移动；A* 寻路（已实现），`PathWalker` 按已走距离插值位置（已实现）。
- 每家店有"入口节点"；顾客小人从入口附近出现并走进去。
- 原因：对 AI 美术友好（无需一致瓦片集）；寻路、耗时、位置插值是纯逻辑可测试；内存可控、好移植。

### 5.3 家业可视化
- 每家店有自己的招牌、装修档次、营业状态、员工小人、收入飘字。
- 同类店用同一模板、不同招牌与名称，保持美术成本可控。
- 地产物业：自有、出租、空置用图标/色块区分，出租物业显示租客。
- 园区：终局时在城郊逐步"长出"，总览中成为焦点。

## 6. 表现层如何接入模拟（技术关键）

世界层**只读**经营结果，不反向影响数值：

- `Core` 的营业模拟在时钟的每个 `TimeAdvanced` 区间内产出顾客事件，事件同时驱动账本入账。
- `Game` 层的 `CrowdDirector` 订阅这些事件：
  - 1×~4×：每个事件生成一个可见小人（同屏上限 30~50，超出则抽样），使用对象池。
  - 更高倍速或玩家不在该区域时：不生成小人，只累计飘字/统计。
- 顾客小人不存档、不入逻辑；读档后只需恢复时钟与店铺状态。
- 玩家与顾客的移动由 `PathWalker` 驱动：每帧按时钟推进量换算成已走距离，得到位置。
- 世界层因此可以在不改动任何经营规则的前提下独立迭代、独立优化。

## 7. 地产系统

### 7.1 物业类型
| 类型 | 说明 |
|---|---|
| 摊位 | 电脑城起点，租金低，面积小 |
| 街铺/店铺 | 主力经营场所 |
| 写字楼单元 | MCN、办公 |
| 住宅 | 玩家的家；升级影响形象与关系事件 |
| 仓库 | 囤货容量与成本 |
| 园区用地 | 终局大地块，需要规划与资金 |

### 7.2 获得与持有
- **租**：月租 + 押金；灵活，无增值。
- **买**：一次性或按揭（接账本与贷款）；有增值/贬值风险。
- **出租**：把买到的物业租给 NPC，赚租金；有空置、欠租、租客纠纷。

### 7.3 价值与行情
- 价值由地段（客流、配套）、开发度（装修、周边）、周期（地产行情、政策）共同决定。
- 地产行情复用"宏观因子 → 价格"机制，加入政策/规划因素（新地铁、拆迁、限购等事件）。
- 关系联动：关系好的人脉可能提前透露规划信息。

### 7.4 范围 `[建议]`
- 1.0 约 20~30 个可买/租地块；地产作为 L3 以后的重要玩法，开局不要求。

## 8. 与既有系统的联动

| 系统 | 联动 |
|---|---|
| 世界时钟 | 一切行为推进同一条时间线；店铺营业、顾客、行情、事件都挂在时钟上 |
| 车与地位 | 车降低移动耗时，座驾显示在世界层 |
| 主播 | 在世界层有固定出现地点；探店、带货活动在地图上可见 |
| 关系网 | NPC 在固定地点出现，点击进入对话/事件 |
| 账本 | 顾客消费实时入账；买地、租金、装修、按揭统一入账；0 点出日结账单 |
| 事件系统 | 街上偶遇作为触发源之一（点击式，非实时动作） |
| 行情 | 地价/客流图层；天气与节日影响客流 |
| 园区 | 世界层终局目标 |

## 9. 技术方案

- **代码分层**：
  - `Core`（纯 C#）：已完成 `GameClock`/`GameTimestamp`、`WorldMap`、`Pathfinder`、`PathWalker`、`TravelCalculator`/`TravelPlanner`；待做：营业模拟与顾客事件、`Property`/`Ownership`、地价模型。
  - `Game`（Unity）：`MapView`、`PlayerController`、`CameraRig`（跟随/缩放/总览/拍照）、`BuildingSlotView`、`CrowdDirector`、时间控制条。
- **全部代码生成，不依赖编辑器拖拽**：路径图和插槽位置用数据文件描述，运行时生成对象。
- **灰盒优先**：先用色块和几何占位走通"走路推进时钟—顾客进店—进入建筑—返回"全流程，再换 AI 美术。
- **角色动画**：不做多方向行走循环。静态小人 + 平滑位移 + 轻微上下起伏与朝向翻转。`[建议]`
- **性能与移植**：顾客数量受控 + 对象池；大图分块、压缩纹理；鼠标/触屏双友好。

## 10. 美术需求

| 项目 | 数量级 | 说明 |
|---|---|---|
| 区域底图 | 6~8 张 | AI 生成 + 人工统一修整，风格必须一致 |
| 建筑/店面插槽图 | 每类 3~4 档装修 × 若干类型 | 模板化，招牌文字运行时叠加 |
| 玩家小人 | 数套服装 | 静态图 |
| 顾客/路人小人 | 十来套可随机组合的通用外观 | 静态图，可换色 |
| 员工、主播、关键 NPC 小人 | 按角色数量 | 静态图 |
| 交通工具 | 步行/电动车/汽车/豪车 | 小图标 + 世界层小图 |
| 图层/状态图标 | 若干 | 产权、客流、营业状态、警示 |

美术风格试验需加测：**街景底图的一致性**（同一风格出 3 张不同区域，检验能否放进同一个世界）。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 世界时钟与玩家操作节奏冲突（想慢慢看却一直流逝） | 可随时暂停；面板里的"看和想"不耗时；高倍速和睡眠跳过 |
| 连续时间让经营变成"盯着屏幕等" | 倍速 + 睡眠跳过 + 快速前往；营业事件合并显示 |
| 营业依赖在场导致前期过于苛刻 | 平衡测试；摊位起步成本和收入需要校准；可加"留纸条/限时营业" |
| 世界层变成"跑腿负担" | 后期快速前往；车和员工降低跑腿；店铺布局集中在电脑城 |
| AI 底图风格不一致，拼不成一个城市 | 风格试验先过关；统一提示词模板、色板和后期调色；必要时请美术做统一收尾 |
| 工作量增加 | 灰盒优先；区域按解锁分批出；店面模板化；顾客用随机组合素材 |
| 顾客演出性能压力 | 同屏上限 + 对象池 + 高倍速不生成 |
| 手机/微信内存 | 分块加载、压缩纹理、控制图集 |

## 12. 对路线的影响

- **M1 底座**：时间系统改为连续世界时钟（已完成）；新增"营业模拟与顾客事件"。
- **M1.5 世界层灰盒**：玩家沿路径移动并推进时钟；相机（跟随/缩放/总览）；时间控制条；建筑插槽与点击进入/返回；`CrowdDirector` 灰盒（色块小人走进色块店）。
- VS1 的验证项：**"同一时刻只能在一个地方"是否让自己干 vs 雇人有感**；**实时看到顾客进店是否带来"看见生意"的满足感**；连续时间的节奏是否舒服。
