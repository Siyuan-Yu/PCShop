# 3C 与世界层设计 v0.1

> 状态：草案，待与用户对齐。标注 `[建议]` 的是我推荐但尚未确认的选择。
> 起因：用户希望游戏"不能完全是东京股神那种纯模拟经营"，要能**走上街**，**真的看到自己开了多家店、家业、地产**。

## 1. 结论先行

游戏由三层组成，玩家在三层之间无缝切换：

| 层 | 玩家在做什么 | 形态 |
|---|---|---|
| **世界层**（新增） | 在城市里走动，看到街道、店面、路人，查看自己的店铺和地产，决定去哪 | 2D 城市地图，角色沿街道行走 |
| **面板层** | 进货、定价、签约、谈判、看行情、读事件、管理员工 | UI 面板（东京股神式） |
| **手操层** | 装机、验货等亲手操作 | 轻量 2D 小游戏 |

- **世界层解决三个问题**：(1) 让"家业、地产"看得见；(2) 让"走路耗时 → 车的价值"有直观体验；(3) 解决纯 UI 游戏商店页截图单调的风险。
- **仍然不做 3D。** 世界层是 2D，不做店内自由走动（进店后切到面板层）。
- 世界层是**重要的体验层，但不是玩法主体**：不做开放世界，不做大量支线，走路是"有代价的选择"，不是"必须重复的劳动"。

## 2. 3C 定义

### 2.1 Character（角色）
- **玩家角色**：创业者。1.0 提供少量外观预设（性别、发型、服装主色），不做捏脸。
- **外观随地位变化**：服装档次、座驾（步行 → 电动车 → 汽车 → 豪车）直接显示在世界层，对应"地位/形象"属性。
- **状态**：以每日时间预算（`TimeBudget`）为主；是否加入体力/精力 `[待定]`，默认不加，避免系统膨胀。
- **NPC**：
  - 员工：显示在自己店面门口/店内窗口；雇人后店面"有人气"。
  - 签约主播：出现在特定地点（直播基地、电竞馆、电脑城活动区）。
  - 供应商、客户、朋友、恋人：在固定地点出现（地点即互动入口），不做全城日程模拟。
  - 路人：氛围性，沿路径随机走动，不参与逻辑。`[建议]`

### 2.2 Camera（镜头）
- **默认**：2D 正交相机，跟随玩家，平滑移动，可滚轮缩放。
- **家业总览模式**：一键缩到全图，叠加图层：
  - 产权图层（自己的店、地产、出租物业高亮）
  - 收入/客流热力
  - 地价/行情标注
  - 异常提示（缺货、欠租、员工状态）
- **进入建筑**：点击店面/建筑，镜头推近淡入，切到面板层（或手操层）；离开后回到世界层原位置。
- 时间与光照：白天/傍晚/夜晚色调变化（低成本氛围），天气作为事件和客流因子。

### 2.3 Control（操作）
- **鼠标为主**：点击地面/建筑/NPC 即移动并交互；所有面板可点击完成。
- **键盘**：WASD 可选移动，快捷键只做补充，**不依赖悬停/右键**（保持触屏可移植）。
- **移动方式**：沿道路路径行走，不做物理碰撞。
- **移动耗时**：每次移动按路径距离和交通工具速度折算成游戏内分钟，从当日 `TimeBudget` 扣除。
  - 前期：店与店、店与住所之间要走一段，耗时明显，"跑货 vs 守摊"是真实取舍。
  - 买车后：耗时降低，直接体现"车省时间"。
  - 后期：解锁"快速前往"（一键到已拥有地点，自动播放移动，按交通工具耗时），避免重复劳动。`[建议]`

## 3. 世界层设计

### 3.1 地图
- **一张城市地图**，分为约 6~8 个区域。`[建议]`

| 区域 | 内容 |
|---|---|
| 电脑城 | 起点；摊位、店铺、供应商、同行、装机生态 |
| 老街/美食街 | 餐饮铺位，人流大，租金中等 |
| 商业中心/写字楼 | MCN 办公室、企业客户、高端商铺 |
| 居住区 | 玩家的家、朋友、恋人、民宿用地 |
| 电竞/娱乐区 | 网吧/电竞馆、直播基地 |
| 汽车城/二手车市场 | 车辆交易、车行 |
| 城郊/新区 | 低价地块，终局园区用地 |
| 银行/政务 | 贷款、证照、规划信息（事件入口） |

- 区域各有：客流特征、租金/地价水平、可用地块数量、相关事件。

### 3.2 地图的实现方式 `[建议]`
**一张底图 + 建筑插槽 + 路径图**，而不是自由行走的瓦片地图：

- **底图**：每个区域一张（或分块）完整街景底图，含道路、绿化、背景建筑。
- **建筑插槽**：底图上预留固定位置，运行时叠加建筑图（店面、招牌、装修等级、营业状态）。
- **路径图**：道路上的节点与边，角色沿边行走；寻路用 A*；距离用于折算移动耗时。
- 原因：
  1. 对 AI 美术友好：不需要一致的瓦片集或等距拼接，一张图一张图出，人工修整即可。
  2. 开发成本低：路径图是纯数据，寻路和耗时计算可放在 `Core` 里做单元测试。
  3. 好移植：大图分块加压缩纹理，内存可控（微信小游戏限制见设计文档第 7 节）。
- 代价：灵活性较低，新增区域/地块要出新图；不支持玩家自由建造（本来也不做）。

### 3.3 家业可视化
- 每家店在世界层有**自己的店面形象**：招牌、装修档次（随升级变化）、营业状态图标（营业/打烊/缺货/忙碌）、员工小人、收入飘字。
- 多家同类店用相同模板、不同招牌与名称，保持美术成本可控。
- 地产物业：自有、出租、空置状态用图标/色块区分；出租物业显示租客。
- 园区：终局阶段，城郊建设时地图上逐步"长出"园区建筑，并在总览中成为视觉焦点。

## 4. 地产系统

### 4.1 物业类型
| 类型 | 说明 |
|---|---|
| 摊位 | 电脑城起点，租金低，面积小 |
| 街铺/店铺 | 主力经营场所 |
| 写字楼单元 | MCN、办公 |
| 住宅 | 玩家的家；升级影响形象与关系事件 |
| 仓库 | 囤货容量与成本 |
| 园区用地 | 终局大地块，需要规划与资金 |

### 4.2 获得与持有
- **租**：月租 + 押金；灵活，无增值。
- **买**：一次性或按揭（接账本与贷款）；有增值/贬值风险。
- **出租**：把买到的物业租给 NPC，赚租金；有空置、欠租、租客纠纷。

### 4.3 价值与行情
- 价值由**地段**（客流、配套）、**开发度**（装修、周边）、**周期**（地产行情、政策）共同决定。
- 地产行情复用现有"宏观因子 → 价格"机制，加入政策/规划因素（新地铁、拆迁、限购等事件）。
- **关系联动**：关系好的人脉可能提前透露规划信息（情报），形成"买在利好前"的玩法。

### 4.4 风险与事件
- 空置、欠租、拆迁/规划变动、行情下跌、贷款利息压力。
- 事件由事件系统驱动，选项和后果走统一规则。

### 4.5 范围控制 `[建议]`
- 1.0 约 20~30 个可买/租地块，不做海量交易和复杂金融衍生品。
- 地产投资作为 L3 以后的重要玩法，开局不要求。

## 5. 与既有系统的联动

| 系统 | 联动 |
|---|---|
| 时间预算 | 移动耗时扣除当日预算；车降低耗时 |
| 车与地位 | 座驾显示在世界层；豪车加成谈判，同时是"形象" |
| 主播 | 主播在世界层有固定出现地点；探店、带货活动在地图上可见 |
| 关系网 | NPC 在固定地点出现，点击进入对话/事件；关系好的人透露情报 |
| 账本 | 买地、租金、装修、按揭统一入账 |
| 事件系统 | 街上遭遇（偶遇、搭讪、突发事件）作为触发源之一 |
| 行情 | 地价/客流图层；天气与节日影响客流 |
| 园区 | 世界层终局目标，视觉上由小摊位到园区建筑群 |

## 6. 技术方案

- **代码分层**：
  - `Core`（纯 C#）：`WorldMap`（节点/边/距离）、`Pathfinder`（A*）、`TravelCalculator`（距离 × 交通工具速度 → 分钟）、`Property`/`Ownership`（地块与产权）、地价模型。全部可单元测试。
  - `Game`（Unity）：`MapView`（底图与插槽加载）、`PlayerController`（沿路径移动）、`CameraRig`（跟随/缩放/总览）、`BuildingSlotView`（店面状态展示）、过渡与入口逻辑。
- **全部代码生成，不依赖编辑器拖拽**：路径图和插槽位置用数据文件（JSON/ScriptableObject 由代码读取）描述，运行时生成对象。用户无需使用场景编辑器。
- **灰盒优先**：先用色块和几何占位走通"移动—耗时—进入建筑—回到地图"全流程，再换 AI 美术。
- **角色动画**：不做多方向行走循环。使用静态小人 + 平滑位移 + 轻微上下起伏（Bob）与朝向翻转，成本低，也避免 AI 难以生成一致行走动画的问题。`[建议]`
- **性能与移植**：大图分块、压缩纹理、按区域加载；保持鼠标/触屏双友好。

## 7. 美术需求（相对 v0.2 的增量）

| 项目 | 数量级 | 说明 |
|---|---|---|
| 区域底图 | 6~8 张 | AI 生成 + 人工统一修整，风格必须一致 |
| 建筑/店面插槽图 | 每类 3~4 档装修 × 若干类型 | 模板化，招牌文字运行时叠加 |
| 玩家小人 | 数套服装 | 静态图 |
| NPC 小人 | 员工、主播、通用路人若干 | 静态图 |
| 交通工具 | 步行/电动车/汽车/豪车 | 小图标 + 世界层小图 |
| 图层图标 | 若干 | 产权、客流、警示等 |

美术风格试验需要加测一项：**街景底图的一致性**（同一风格出 3 张不同区域，检验能不能放到同一个世界里）。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 世界层变成"跑腿负担"，重复无聊 | 移动耗时有明确意义；后期快速前往；不做满街 NPC 日程 |
| AI 底图风格不一致，拼不成一个城市 | 风格试验先过关；统一提示词模板、色板和后期调色；必要时请美术做统一收尾 |
| 工作量显著增加 | 灰盒优先；区域按解锁分批出；店面模板化 |
| 世界层抢走核心差异点（硬件行情/主播） | 世界层定位为"承载和展示"，不是新的玩法分支 |
| 手机/微信内存 | 分块加载、压缩纹理、控制图集 |

- 在底座之后、VS1 之前加入 **M1.5：世界层灰盒**：
