## 1. 结论先行

游戏由三层组成：

| 层 | 玩家在做什么 | 性质 |
|---|---|---|
| **世界层** | 在城市里走动，看到自己的店、地产、车队，实时看到顾客走进店里消费；点击建筑进入经营 | 展示 + 成就感 + 入口 |
| **店内层（小店室内）** | 守店：顾客进来挑货、到柜台结账，玩家点击收款；接装机订单 | L1 的主场景（固定镜头） |
| **面板层** | 进货、定价、签约、谈判、看行情、读事件、管理员工 | 经营决策（东京股神式），打开即暂停 |
| **手操层** | 装机等小游戏 | 技巧操作（2D 覆盖层） |

### 原则
1. **一条世界时间线。** 玩家无论走路、装机、谈判还是睡觉，都在推进同一个世界时钟；玩家忙着的时候，别处的生意照常运转。
2. **表现层服从模拟层。** 街上顾客是经营模拟的可视化，数字是真的，画面是它的演出；世界层不反向影响数值。
3. **基本没有实时动作要素。** 世界时间在流动，但不需要手速：没有战斗、抢时间。玩家可以随时暂停。唯一例外是骑三轮车躲交警（见 5.1.3），也只靠选路线，不靠手速。
4. **规模随家业成长。** 起点是冷清的小店，终局是车水马龙的商业帝国，这个对比本身就是奖励。
5. **3D 低多边形 + 固定斜俯视正交相机**（画面效果为 2.5D），可做昼夜、夜景灯光、天气。不做店内自由走动：进店切到固定镜头的室内场景（守店、手操）。
6. 进货、定价、行情、签约、员工、账本等是 UI 面板，不单独做成 3C；线上进货随时可下单，线下进货要走到批发商（耗世界时间，但更便宜、能砍价和攒人脉）。

## 2. 时间模型

### 2.1 世界时钟
- 分钟级连续时钟（已实现：`GameClock`、`GameTimestamp`）。每天 1440 分钟，每月 30 天，每年 360 天。
- **7 天一周**（已实现：`GameDate.Weekday` / `IsWeekend`）：周末商业街客流更大、批发商休息、适合社交。星期从第 1 年 1 月 1 日（周一）起连续循环，与 30 天的月份无关。
- 时间推进事件按"左闭右开区间"通知订阅者，跨过午夜自动拆成两段，保证营业模拟和顾客生成不会看到跨天的区间；午夜后另有"跨日"事件用于结算房租、工资、账单。

### 2.2 时间控制（已确认）
- 暂停 / 1× / 2× / 4× / 8×，类似东京股神的时间条。
- 1× 节奏：**一个游戏日约 3~5 分钟真实时间**（1 游戏分钟约 0.2~0.3 秒），做成可调参数，原型试玩后定具体值。以 0.25 秒计，步行 800 米（10 分钟）约 2.5 秒，16 小时清醒时间约 4 分钟。
- 一局目标 40~60 小时，限期约 3 年（约 1080 个游戏日），配合倍速和睡眠跳过。
- 暂停时世界不流动，但玩家可以点击查看、规划和打开面板；**打开面板自动暂停**。

### 2.3 什么消耗时间
| 行为 | 耗时 |
|---|---|
| 在世界层行走/乘车 | 按路径距离和交通工具折算分钟，时钟随行走实时推进 |
| 手操（装机等小游戏） | 小游戏本身不让世界时钟实时走表；完成后按"标准耗时 × 熟练系数"一次性推进世界时间，期间其他店照常营业 |
| 面板里的"看和想"（看行情、读研报、对比价格） | **不耗时**（打开面板自动暂停） |
| 面板里的"做"（谈判、面试、拜访、进货验货等） | 明确标注耗时，执行时推进世界时钟 |
| 守店结账 | 每次收款推进少量标准耗时（现金最慢，收款码、自助结账更快） `[建议]` |
| 睡觉 | 回家睡到指定时刻（如次日 8:00），回家路程同样计入。**不强制**：到点提醒，没按时睡则第二天精神下降（见 `05-player-life.md`） |
| "快速前往"（后期解锁） | 自动走完全程，并以较高倍速播放；**世界时间照常消耗**，只是省去手动点击和等待 |

### 2.4 "自己干 vs 雇人"的取舍如何成立（取代原"每日时间预算"）
- **营业依赖在场**（已确认）：只有玩家一个人时，离开小店就关门，客流流失；雇人后小店可以持续营业。后期的自助结账**不能**代替人值守。
- 玩家做别的事（跑货、谈判、睡觉）时，小店如果没人就不赚钱，因此：
  - L1：自己守店赚钱，但进货、社交都要离开小店。
  - L2：雇第一位员工后小店持续营业，玩家去做采购、行情、社交。
  - 之后每多一家店，都需要人手。
- 这样"时间稀缺"不再靠一个额度，而是靠"同一时刻你只能在一个地方"来体现，更直观，也让世界层的位置有意义。

### 2.5 营业与顾客
- 每家店有营业时间和营业状态（营业/打烊/缺货/忙碌/无人值守）。
- **营业模拟**（待做）在每个时间区间内，根据店铺条件（地段、口碑、价格、缺货、天气、时段、是否有人）生成顾客到店事件：`CustomerVisit { shop, timestamp, spend }`，消费**实时入账**。
- 账本按事件实时记账；0 点跨日时结算房租、工资等并出日结账单。

### 2.6 守店流程（小店室内，已确认）
1. 玩家走进商业街上自己的小店，镜头切到小店室内固定镜头。
2. 顾客小人进来，在货架/柜台前挑货（停留时间按顾客类型）。
3. **散件**：顾客挑好后到柜台排队，玩家点击结账收款。排队太久会流失。
4. **装机订单**：顾客下单后进入订单队列，玩家打开装机小游戏（2D 覆盖层）手动装；完成后一次性推进标准耗时。
5. **支付方式升级**：前期只收现金（玩家只有按键手机）→ 买智能手机后解锁收款码 → 再解锁自助结账平台。不带现金的顾客在只收现金时会放弃购买；升级后结账更快、流失更少。
6. 玩家离开小店：没有员工则关门；雇人后由员工接待和结账，玩家回到世界层。

与"顾客事件"的关系：营业模拟仍在 Core 产出顾客到店，但散件交易变成"待结账"状态，由玩家结账（或员工、自助结账）后才入账；超时未结账记为流失。

## 3. 3C 定义

### 3.1 Character（角色）
- **玩家角色**：创业者，1.0 提供少量外观预设（性别、发型、服装主色），不做捏脸。外观随地位变化；座驾（步行 → 电动车 → 汽车 → 豪车）显示在世界层。
- **顾客小人**（表现用）：
  - 订阅"顾客到店"事件，在店门口附近的人行道淡入，走进店里并消失；偶尔拎着购物袋出来。
  - 外观从少量通用素材随机组合，不具备个体逻辑，不参与关系系统，不存档。
  - 门口人群、排队直观反映客流。
- **员工**：站在自己的店面（门口/橱窗），雇人后店面有人气。
- **主播/关键 NPC**：出现在固定地点，点击进入对话/事件。
- **路人**：氛围用，数量受控。
- 不做全城 NPC 日程模拟。`[建议]`

### 3.2 Camera（镜头）
- **默认**：3D 场景 + 固定斜俯视角（约 45°）的正交相机，跟随玩家，平滑移动，可滚轮缩放。
- **自由查看**：可拖拽相机查看任意区域（时间仍在流动，或者玩家暂停后查看）。
- **家业总览**：一键缩到全图，叠加图层——产权、收入、客流热力、地价、异常提示（缺货、欠租、无人值守）。
- **里程碑镜头**：开业、扩张、买下重要地块、园区落成等时刻，镜头自动巡游展示成果（可跳过）。
- **进入建筑**：点击店面，镜头推近淡入，切到该店的室内固定镜头（自己的小店/店铺）或面板层（批发商、银行等）；返回后回到原位置。
- **拍照模式**：隐藏界面、自由取景、保存截图（暂停世界时间）。`[建议]`
- 白天/傍晚/夜晚色调与天气作为低成本氛围。

### 3.3 Control（操作）
- **鼠标为主**：点击地面/建筑/NPC 即移动并交互；不依赖悬停和右键，保持触屏可移植。
- **键盘**：WASD 可选，快捷键只做补充（空格暂停、数字键调速）。
- **移动方式**：沿道路路径行走，无碰撞。所有移动耗时一致规则，**没有免费移动**。

## 4. 成就感设计（世界层的核心目的）

| 手段 | 说明 |
|---|---|
| 街景演变 | 家业越大，街景越繁荣：招牌更多、装修档次提升、门口排队、车队、绿化与灯光 |
| 顾客演出 | 实时看到顾客走进自己的店：进店高峰、门口人群、拎袋出店 |
| 收入飘字 | 每笔消费在店面上方飘字，高倍速下合并为汇总 |
| 家业总览 | 一张图看到所有店、地产、车、园区，叠加收入/客流 |
| 里程碑镜头 | 重要事件触发的巡游镜头 |
| 拍照模式 | 玩家可以保存和分享自己的帝国 |
| 对比 | 开局的冷清小店与终局繁华街区形成强烈对照 |

## 5. 世界层设计

### 5.1 地图
- **一张连续的大地图**（已确认），不按区域拆场景；约 6~8 个区域 `[建议]`。
- 布局固定设计：区域、街道、建筑插槽、路径图节点都由数据文件（JSON）描述；`ProceduralCityBuilder` 按数据生成外观，不再用随机种子决定布局（随机只用于外观细节）。

### 5.1.1 起始地图（已确认，VS1 范围）
- **商业街**：一条街约 20 家店，每家一个业态（电脑、餐饮、服装、奶茶、手机维修等）。店铺分大/中/小三种规格（`[建议]` 小约 12㎡、中约 36㎡、大约 96㎡，按 4 大、8 中、8 小配置）。
- **玩家的店**：最小的一间，离地铁站最远，客流最少。
- **地铁站**：在商业街一端，是客流来源；后期用来去其他区域。
- **住所**：5 条街之外的城中村出租屋，便宜，居住环境差。
- **电子配件批发市场**（已确认）：离商业街约 2 公里，几家专营档口（CPU、显卡、内存/硬盘、主板/电源等）。步行约半小时，也可打车、骑小电驴/三轮车或坐地铁。
- 店铺只开在街的北侧，门脸朝 −Z（固定镜头只能看到建筑的 −Z、−X 面）；南侧是人行道、树、公交站和地铁口。
- 客流：街道基础客流 × 位置系数（离地铁站越远越低，最远约为最近的 40%）× 规格系数 × 知名度系数。`[建议]`
- 距离按真实尺度：商业街约 150 米，到城中村约 500 米（步行约 6~7 游戏分钟），到批发市场约 2 公里（步行约 25 游戏分钟）。

以下为后期的完整城市规划（区域随进度解锁）：

| 区域 | 内容 |
|---|---|
| 商业街 | 起点；玩家的小电脑店、同行、各类业态 |
| 老街/美食街 | 餐饮铺位，人流大 |
| 商业中心/写字楼 | MCN 办公室、企业客户、高端商铺 |
| 居住区 | 玩家的家、朋友、恋人、民宿用地 |
| 电竞/娱乐区 | 网吧/电竞馆、直播基地 |
| 汽车城/二手车市场 | 车辆交易、车行 |
| 城郊/新区 | 低价地块，终局园区用地 |
| 银行/政务 | 贷款、证照、规划信息（事件入口） |

### 5.1.2 进货地点与载具（已确认，VS1 范围）
- 线下进货要肉身跑到专门卖某类配件的档口（如"CPU 档口"），找老板谈价。档口工作日营业，周末休息。
- 网上可在"1788"平台下单（UI 面板，不用跑腿），到货要等。找对店铺靠看评价、先下小单试货，以及同行和人脉推荐。
- 交通方式：步行、打车（按里程付费，速度快）、小电驴、三轮车。载具决定移动耗时和一次能拉多少货。

### 5.1.3 交警（已确认，VS1 范围）
- 只在骑三轮车时出现：路上按概率在某些路口刷出交警。
- 交警有**画面上可见的视线范围**（扇形）。玩家进入视线被发现后，交警会追；追上了罚款，`[建议]` 可能扣车。
- 玩家通过选路线绕开视线来躲避，不需要手速。`[建议]` 被追时自动切回 1×，方便玩家反应。

### 5.2 实现方式（已确认）
**3D 模块 + 建筑插槽 + 路径图**：
- 场景：一个连续的 3D 城市，街道、建筑、店面、设施由代码程序生成（见 `06-art-and-rendering.md`），布局由数据文件描述。
- 建筑插槽：场景里预留固定位置，运行时放置对应档次的店面模型、招牌、装修档次、营业状态。
- 打光：一盏主光 + 少量点光，夜间招牌、橱窗、路灯用自发光；昼夜随世界时钟变化。
- 路径图：道路节点与边；玩家与顾客小人沿边移动；A* 寻路（已实现），`PathWalker` 按已走距离插值位置（已实现）。
- 每家店有"入口节点"；顾客小人从入口附近出现并走进去。
- 原因：不依赖手工摆场景（AI 协作无法操作编辑器）；寻路、耗时、位置插值是纯逻辑可测试；以后换美术只替换模块预制体。

### 5.3 家业可视化
- 每家店有自己的招牌、装修档次、营业状态、员工小人、收入飘字。
- 同类店用同一模板、不同招牌与名称，保持美术成本可控。
- 地产物业：自有、出租、空置用图标/色块区分，出租物业显示租客。
- 园区：终局时在城郊逐步"长出"，总览中成为焦点。

## 6. 表现层如何接入模拟（技术关键）

世界层**只读**经营结果，不反向影响数值：

- `Core` 的营业模拟在时钟的每个 `TimeAdvanced` 区间内产出顾客事件，事件同时驱动账本入账。
- `Game` 层的 `CrowdDirector` 订阅这些事件：
  - 1×~4×：每个事件生成一个可见小人（同屏上限 30~50，超出则抽样），使用对象池。
  - 更高倍速或玩家不在该区域时：不生成小人，只累计飘字/统计。
- 顾客小人不存档、不入逻辑；读档后只需恢复时钟与店铺状态。
- 玩家与顾客的移动由 `PathWalker` 驱动：每帧按时钟推进量换算成已走距离，得到位置。
- 世界层因此可以在不改动任何经营规则的前提下独立迭代、独立优化。

## 7. 地产系统

### 7.1 物业类型
| 类型 | 说明 |
|---|---|
| 小店 | 商业街起点，约 12㎡，租金低，位置差 |
| 中店 / 大店 | 约 36㎡ / 96㎡，可放装机台、展示区、仓储 |

店铺本身就是仓库：库存容量按规格（`[建议]` 小 40 格、中 120 格、大 300 格），散件占空间少、卖价低，盒装占空间多、卖价高且顾客更信任（详见 `02-design.md` 4.1）。
| 街铺/店铺 | 主力经营场所 |
| 写字楼单元 | MCN、办公 |
| 住宅 | 玩家的家；升级影响形象与关系事件 |
| 仓库 | 囤货容量与成本 |
| 园区用地 | 终局大地块，需要规划与资金 |

### 7.2 获得与持有
- **租**：月租 + 押金；灵活，无增值。
- **买**：一次性或按揭（接账本与贷款）；有增值/贬值风险。
- **出租**：把买到的物业租给 NPC，赚租金；有空置、欠租、租客纠纷。

### 7.3 价值与行情
- 价值由地段（客流、配套）、开发度（装修、周边）、周期（地产行情、政策）共同决定。
- 地产行情复用"宏观因子 → 价格"机制，加入政策/规划因素（新地铁、拆迁、限购等事件）。
- 关系联动：关系好的人脉可能提前透露规划信息。

### 7.4 范围 `[建议]`
- 1.0 约 20~30 个可买/租地块；地产作为 L3 以后的重要玩法，开局不要求。

## 9. 技术方案

- **代码分层**：
  - `Core`（纯 C#）：已完成 `GameClock`/`GameTimestamp`、`WorldMap`、`Pathfinder`、`PathWalker`、`TravelCalculator`/`TravelPlanner`；待做：营业模拟与顾客事件、`Property`/`Ownership`、地价模型。
  - `Game`（Unity）：`MapView`、`PlayerController`、`CameraRig`（跟随/缩放/总览/拍照）、`BuildingSlotView`、`CrowdDirector`、`StallInteriorView`（小店室内、顾客挑货与柜台结账）、时间控制条。
- **全部代码生成，不依赖编辑器拖拽**：路径图和插槽位置用数据文件描述，运行时生成对象。
- **灰盒优先**：先用几何占位走通"走路推进时钟—进入小店—顾客挑货结账—离开关门—返回世界层"全流程，核心循环验证后再升级美术。
- **角色动画**：占位阶段用几何小人 + 平滑位移 + 轻微上下起伏 + 转向；人物通过"外观组件"接收状态，以后换成带骨骼动画的模型（见 `06-art-and-rendering.md` 第 5 节）。
- **性能与移植**：顾客数量受控 + 对象池；大图分块、压缩纹理；鼠标/触屏双友好。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 世界时钟与玩家操作节奏冲突（想慢慢看却一直流逝） | 可随时暂停；面板里的"看和想"不耗时；高倍速和睡眠跳过 |
| 连续时间让经营变成"盯着屏幕等" | 倍速 + 睡眠跳过 + 快速前往；营业事件合并显示 |
| 营业依赖在场导致前期过于苛刻 | 平衡测试；小店起步成本和收入需要校准；可加"留纸条/限时营业" |
| 守店点结账变成重复劳动 | 支付升级线（收款码、自助结账）逐步减少点击；雇人后完全交给员工 |
| 世界层变成"跑腿负担" | 后期快速前往；车和员工降低跑腿；店铺布局集中在商业街 |
| 程序生成的人物、车辆精度不够 | 外观组件与预制体可替换；VS1 验证后再决定美术升级方案 |
| 一张连续大地图的性能 | 按视野分块启用/禁用；灯光与顾客数量受控 |
| 工作量增加 | 灰盒优先；区域按解锁分批出；店面模板化；顾客用随机组合外观 |
| 顾客演出性能压力 | 同屏上限 + 对象池 + 高倍速不生成 |

## 12. 对路线的影响

- **M1 底座**：时间系统改为连续世界时钟（已完成）；新增"营业模拟与顾客事件"。
- **M1.5 世界层灰盒**：数据驱动的城市布局与路径图；玩家沿路径移动并推进时钟；相机（跟随/缩放/总览）；时间控制条；建筑插槽与点击进入/返回；小店室内灰盒（顾客挑货、柜台结账、离开关门）；`CrowdDirector` 灰盒。
