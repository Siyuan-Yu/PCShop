# 3C 与世界层设计 v0.2

> 状态：草案，待与用户对齐。标注 `[建议]` 的是我推荐但尚未确认的选择。
> v0.2 变更：根据用户澄清，世界层定位为**家业的展示与成就层**——没有实时动作要素；玩家可以逛，能看到小人走进店里消费；核心价值是"建立商业帝国之后的成就感"。

## 1. 结论先行

游戏由三层组成：

| 层 | 玩家在做什么 | 性质 |
|---|---|---|
| **世界层** | 在城市里走动和巡视，看到自己的店、地产、车队，看到顾客走进店里消费；点击建筑进入经营 | **展示 + 成就感 + 入口** |
| **面板层** | 进货、定价、签约、谈判、看行情、读事件、管理员工 | 经营决策（东京股神式） |
| **手操层** | 装机等小游戏 | 技巧操作 |

### 世界层的原则
1. **表现层服从模拟层。** 街上的人、店里的客流是经营数据的**可视化**，不是独立的 AI 模拟。数字是真的，画面是它的演出。
2. **没有实时动作要素。** 不躲避、不抢时间、不战斗，没有需要手速的玩法。
3. **规模随家业成长。** 起点是冷清的电脑城小摊位，终局是车水马龙的商业帝国——这个对比本身就是奖励。
4. **仍然不做 3D，不做店内自由走动**（进店切到面板层）。

## 2. 3C 定义

### 2.1 Character（角色）
- **玩家角色**：创业者，1.0 提供少量外观预设（性别、发型、服装主色），不做捏脸。
- **外观随地位变化**：服装档次、座驾（步行 → 电动车 → 汽车 → 豪车）显示在世界层。
- **顾客小人**（表现用）：
  - 由当日经营数据生成：某店当天接待了 N 位顾客，世界层按比例抽样生成可见小人（有上限），走到店门口、进店、消失；偶尔出现"拎着购物袋出来"。
  - 外观从少量通用素材随机组合，不具备个体逻辑，不参与关系系统。
  - 店面繁忙程度（排队、门口人群）直观反映客流。
- **员工**：站在自己的店面（门口/橱窗），雇人后店面"有人气"。
- **主播/关键 NPC**：出现在固定地点；点击进入对话/事件。
- **路人**：氛围用，数量受控。
- 不做全城 NPC 日程模拟。`[建议]`

### 2.2 Camera（镜头）
- **默认**：2D 正交相机，跟随玩家，平滑移动，可滚轮缩放。
- **巡视模式**：自由查看，可拖拽相机；时间暂停或极慢，专为"看家业"设计。`[建议]`
- **家业总览**：一键缩到全图，叠加图层——产权、收入、客流热力、地价、异常提示（缺货、欠租、员工状态）。
- **里程碑镜头**：开业、扩张、买下重要地块、园区落成等时刻，镜头自动巡游展示成果（可跳过）。
- **进入建筑**：点击店面，镜头推近淡入，切到面板层或手操层；返回后回到原位置。
- **拍照模式**：隐藏界面、自由取景、保存截图。对玩家有成就感和分享价值，对商店页宣传也有帮助，实现成本低。`[建议]`
- 白天/傍晚/夜晚色调与天气作为低成本氛围。

### 2.3 Control（操作）
- **鼠标为主**：点击地面/建筑/NPC 即移动并交互；不依赖悬停和右键，保持触屏可移植。
- **键盘**：WASD 可选，快捷键只做补充。
- **移动方式**：沿道路路径行走，无碰撞。
- **两种移动语义** `[建议]`：
  - **前往**（任务出行）：点击目的地，按路径距离和交通工具折算分钟，从当日时间预算扣除；体现"走路有代价、车有价值"。后期解锁"快速前往"。
  - **巡视**（逛街）：不耗时间，用于欣赏家业；此时游戏时间暂停或极慢。
  - 这样既保留"跑货 vs 守摊"的取舍，又不会让"想逛逛看家业"的玩家觉得被惩罚。

## 3. 成就感设计（世界层的核心目的）

| 手段 | 说明 |
|---|---|
| 街景演变 | 家业越大，街景越繁荣：招牌更多、装修档次提升、门口排队、车队、绿化与灯光 |
| 顾客演出 | 顾客走进自己的店；进店高峰、门口人群、拎袋出店 |
| 营业回放 | 每天结算时，世界层加速回放当天营业：顾客进出、收入飘字，随后弹出日结账单。可跳过、可倍速。`[建议]` |
| 家业总览 | 一张图看到所有店、地产、车、园区，叠加收入/客流 |
| 里程碑镜头 | 重要事件触发的巡游镜头 |
| 拍照模式 | 玩家可以保存和分享自己的帝国 |
| 对比 | 开局的冷清摊位与终局繁华街区形成强烈对照 |

## 4. 世界层设计

### 4.1 地图
- 一张城市地图，约 6~8 个区域。`[建议]`

| 区域 | 内容 |
|---|---|
| 电脑城 | 起点；摊位、店铺、供应商、同行、装机生态 |
| 老街/美食街 | 餐饮铺位，人流大 |
| 商业中心/写字楼 | MCN 办公室、企业客户、高端商铺 |
| 居住区 | 玩家的家、朋友、恋人、民宿用地 |
| 电竞/娱乐区 | 网吧/电竞馆、直播基地 |
| 汽车城/二手车市场 | 车辆交易、车行 |
| 城郊/新区 | 低价地块，终局园区用地 |
| 银行/政务 | 贷款、证照、规划信息（事件入口） |

### 4.2 实现方式 `[建议]`
**一张底图 + 建筑插槽 + 路径图**：

- 底图：每个区域一张（或分块）街景图。
- 建筑插槽：底图上预留固定位置，运行时叠加店面图、招牌、装修档次、营业状态。
- 路径图：道路节点与边；玩家与顾客小人沿边移动；A* 寻路（已实现，见 `Core/World`）。
- 顾客小人：每家店有"入口节点"，小人从附近出生点沿路径走到入口、淡出；出店则反向。
- 原因：对 AI 美术友好（无需一致瓦片集）；寻路与耗时是纯逻辑可测试；内存可控、好移植。

### 4.3 家业可视化
- 每家店有自己的招牌、装修档次、营业状态（营业/打烊/缺货/忙碌）、员工小人、收入飘字。
- 同类店用同一模板、不同招牌与名称，保持美术成本可控。
- 地产物业：自有、出租、空置用图标/色块区分，出租物业显示租客。
- 园区：终局时在城郊逐步"长出"，总览中成为焦点。

## 5. 表现层如何接入模拟（技术关键）

世界层**只读**经营结果，不反向影响数值：

- `Core` 在每日结算时产出 `DailyBusinessReport`：每家店的客流人数、营收、缺货/忙碌状态等纯数据。
- `Game` 层的 `CrowdDirector` 读取报告，按比例**抽样**生成可见顾客（总数设上限，如同屏 ≤ 30~50，对象池复用），并在"营业回放"里按时间分布播放。
- 顾客小人不存档、不入逻辑；读档后根据当天报告重新生成即可。
- 这样世界层可以在不改动任何经营规则的前提下独立迭代、独立优化。

## 6. 地产系统

### 6.1 物业类型
| 类型 | 说明 |
|---|---|
| 摊位 | 电脑城起点，租金低，面积小 |
| 街铺/店铺 | 主力经营场所 |
| 写字楼单元 | MCN、办公 |
| 住宅 | 玩家的家；升级影响形象与关系事件 |
| 仓库 | 囤货容量与成本 |
| 园区用地 | 终局大地块，需要规划与资金 |

### 6.2 获得与持有
- **租**：月租 + 押金；灵活，无增值。
- **买**：一次性或按揭（接账本与贷款）；有增值/贬值风险。
- **出租**：把买到的物业租给 NPC，赚租金；有空置、欠租、租客纠纷。

### 6.3 价值与行情
- 价值由地段（客流、配套）、开发度（装修、周边）、周期（地产行情、政策）共同决定。
- 地产行情复用"宏观因子 → 价格"机制，加入政策/规划因素（新地铁、拆迁、限购等事件）。
- 关系联动：关系好的人脉可能提前透露规划信息。

### 6.4 范围 `[建议]`
- 1.0 约 20~30 个可买/租地块；地产作为 L3 以后的重要玩法，开局不要求。

## 7. 与既有系统的联动

| 系统 | 联动 |
|---|---|
| 时间预算 | "前往"耗时扣除当日预算；车降低耗时；"巡视"不耗时 |
| 车与地位 | 座驾显示在世界层 |
| 主播 | 在世界层有固定出现地点；探店、带货活动在地图上可见 |
| 关系网 | NPC 在固定地点出现，点击进入对话/事件 |
| 账本 | 买地、租金、装修、按揭统一入账；日结账单在营业回放后弹出 |
| 事件系统 | 街上偶遇作为触发源之一（点击式，非实时） |
| 行情 | 地价/客流图层；天气与节日影响客流 |
| 园区 | 世界层终局目标 |

## 8. 技术方案

- **代码分层**：
  - `Core`（纯 C#）：`WorldMap`、`Pathfinder`、`TravelCalculator`/`TravelPlanner`（已完成）；`DailyBusinessReport`、`Property`/`Ownership`、地价模型（待做）。
  - `Game`（Unity）：`MapView`、`PlayerController`、`CameraRig`（跟随/缩放/总览/巡视/拍照）、`BuildingSlotView`、`CrowdDirector`、`BusinessReplay`。
- **全部代码生成，不依赖编辑器拖拽**：路径图和插槽位置用数据文件描述，运行时生成对象。
- **灰盒优先**：先用色块和几何占位走通"移动—顾客进店—进入建筑—返回"全流程，再换 AI 美术。
- **角色动画**：不做多方向行走循环。静态小人 + 平滑位移 + 轻微上下起伏与朝向翻转。`[建议]`
- **性能与移植**：顾客数量受控 + 对象池；大图分块、压缩纹理；鼠标/触屏双友好。

## 9. 美术需求

| 项目 | 数量级 | 说明 |
|---|---|---|
| 区域底图 | 6~8 张 | AI 生成 + 人工统一修整，风格必须一致 |
| 建筑/店面插槽图 | 每类 3~4 档装修 × 若干类型 | 模板化，招牌文字运行时叠加 |
| 玩家小人 | 数套服装 | 静态图 |
| 顾客/路人小人 | 十来套可随机组合的通用外观 | 静态图，可换色 |
| 员工、主播、关键 NPC 小人 | 按角色数量 | 静态图 |
| 交通工具 | 步行/电动车/汽车/豪车 | 小图标 + 世界层小图 |
| 图层/状态图标 | 若干 | 产权、客流、营业状态、警示 |

美术风格试验需加测：**街景底图的一致性**（同一风格出 3 张不同区域，检验能否放进同一个世界）。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 世界层变成"跑腿负担" | 移动耗时只用于"前往"；提供"巡视"不耗时；后期快速前往 |
| 世界层沦为"好看但无意义" | 它承载成就感、入口、客流可视化和地产信息；营业回放串起日结 |
| AI 底图风格不一致，拼不成一个城市 | 风格试验先过关；统一提示词模板、色板和后期调色；必要时请美术做统一收尾 |
| 工作量增加 | 灰盒优先；区域按解锁分批出；店面模板化；顾客用随机组合素材 |
| 顾客演出带来性能压力 | 同屏上限 + 对象池 + 仅在可视范围生成 |
| 手机/微信内存 | 分块加载、压缩纹理、控制图集 |

## 11. 对路线的影响

- **M1.5 世界层灰盒**：路径图/寻路/耗时（已完成）；玩家移动与相机（跟随/缩放/总览/巡视）；建筑插槽与点击进入/返回；`DailyBusinessReport` + `CrowdDirector` 灰盒（色块小人走进色块店）；营业回放。
- VS1 的验证项：移动耗时是否让取舍有感；**顾客进店与营业回放是否带来"看见生意"的满足感**。
