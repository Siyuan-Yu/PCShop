# 每日多货源采购与招聘修正（2026-11-01）

本文替代旧文档中员工采购的单一货源、手填预算与每日开关规则。岗位安排、次日跨店和车辆独占规则继续沿用 [员工管理](13-employees-and-procurement.md)。

## 本次四项调整

1. 店内底部统一显示“离开店铺”，删除“没人看店就关门”“店员看店”等括号备注。实际无人值守等离店后果仍在需要时确认。
2. 招人页在已有候选人时也显示“再贴招聘告示（¥50）”。未聘用的人保留，新一批次日 9:00 到达后追加到名单；聘用只移除选中的人。一张待生效的告示不能重复投放。
3. 员工采购不再输入预算，也不需要额外预留一笔采购预算。系统按整张清单自动计算货款、往返车费、货车运费和合计，出发时统一扣实际费用。旧存档预算字段不再限制采购；1788 自动补货的预算及现金保留规则仍是独立系统。
4. 一位进货员可维护多商品、多档口、多商店的长期清单。浏览货源只筛选可加购商品，不删除其他货源的已选项。“完成”固定在窗口底部，保存整张清单并启用每天一次采购。

## 怎么安排

在顶栏“员工”为当前进货员点击“安排进货”：

1. 默认浏览全部货源，可按商家、品类或搜索筛选。目录包含现有可购买的配件、烟酒饮料水果、大米食材、家具货架；不包含车辆、应用和即时服务。
2. 用减号、数量输入、加号或加五设置件数。同一型号在不同货源分别记一行，不擅自换商家或型号。
3. 在“已选采购清单”核对各货源、商品、数量、金额，可单独移除或清空。切换商家后这里仍显示完整清单。配件行显示目的店库存与在途量。
4. 选择步行加货车、打车加货车、小电驴、三轮车或自有小货车；查看自动费用和不能出发的原因。
5. 点击 **完成**：保存，不立即扣钱；恢复游戏后在可工作时每天按整单尝试一次。也可点 **完成并立即采购** 保存并马上出发。现金不足或当前下班时仍能完成保存，次日再尝试。

每天按固定件数重新采购，不是库存目标补货。日常失败当天不反复尝试，第二天继续；也可编辑后手动立即采购。可暂停每日采购；清空后点完成会停用。前一趟人和货尚未全部回来时不发下一趟，也不提前消耗下一天的尝试机会。

## 行程、费用与到货

- 系统按清单货源分组串联行程，同一商家只访问一次，合计路程、采购耗时、货物重量和运费；每日出发重新按当日价格计算。
- 必须具备整单现金、仓位、档口额度和运输能力，并能在各商家营业时到达、员工下班前返店。任何一项不满足会显示原因，整单不扣款、不偷减数量、不改型号。
- 配件档口工作日 9:00–18:00，农贸市场每天 6:00–18:00，其他采购商店每天 9:00–21:00；零售清单不受电子市场周末停业限制。
- 小电驴、三轮车、小货车继续按空闲台数独占；步行或打车配货车不占自有车。返店释放车辆，货物独立到达。
- 货物送往该员工出发时所在门店。配件和烟酒饮料等进入库存；大米、食材和家具进入当地纸箱，容量不足进临时存放，食材保留保质期。
- 在途订单是出发时清单的副本，编辑今后的每日计划不会改变已付款订单。存读档不会重复扣款、到货或释放车辆。
- 旧存档的全局档口在首次编辑时绑定到各采购行；没有指定档口的旧配件按当前最低价可购货源绑定。原有数量、运输方式及每日状态保留，点击完成后使用新规则。

- `GameSession.Shop.cs` / `GameUi.Shop.cs`：追加招聘候选人、持续展示告示入口、精简离店文字。
- `PurchasePlanTests.cs` / `GameSceneBuilder.PurchasePlan.cs`：逻辑与图形回归。
