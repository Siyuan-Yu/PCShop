## 后续开发必须保持的规则

1. 属性不足的策略仍可选择，低于门槛必定失败；不把属性门槛做成灰掉不能选。金钱不足、缺场所或缺实物属于实际业务条件，可阻止支付或执行。
2. 活动必须有真实人物、地点、过程、耗时及结算；有商品或订单就对真实库存与资金账，不发“文字里成交了”的虚拟收入。
3. 金额要符合时间、经营规模和风险。参考[102金额审查](102-event-money-audit.md)，不把几十元套在高档消费或重大经营上；退款、差额、商品价格按真实交易，不能统一乘十。
4. 玩家二手店与独立旧市场分开；不要为了事件改掉已有玩家经营系统。
5. 交互简洁，文字短，重点信息优先；按钮紧凑，过程在实际场景中表现。新页面不堆实现细节。
6. 所有延迟收益、占位、债务、次数与状态保存；退租、改业态和重复操作要检查原门店身份，不能跨门店发奖励。
