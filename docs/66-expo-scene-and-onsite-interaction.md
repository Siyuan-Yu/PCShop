# 展会现场场景与到场交互

本轮将季度展会接入云帆会展中心的真实3D室内。玩家先在品牌页准备摊位，再在展期亲自出行到场；进入会场后，以展厅、展台、KOL和观众作为主要画面，右侧保留现场判断与报到操作。每季度4天、每种100件、签约KOL和日结费用继续采用[第65篇](65-quarterly-expo-and-kol-payroll.md)规则。

## 如何进入现场

1. 在右上角“品牌 → 展会”预订摊位，选择展品与已签约KOL；中大型摊位需完成海报委托。
2. 开幕日在品牌展会卡片点击“前往会展中心”，或通过城市地图实际出行到云帆会展中心。该按钮使用正常城市出行流程。
3. 进入建筑后自动显示展厅与右侧报到面板。KOL尚未到齐时可以“在会场等10分钟”，实际时钟、NPC出行与日常经营同时推进。
4. 准备齐全后点“报到并开始4天参展”。按每天6段现场事件与舞台环节推进，夜间统一休息。
5. 可保存当前现场进度；重新读档会恢复当前事件、商品余量和人物到场状态。闭展后查看结果，点击“离开展馆”恢复普通城市活动。

尚未报名也能在展期进入公共展厅参观。非展期不展示正在举办的季度展会，馆内显示空置接待处。品牌页的远程筹备不会打开现场；现场操作还会检查玩家确实处于会展中心及本届日期。

## 展厅内容

场景沿用城市已有的低多边形人物、配色与几何模型。会展中心保留原来的实际坐标、朝向和出入口，没有另建一个与城市无关的背景。

| 区域 | 显示内容 | 数据来源 |
| --- | --- | --- |
| 本品牌展台 | 小中大不同宽度的展台、商品模型、名称、剩余库存、备货箱 | 本届实际报名摊位与保管库存 |
| 商品陈列 | 电脑配件、服装展示架、模型类展品 | 选定商品ID；按品类生成简化几何，不是每款独立精细模型 |
| 海报 | 品牌标题、商品图形与新品介绍 | 已完成的海报委托；未到交付时间不显示 |
| 舞台 | 品牌屏幕、当日主题、当前环节、讲台、话筒、音箱与演示台 | 当前参展品牌、日期和事件 |
| KOL站台 | 对应人物、姓名和衣着，舞台或展台站位 | 本届签约名单及真实NPC位置；未到场或仍有活动时不显示为到场 |
| 观众区 | 排队、围观、走动、舞台前聚集 | 当前热度与事件；最多26名匿名展示观众 |
| 周边展区 | 同行新品及创作者展示台 | 公共展览布景，不另造可交易商家或具名NPC |
| 接待区 | 报到柜台、采访和买家洽谈位置 | 当前现场事件 |

卖出商品后，展台余量与备货箱随之减少；闭展退货后撤掉备货箱，标签显示退回数量。观众数量用于表现现场热度，不额外执行一套零售结算；收入、库存、费用仍由原参展逻辑统一处理。

## 现场交互与镜头

右侧面板约占画面宽度的三分之一，移除原来的全屏遮罩。总览、展台、舞台、接待按钮可切换区域；也可直接点场景中的展台、舞台、接待台或观众互动区。滚轮缩放、右键拖动旋转，Q/E转向，V回到展厅总览；正在参展时按F回到当前事件区域。

镜头会把目标区域放在左侧可视部分。展台近景会随小中大尺寸调整距离。使用现有玩家角色在各区域移动，不复制一个新玩家；离场后恢复街道位置和镜头。馆内站位属于同一地点的表现层，不改变城市出行路线。

排队事件显示队列与隔离带，采访和拍摄事件出现摄影机及来访者，故障事件出现警示牌、工具箱和处理人员，采购事件出现买家，舞台环节展示实物演示台与聚集观众。当前事件区域有地面提示。事件与舞台仍采用三选一判断，不是自由操作的演讲或动作小游戏。

报到和决策界面暂停游戏时钟，展厅人物仍保留轻微动作与走位；这些动画不会增加收入、扣费、推进日期或消耗游戏随机数。等待与选项才推进实际玩法。参展期间普通经营快捷操作不可从现场HUD启动，保存按钮保持可用。

## 存档与运行开销

场景由已有报名、库存、KOL位置和事件进度重建，无新增存档格式。已在进行中的4天展会读档后直接回到对应现场。较早的一天三轮旧格式报名仍采用旧接待逻辑。

展厅仅在本人与展期条件满足时启用；布局只在参展内容或存档改变时重建。人物到场信息低频同步，观众复用固定池；库存和事件变化只更新道具、文字与站位。真实KOL在展厅显示时，普通街景人物层不重复显示同一个人。

## 验证范围

自动检查在Unity 2022.3.6f1隔离副本中以无图形模式运行，覆盖地点与日期门槛、三种摊位、实际商品与KOL身份、库存变化、保存恢复、场景点击、相机与玩家切换，以及面板位置与决策操作。详细结果见[验证记录](validation/66-expo-scene-results.txt)。

按用户要求未截图或查看游戏画面；视觉观感与实际渲染帧率仍需游戏内验收。本轮未打Windows包，未提交或推送GitHub。
