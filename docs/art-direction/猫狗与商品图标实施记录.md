## 动物的实现

以 `concept/animals/pet-dog-buildable.jpg`、`pet-cat-buildable.jpg` 为形体标准。评估过人物雕刻流水线；动物保留少量基础形体，以纯色、直腿和明确的猫狗轮廓完成，不引入毛发贴图或新着色器。

- 狗：圆头、下垂耳、浅嘴与胸、白额线、深色鞍斑、短尾。猫：宽圆头、三角耳、粉鼻、两侧胡须、两段翘尾；橘色、沙色与事件棕猫有三道背纹和两道尾纹，灰猫、奶白猫不加虎斑。
- 四种寄养毛色保持 `#D68F4D`、`#C4A178`、`#8C8F8C`、`#E8DBC4`。陪伴狗采用 `#A66E3B`，来歇脚的小猫采用 `#B38557`。
- `PetSceneModels.BuildAnimal` 统一寄养、主人送来时的交接、陪伴狗、店铺事件猫。事件代码原来的方块模型已移除。水碗仍随事件状态独立显示。
- 保留 `PetHead`、四个 `PetHip`、`TailPivot`；腿不增加膝踝，猫尾不增加多关节。每只动物合为一个刚性蒙皮网格，同色部件跨关节合并，仍用现有 `Mats.Lit` 和 URP Lit。
- 寄养动作沿用现有捡球、逗猫、点头、摆尾与走路流程。事件猫狗通过 `PetCompanionMotion` 根据位移迈步，停下时轻点头、摆尾；暂停时停住，切换父级或传送不产生跨场景步态。

## 商品图标的实现

以 §13 的纸面 UI 和 `concept/props/concept/goods.jpg` 为风格依据，使用内置 image_gen 重绘十套原图集，并新增一套九项补充图集，合计 256 个物品键。资源在 `Assets/Resources/ItemPortraits/`，原有十张 PNG 保留 `.meta` GUID。

覆盖配件、食材和饭菜、服装、鲜花、模型、宠物用品、住宅与门店家具、二手旧物、鱼和钓具、事件物品、赛车配件等。九项补图包括四款大型模型、自有通勤衫、自有拼装模型、喷漆台、二手修复台和二手游戏机。游戏机原来的面板和文字占位图已替换。家电按定稿保持干净，坏风扇保留剧情破损。家用／店铺纸箱共用纸箱轮廓。

- 图标采用透明底、水粉笔触、暖棕轮廓，不再使用旧的深蓝背景。
- 每个物品记录独立 UV 范围，并保留原宽高比。AI 图集留白没有严格等分，直接按五等分取图会带入下一格，本轮已修正。
- 图集自身的 alpha 直接参与 UI 渲染；停止套用旧 `ItemPortraitBackdrop` 蓝底色键，避免蓝衣、主板与鱼身颜色被误删。
- 物品 ID、库存、重量、价格及采购规则不变。车辆继续使用已有车型实机缩略图；本轮统一的是物品图集。

生成方式为内置 image_gen，未使用 CLI。原始提示词、参考源和生成文件出处记录在 `tools/pet-item-art-capture/图标生成记录.json` 与 `图标补充生成记录.json`；运行时只读取项目内 PNG。裁切工具只分析 alpha 并写元数据，不重绘或修改图像像素。

## 复拍与检查

编译与复拍在独立预览工程进行，不运行用户已打开的主项目，不使用正式存档。

1. 狗和猫的四种毛色各拍正面、默认高角度、侧面、背面。对照可建版，检查耳、嘴、胸、直腿、背纹、尾根与尾段接缝。
2. 临时存档里准备四只实际寄养宠物，调用实际 `ShopInteriorView`；分别完整拍下捡球、逗猫的 12 个动作时点。
3. 从实际事件控制器生成陪伴狗和店铺猫，再拍走路及点头／摆尾端点。走路摆拍的位移由脚本提供，步态调用生产 `PetCompanionMotion.Advance`。
4. 准备主人到店状态，通过生产交接入口生成动物；随后将陪伴狗切到领养回家状态，检查模型随场景正确重挂。
5. 256 个图标逐项以实际 `FillItemPortrait` 在 88、52、34 像素显示。另拍真实背包与后仓、电脑配件网购、城市进货界面。
6. 商品映射记录枚举实际商品、家具、配件、鱼、事件物品与二手种类，不允许已知目录回退到未知纸箱图。

迭代修正过猫纹凸起、尾段缝隙、胡须离脸、白额线锯齿与孤立白斑、鞍斑浮起、狗耳与尾巴过长、图集串格和宽高拉伸。截图工具也修正了临时隐藏父级及室外地面重叠的取景问题；这两项是摆拍环境问题，没有修改实际场景布局。

本轮不宣称未经测量的“95% 相似度”。按上述具体项目做实机检查；概念中不适用的细毛、腿纹和附件不加入。当前图档保留 Unity 原帧，动图仅缩放合成；走路动图约半速，方便看关节连接。

最终 Unity 批次完成并输出 `PET_ITEM_CAPTURE_DONE`。228 条实际目录键全部命中，256 个图标组件全部复拍。交接入口生成共享狗网格，领养回家后模型父级为实际住宅。编译未出现 C# 错误或运行时异常。使用独立工程的临时存档准备这些状态，不修改正式存档。

## 换机与复现

- 实体模型：`Assets/Scripts/Game/Runtime/PetSceneModels.Animals.cs`、`PetCompanionMotion.cs`。家具部分仍在 `PetSceneModels.cs`。
- 事件入口：`GameController.LifeEvents.cs`、`GameController.ShopEvents.cs`；寄养入口继续由 `ShopInteriorView.Pets.cs` 驱动。
- 图标映射：`Assets/Resources/ItemPortraits/catalog.json`、`GameUi.ItemPortraits.cs`。
- 用带 Pillow、numpy 的 Python 执行 `tools/pet-item-art-capture/extract_icon_regions.py` 可重新分析裁切范围。只在替换图集后需要执行。
- 将 `tools/pet-item-art-capture/PetItemArtCapture.cs` 放进独立 Unity 工程的 `Assets/Editor`，设环境变量 `PCSHOP_PET_ITEM_OUTPUT` 为输出绝对路径，然后执行 `-batchmode -executeMethod PetItemArtCapture.Run`。此入口只准备临时状态和复拍，不调用测试框架、不构建发布包。
- 执行 `make_review.py <复拍目录>` 归档原帧、生成对照 HTML 与动作动图。后续若更换图标，必须复拍全部小尺寸图标；修改几何、关节或蒙皮时，重新检查八机位和动作端点。

本轮修改留在当前美术分支；没有执行新的提交、推送或发布。自动测试及目标设备帧率测试尚未运行。
