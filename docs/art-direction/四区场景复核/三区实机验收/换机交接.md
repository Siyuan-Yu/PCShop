## 下一轮怎样改、怎样验收

1. **先做树冠与林下光影。** 从裁缝铺两侧的小径和长椅开始，对照冠幅、树冠高低、外缘透光和林下亮斑，再把有效改动带到公园池岸、花园庭院及看台周围。社区沿用自然日光，公园保持新建园林的清亮，花园保留冷中性天光。[树冠模型](../../../../Assets/Scripts/Game/Runtime/PaintedWoodland.cs) · [树冠着色](../../../../Assets/Resources/OldTown/Crown.shader) · [林下遮蔽](../../../../Assets/Scripts/Game/Runtime/ForestFloorShade.cs)
2. **公园水面单独细化。** 以浅石池岸为参照，比较柳荫下的较暗倒影、朝天一侧的亮面和岸边窄带。转到 B 机位再看反光与细波是否自然。公园池走 `WaterBasin.Pond`，和湖面、钓场及别墅泳池共用部分着色逻辑；修改共用部分时一起复看这些水体。[河岸公园池体](../../../../Assets/Scripts/Game/Runtime/CityVenueView.cs) · [分水体材质](../../../../Assets/Scripts/Game/Runtime/IndustrialMaterials.cs) · [水面着色](../../../../Assets/Resources/Shaders/LakeWater.shader)
3. **花园别墅玻璃单独细化。** 先看树影或天空遮住了多少玻璃，再看窗框之后能否读出室内空间、暖色陈设和楼层深度。用同一栋楼的正侧两个机位检查，最后回看傍晚与夜间。[别墅窗带与几何](../../../../Assets/Scripts/Game/Runtime/CityArchitecture.ModernVilla.cs) · [街区玻璃材质](../../../../Assets/Scripts/Game/Runtime/DistrictFinishes.cs) · [贴图及来源](材质制作记录.md)
4. **六个地点分别留结论。** 每轮保存“已确认概念、上轮实机、本轮实机”三张并排图，以正常游玩距离、同地点、同朝向的镜头判断。赛场先以相应概念格里的棚顶、器材房与弯道校准机位，另外保留看台正面、入口和弯道作细节检查。鸟瞰用于看路网、绿量和片区轮廓。某一区域或某个赛场未达到 95%，就记录可见差距、继续改该处并复拍，按阶段提交。

现有四镜头色差参考分为社区 **86.7**、公园 **86.3**、花园 **85.1**，其中包含两张鸟瞰。对应的正常距离街景 A/B 分别是 **84.4 / 85.0、84.0 / 83.5、82.5 / 83.2**。这些数字衡量像素颜色接近程度；美术验收还要在图上看轮廓、材质、透光和阴影。赛场单独记录结论。[参考分的算法与原始分项](README.md#画面对比)

## 新设备如何复现

新克隆直接选择本次使用的美术分支。已有仓库可先 `git fetch origin`，再 `git switch art/experiment` 和 `git pull --ff-only`。

```powershell
git clone --branch art/experiment https://github.com/Siyuan-Yu/PCShop.git PCShop-ArtReview
```

在复拍用的项目副本使用 **Unity 2022.3.6f1、URP、Direct3D 11**。编辑器工具与概念图、材质和实机图均随该分支传递。城市预生成缓存由本机重建。下面的 PowerShell 在副本根目录执行，将第一行改为当地 Unity 编辑器的实际路径。

```powershell
$unity = 'D:/UnityEditor/2022.3.6f1/Editor/Unity.exe'
$repo = (Get-Location).Path
$shots = Join-Path $repo ('work/art-review-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Force -Path $shots, 'Assets/ArtCapture/Editor' | Out-Null
Copy-Item -LiteralPath 'tools/district-art-capture/TownMatchCamera.cs' -Destination 'Assets/ArtCapture/Editor/TownMatchCamera.cs' -Force
& $unity -batchmode -force-d3d11 -projectPath $repo -executeMethod CityMapBaker.RunBakeOnly -logFile (Join-Path $shots 'bake.log') | Out-Host
if ($LASTEXITCODE -ne 0) { throw '预生成中断，请查看 bake.log' }
$env:PCSHOP_BAKED_REVIEW = '1'
$env:PCSHOP_TOWN_SHOTS = $shots
& $unity -batchmode -force-d3d11 -projectPath $repo -executeMethod TownMatchCamera.Run -logFile (Join-Path $shots 'capture.log') | Out-Host
if ($LASTEXITCODE -ne 0) { throw '复拍中断，请查看 capture.log' }
Select-String -LiteralPath (Join-Path $shots 'capture.log') -Pattern 'CONCEPT_CAMERA_CAPTURED baked=True sites=182'
```

这批截图使用种子 `914`、游戏时间 10:30、16:9 和 1600×900 分辨率。每处街景的两个机位对准同一地块。A 的水平角为地块朝向 +34°，俯角 36°。B 的水平角为地块朝向 −37°，俯角 31°。社区、公园、花园的 A 机位正交尺寸依次为 14.5、18.5、15，B 取各自的 0.91 倍。玩家默认镜头在到达门口后由游戏的 `SnapCamera` 单独产生。[复拍脚本与赛场机位](../../../../tools/district-art-capture/TownMatchCamera.cs)

[交接原帧](交接原帧/)随仓库保存 30 张未经调色或缩放的 PNG。每区 10 张，分别为街景 A/B、玩家镜头、鸟瞰 A/B，以及对应赛场的固定机位 A、看台正面、全场 B、入口 C、弯道 D。下一轮输出到新目录，原帧用于并排比较。可用现有排版脚本在本机生成一套新图版，并打印同一算法计算的新旧分数。该命令需要 Python 和 Pillow。

```powershell
$review = 'docs/art-direction/四区场景复核'
python tools/district-art-capture/contact_sheets.py $shots "$review/分区概念" "$shots/对照图" --baseline "$review/三区实机验收/交接原帧"
```
