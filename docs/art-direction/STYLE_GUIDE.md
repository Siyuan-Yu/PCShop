## 0. 一句话

**像素感偏重的手绘老城**：厚实、做旧、灰暗偏暖的中国老城区日常生活；细深棕描边；一切像被生活磨过——脏渍、剥落、褪色。**不是**明亮高饱和的卡通，**不是**二次元，**不是**P5 描边风。

## 3.1 密度原则（重要）

- 游戏里不会有拥挤的人群：街上同屏行人 3~5 个即可，不要做人山人海或密集摊位。
- 室内要整洁：家具对齐、地面大片留空、不堆杂物；杂乱感只来自墙面做旧和少量点缀，不靠堆东西。
- 路人模型（char-sheet-04-crowd）是供随机抽取的人物库，不代表同屏数量。

## 5. 渲染与打光（灯光是风格的一半）

目标：**暖、低角度太阳 + 可见的柔和阴影 + 压低的饱和度与对比**。当前原型里已经调好的一组（`DayNightLighting.PaintedLook`，见 §9）：

| 项 | 数值 |
| --- | --- |
| 主光色 | `#FFE0B3`，强度中等；低角度（约 45–50°俯角） |
| 阴影强度 | 0.72（要看得见，但边缘柔） |
| 天空补光 | 强度 0.36 |
| 反射补光 | 强度 0.30 |
| 环境光 | 平的暖灰 `#BDB3A3` |
| 雾 | 暖灰尘雾 `#C7B8A3`，近 70 / 远 300 |
| 色调映射 | Neutral（不要 ACES，避免拉饱和） |
| 饱和度 | −8（白天） |
| 对比度 | +8 |
| 曝光 | −0.1 |
| 颜色滤镜 | `(1, 0.94, 0.86)` 偏暖 |
| 暗角 | 0.2，深棕 |
| 颗粒 | 0 |
| Bloom | 0.12，阈值 1.1（只让窗灯/路灯微微发光） |
| 分色 | 阴影偏冷灰 `#808594`，高光偏暖 `#948A75` |

夜晚/雨天：整体压成深蓝灰，**暖色窗灯与路灯是唯一高饱和点**；湿沥青反射暖光；参考 `scene-04-night-rain.jpg`。

## 6. 材质与质感

- **所有物体统一的手绘质感**：世界空间/物体空间的程序或手绘贴图，带点染笔触、脏渍、剥落、水渍、裂纹；不使用光滑 PBR、不使用渐变。
- **明暗：两档色阶 + 柔阴影**（暗部是亮部的暖灰偏紫，约 `×0.74, 0.70, 0.78`），亮暗交界用小范围平滑。
- **描边**：细、深棕，固定像素宽（约 1px，物体可略粗到 1.2px），**不粗、不黑、不做速度线**。地面/路面不描边。
- 墙面：灰米抹灰，斑驳，底部返潮泛脏，雨水顺窗台流下的竖向脏痕，局部露出砖色。
- 铁栏：圆杆，深棕锈色，带螺栓头。
- 布料：有织纹、磨白、污渍；围裙、床单有褶皱和厚度。
- 木头：干裂、边缘磨圆。

## 7. 建模规范

### 7.1 建筑

- 居民楼 4 层为基准：层高 ≈2.7m，首层架空基座 0.5m；面宽按 2.7m 的开间模数排窗。
- 大瓦屋顶（棕红）+ 女儿墙，屋顶放水箱、天线、杂物、楼梯间。
- 正面构件库（见 `asset-sheet-buildings-props.jpg`）：铁栏窗、带空调窗、阳台+晾衣杆+花盆、卷帘门+小瓦檐、青绿雨棚店面（货架、柜台）、单元门（台阶、信箱）、外挂排水管、楼梯。
- 窗：过梁 + 凹窗 + 窗框 + 窗台及托架 + 竖向污痕；窗内有窗帘或暗色。
- 底层贴街：纸箱、盆栽、电动车、三轮车、塑料凳、垃圾桶、水洼。
- 电线杆 + 电线（下垂弧线）：沿街 + 连到楼上。

### 7.2 地面与绿化

- 草地：深橄榄，斑驳点染，局部偏黄，不要纯色平铺。
- 道路：深沥青，芥末黄虚线，白边线，微裂、油渍、碎石；**路缘与人行道的方砖要有缝**。
- 树：圆形分层树冠，两到三层 + 顶冠，每个团块**两色点染**（暗在下、亮在上），团块要圆润柔和而不是多边形硬面；有树干、根部外扩、2–4 根枝杈。树冠约 4.5–5m 高。
- 灌木：低矮团块，同色系；偶尔带小花。

### 7.3 人物

- **比例：以 §17 用户指定下排样板为准，约 4.5–5 头身**，保留肩宽、躯干和四肢的整体关系。此前 3.8 头身的数字已由当次纠正取代。身高差异仍保留（房东最矮，酒保最高）。
- 脸：**小圆点眼 + 一点高光**，小眉，小鼻，淡淡腮红，小嘴微笑。不要大眼睛、不要二次元反光眼。
- 头发：近黑，成束的发片，有体积；每个角色发型明确（见 §7.4）。
- 手：有手掌+手指（至少拇指+一组手指），**不要球状手**。
- 脚：鞋有鞋头/鞋带/鞋底厚度。
- 衣服：有袖子/裤腿的粗细变化、肘膝褶皱、领口袖口罗纹、口袋盖、纽扣；**布有厚度**，不是贴皮。
- 动作骨骼：髋、膝、肩、肘 4 对关节够用；站立 / 走路 / 双手交叠（房东）。

## 8. UI 风格（早期方案；按钮与色彩以 §13.6 为准）

- 字：使用现有字体，保持可读性；游戏内文字以本地化为准。

## 11. 验收标准

- 随便截一张街景，放在 `reference/ref3_scene.jpg` 旁边，**明度、冷暖、饱和度和阴影**要接近。

## 12. 四区室内与建筑标准（2026-11-26 确认）

概念图在 `concept/interiors/`，实机现状截图在 `concept/interiors/real-current/`（与概念图对照用）。**概念图里的文字、招牌、墙画一律忽略**，建模用空白。

### 12.1 总原则

- **只有城郊是旧、黄、做旧的**。社区开始干净中性，公园、花园逐级更现代、更科技、更高级，但不用霓虹、不闪、不花。
- **科技感靠材质、玻璃、灯带、屏幕**，不靠发光色块。强调光只用暖白、暖琥珀、很淡的青色。

## 14. 家具、车辆与货物建模标准

本节使用 2026-11-26 确认的八张概念原图。单门和双门冰箱均按干净版执行。现行实装范围和取景方式见 §14.7。

### 14.1 总原则

- 画风：等距手绘水粉，哑光，粗暖棕描边，表面只有轻微笔触纹理。**不要**塑料光泽、像素风、写实 PBR 反光。
- 轮廓要一眼认出是什么：保留现在的比例和占地，只补细节（把手、门缝、踏板、灯、屏幕、图案、包装印刷）。
- 颜色沿用现在的主色（床品、车身、商品包装），不要改色相，只加明暗和少量笔触。
- 概念图是方向，不是三视图。尺寸、占地、朝向以代码为准（`FurnitureCatalog`、`RoomSpec`、`MotorCatalog`）。图里的中文有乱码，名称以本地化文本为准。

### 14.2 旧与新（磨损规则）

- 磨损用来表现档次，不是所有东西都画旧：
  - 可以旧：城郊低档家具（硬板床、塑料矮凳、折叠桌、布衣柜）、低价二手车和三轮车、老旧货架。表现为轻微掉漆、锈点、补丁，不要脏污堆叠。
  - **冰箱（单门、双门）必须干净**：表面平整的米白或浅灰，**不要**锈迹、划痕、污渍、掉漆、磨损的边角，把手整齐。其他家电（电饭锅、空调、落地扇）同样保持干净；“坏电风扇”是剧情物件，可以旧。
  - 新、贵的东西一律干净：实木床、实木衣柜、沙发、书桌、跑车、商品包装。
- 同一个家具在不同价位只换材质和旧程度，不换造型。

## 15. 事件 CG（Resources/EventCg，共 43 张）

- 构成：场景底图（JPG 质感 PNG，16:9 约 1024）+ 道具抠图 prop_*（最长边 768）+ 人物抠图 person_*（最长边 1024），由 GameUi.EventCg 运行时叠加，人物无专属图时回退到立绘。
- 场景 10 张：开场到达/饥饿、商铺/住宅租金、公园划船、旧货集市（钟表/唱片）、社区介绍，以及食物特写 prop_hotpot / prop_tastingrice。
- 道具 28 张：统一水粉描边，无地面投影，透明底；人物 3 张（res_coder、res_coder_seated、zhang）。
- 画面规则：不出现文字与标签；脸必须画完整；家电与厨具保持干净；环境光由代码染色（停电/应急/烛光/傍晚/雨）而不是烘进图里。
- 抠图流程：灰底生成 → 边缘泛洪去背景 → 扩 3px 去光晕 → MinFilter+高斯 0.8 柔化 alpha → 按包围盒加 3% 留白缩放。替换 PNG 时保留原 .meta。
- 样图：concept/cg/（10 张标准样图）。
- NPC 无专属抠图时的运行时去背景（ScenePortraits.RemoveBackdrop，对全部 179 个立绘离线验证过）：
  1. 取立绘上方两角的底色，从上边与左右边按严格容差（18）泛洪；底边不作起点，否则白大褂会被吃掉。
  2. 清除被头发/轮廓围住的封闭底色小块（≥6 像素）：平整、接近底色、四周深色占比 ≥ 60% 才删，白衣服的阴影不会误删。
  3. 沿轮廓再吃掉 3 像素浅色光晕。
  4. 解混：轮廓 12 像素内、接近底色且 7x7 邻域里 ≥40% 是强色（头发/轮廓）的像素，颜色换成邻近前景色，alpha 取与底色的混合比例——专门处理发丝间的细缝和发梢。
  5. 透明像素的颜色向外扩散为前景色（防止双线性/mipmap 采样把灰底混回来形成白边），alpha 做 σ0.5 柔化；最后 5% 行渐隐。
  - 立绘导入上限为 1024（NpcPortraitImportRules）；512 会把发丝糊进灰底，抠出来必有白边。
  - 立绘新底色为 #E6E6E8 附近的中性灰；换底色、加渐变背景或出现黑边（曾有 life_leisure_staff_ktv_tier3_day 左右黑边）时要重新检查。
- 已知小问题：person_res_coder_seated 比旧图多了挂绳和手表细节。

## 16. 动物建模标准（2026-11-26 用户确认）

> 已评估人物雕刻流水线；本轮采用少量基础形体与纯色，合成共享刚性蒙皮网格。保留六组动作关节，不增加动物贴图或着色器。下文以本轮实装说明修正原先的逐件渲染方式。

### 16.1 范围

游戏里现有 4 类动物，都按本节建：

| 动物 | 出现位置 | 代码入口 | 现状 |
|---|---|---|---|
| 寄养狗（4 种毛色） | 宠物店寄养区、收留时 | `PetSceneModels.BuildAnimal(dog:true)` | 已统一，圆头、下垂耳、贴合背部的鞍斑 |
| 寄养猫（4 种毛色） | 同上 | `PetSceneModels.BuildAnimal(dog:false)` | 已统一，三角耳、胡须、两段翘尾 |
| 陪伴小狗 | 生活事件（领养、跟随） | `GameController.LifeEvents.cs` → `BuildAnimal` | 已统一，栗棕毛色与位移步态 |
| 来歇脚的小猫 | 店铺事件 | `GameController.ShopEvents.cs` → `BuildAnimal` | 已统一，棕虎斑与事件水碗 |

四类入口均已复用 `BuildAnimal`，只换颜色和是否带水碗，不再内联拼。

### 16.2 总原则

1. **每个部位只用一个基础形体**：椭球、三角锥、锥形圆柱、扁椭球、细扁条。不用毛发、条纹贴图或笔触。
2. **纯色块 + 轻微面感**。不要真实 PBR 毛发，不要做 fur shader。
3. **腿是直的**，不做膝盖、脚踝弯曲。游戏只摆动髋关节（`PetHip`），做弯腿也不会动。
4. **玩具化比例**：大头、短腿、粗身体，从高 45° 的游戏视角看轮廓要一眼认出是猫还是狗。
5. **4 种基础颜色**：毛色、深色（耳、鞍斑、尾）、浅色（嘴、胸、爪）、黑色（眼、鼻）。猫的鼻与内耳另用同一种粉色。浅色 = 毛色向白色靠近 45%，深色 = 毛色向墨色靠近 35%。
6. 不加项圈、衣服、配饰。

|---|---|---|---|---|

| 鼻 `Nose` | 极小椭球 | 狗黑，猫粉 | 有 | 有 |
| 眼 ×2 | 小椭球 | 黑 | 有 | 有 |
| 耳 ×2 | 狗：扁椭球，下垂；猫：三角锥 | 深色（猫的外耳用毛色） | 深色 | 内耳嵌在同一三角锥正面 |

### 17.1 现状：游戏里已经有一套雕刻人物流水线

- **骨骼与着色**：`PlayerCharacterModel` 一副 15 根骨骼（髋、膝、肩、肘等），网格分身体、衣服、腿和鞋三层，颜色按槽位（皮肤、头发、上衣、下装、鞋等 12 种）上色。着色器是 `Resources/Characters/PlayerSoftClay.shader`（`PETSHOP/PlayerSoftClay`）。
- **网格不是代码拼的**：是 Python 脚本用符号距离场雕出来，再用 marching cubes 烘成二进制网格，放在 `Resources/Characters/PlayerB-*.bytes`（34 个）。脚本在 `tools/`：
  - `sculpt_player_b.py`：主角，以及身体、手、鞋、脸、头发等共用的几何函数。依赖 numpy、scipy、scikit-image、fast-simplification。
  - `sculpt_npc_b.py`、`sculpt_npc_neighborhood.py`：几个命名角色。
  - `sculpt_npc_wardrobe.py`：所有 NPC 共用的头（`bake_head`，12 种）、上衣（`bake_top`，8 种：short、jacket、formal、coat、apron、uniform、track、patrol）、下装（`bake_bottom`，3 种：pants、shorts、skirt）。
- **NPC 拼装**：`NpcLook`（`NaturalFigure.cs`）按立绘把人物对应到头型；`CityNpcClothing` 有 12 种服装风格、每种 3 套配色，另给房东、中介、厨师等少数人单独配色。
- **老街区已有一种"手绘人物"效果**：`PlayerSoftClay.shader` 里的 `_OldQuarterFigureZone` 分支，用分级明暗加边缘墨线，但只在老街区附近生效（`DayNightLighting.cs` 里设置）。

以上为改造前的通用流水线。本次三个样本使用 `tools/sculpt_character_samples.py`、PBM2 网格及 `PlayerPainted.shader`，沿用原 15 根骨骼，另补双马尾 2 根和衣摆 1 根；薄围裙、百褶裙使用显式曲面。运行时兼容 PBM1；其他人物资源和着色器不随三人试做批量替换。轮廓壳合入缓存网格的原子网格内，不额外增加 Renderer 或材质批次，但增加顶点与三角面，尚未作帧率基准测试。

所以结论是：**不重建人物，也不做每个 NPC 一个独立模型**。在现有流水线上改渲染、比例和服装款式。

### 17.4 渲染规则（第一步，所有人物一次受益）

| 项 | 规则（原型验证过的数值） |
|---|---|
| 色阶 | 两档：亮面、阴影，过渡很窄。亮面取 `smoothstep(-0.10, 0.30, N·L)`；阴影 = 底色 × (0.66, 0.65, 0.74)，**偏冷、不偏黄**；迎光最亮处再提亮约 10% |

## 22. 地点编号体系、等级图标与底栏快捷前往（2026-11-28 用户确认）

### 22.1 要解决的问题

- 底栏「快捷前往」的按钮用地点全名（「城郊老破小出租屋」「暖爪宠物用品店」），长短不一，全被截断成省略号；下拉三角是深色画在深炭底上，看不清；底栏本身太高。
- 玩家要从名字猜地点在哪个片区，而游戏里本来就有一套地址体系（`city_layout.json` 里 10 条街 `01 城郊旧居街 … 10 花园别墅街`，住宅 `N号住宅`，招租商铺 `N号招租商铺`），底栏没用上。
- 结论（用户确认）：**所有地点用同一套「街号 + 门牌」描述；类别和片区等级由图标表达，文字里不再写城郊、社区、公园、花园。**

### 22.2 编号规则

1. 地址码 = 两位街号 + 「街」 + 空格 + 门牌号 + 「号」，例如 `01街 4号`、`03街 2号`、`10街 12号`。
2. 没有门牌的地点只写街号：`02街`、`03街`。例如批发市场、中介、车站、医院、银行、各类娱乐场馆。
3. **必须有门牌的地点**：住宅、可成为「我的店」的商铺（含空铺、招租商铺、零售商铺）。这样同街两家店、两处住宅不会重名。
4. 门牌来源：
   - 住宅区块用已有的 `blocks[].homeNumber`；
   - 招租商铺用名字里已有的 `N号`；
   - 其余缺门牌的住宅和商铺，在 `city_layout.json` 的地点里新增可选字段 `doorNumber`（整数），补成该街上"下一个没用过的号"，按地点 id 排序稳定生成，生成后写死在数据里，不要每次运行重新分配；
   - 同一条街上同一类别的门牌不得重复。
5. **起始住处**「城郊老破小出租屋」（`home`，街 `s_oldhomes`）：门牌取该街下一个空号。`s_oldhomes` 的住宅已占用 1–26 号，所以起始住处是 **`01街 27号`**（用户原先想要 1 号，但 1 号已被一套住宅占用；若要改成 1 号，须同时把那套住宅改号，由用户决定，默认不动）。同理补号：`home_tier1`（`s_services` 街）、`home_tier2`（`s_sports` 街）、`home_tier3`（`s_newtown` 街）、各 `life_home_*`。
6. 玩家给店起的名字（暖爪宠物用品店）、街道全名、片区名、状态（主住所、已租、已购、有租户、片区未开放）**不放在底栏上**，只出现在悬停提示和下拉列表里。
7. 在 Core 层提供统一入口，所有界面共用，不要各处各写各的：
   - `string PlaceAddressCode(Place p)` 返回 `01街 4号` / `03街`；
   - `PlaceCategory PlaceCategoryOf(Place p)` 返回 22.3 的类别；
   - `int PlaceTierOf(Place p)` 返回 1–4（城郊、社区、公园、花园），用现有的 `DistrictTierOf` 加 1 即可。
8. 世界里的楼牌（`01 城郊旧居街 4号住宅`）已经带编号，保持不变，和新的地址码一致。
