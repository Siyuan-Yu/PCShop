# 店型差异化玩法备忘（2026-11-02）

状态：本篇保留讨论来源与设计收敛记录。已确认的五类店型核心、线下供货上限及最大采购现已实现，当前规则与验证以 [第36篇](36-shop-core-gameplay-and-supplier-stock.md)为准；宠物店玩法仍待讨论，本轮未实现。冰箱永久保存见 [第35篇](35-permanent-fridge-storage.md)。

供货后来进一步细化为批发商/型号/星期共享分配，当前安排以 [第38篇](38-supplier-model-allocation-and-weekdays.md)为准；完整版本与验证边界见 [第40篇](40-current-snapshot-2026-11-02.md)。

## 目标

不同店型应有不同的经营重点，不能只是换一批商品、套用相同的进货和销售流程。优先让玩家在选品、库存、人员或订单上做不同的决策，不为增加店型而增加复杂度。

## 用户提出的方向

| 店型 | 暂定方向 | 希望形成的主要区别 |
| --- | --- | --- |
| 电脑店 | 保留，装机玩法已比较完整 | 科技发展、新品与旧配件淘汰带来的价格变化，结合装机与配件搭配 |
| 手办模型店 | 保留并突出特色 | 动漫、电视剧、电影播出或热度变化带来快速、剧烈的涨跌；热度消退后也可能大跌 |
| 服装店 | 保留，强化季节约束 | 平时价格相对稳定，换季选品与清库存更重要 |
| 生鲜市场／生鲜店 | 用户已确认移除玩家经营店型 | 城市农贸市场与餐馆、生活用食材继续保留 |
| 食品店 → 简易餐馆 | 用户已确认保留餐饮方向，改做加工与堂食 | 进食材、按单烹饪、及时出锅、上菜；独立厨房和餐桌结构 |
| 花店 | 用户已决定移除玩家经营店型 | 之前的花艺订单建议不采用，送礼和城市花店不因此自动删除 |
| 宠物用品店 | 用户已确认保留，玩法以后再想 | 暂缓具体玩法设计；此前推荐、试用和熟客系统不作为实施方案 |
| 二手旧物店 | 用户认可为独立玩法，采用带风险的收购方向 | 听卖家说辞、判断真假、出价收购；买下后才能鉴定，再定价转售 |

### 电脑店

- 沿用已有装机玩法，暂不推翻重做。
- 价格变化的核心因果是科技发展，例如新一代配件发布、旧代产品降价或退出主流。
- 具体新品周期、淘汰速度及旧货价值以后再定。

### 手办模型店

- 价格涨跌速度快、幅度大，明显区别于服装的低频波动。
- 作品播出、角色走红等事件可使相关商品迅速上涨；作品热度下降后价格也会大幅回落。
- 玩家面对的是提前选品、追热度、及时出货与压货风险。
- 暂未指定涨跌百分比与持续时间；不能把例子直接当成已定数值。

### 服装店

- 日常价格相对平稳，主要经营压力来自季节，而不是频繁炒价。
- 棉花产量、山火、暴雨、干旱等可以作为低频供给事件的题材。全年最多约一至两次这类波动，影响周期较长，幅度最多约50%。事件影响哪些款式、50%以什么基准计算，后续设计再确定。
- 希望显著加强不应季服装的需求限制：约90%的顾客不购买不应季衣服，仍允许少数例外。
- 冬季：约90%的顾客不买夏装、春秋装。
- 春／秋季：约90%的顾客不买夏装、冬装；目前将春秋装作为同一季节组理解。
- 夏季：按相同原则，约90%的顾客不买春秋装、冬装。
- 上述90%指顾客对不应季服装的选择／购买限制，不是“90%的顾客不进店”，也不是直接把售价降低90%。是否仍受价格、预算、其他混售商品影响，实施时需统一规则。
- 本轮不调整现有季节参数。

### 已确认去除店型的边界

- 生鲜店、花店退出玩家可选择经营的店型，是本轮明确的设计决定；代码入口尚未调整。
- 生鲜店退出不等于移除城市农贸市场、生活购物、角色吃饭、餐馆食材；花店退出也不等于移除送花或送礼商品。
- 原食品零售类型改做简易餐馆，不能只改名称并继续使用原上架零售流程。
- 实施去除或餐馆替换时，要保留已开的店、库存、员工、采购清单和旧档资产，并提供兼容或转型处理，不能直接清空。

## 简易餐馆：用户确认的方向

- 先前“食品店暂缓”的结论被本次讨论替代，保留餐饮，形态改为简易餐馆。
- 每天补进一些食材，玩家有实际加工操作：投料、烹饪、避免煮糊、及时捞出或出锅，再交给顾客。
- 烹饪采用容易理解的小玩法，不能过于复杂。
- 店内需要加工台／橱柜、冰箱、炒锅或灶台、餐桌；员工需要服务员，布局与普通货架零售不同。
- 冰箱内永久保存，外部食物按原保质期过期。每天采购是补充消耗的经营节奏，不是强制清空冰箱库存。

### 建议的首版循环（助手建议，待讨论）

进食材 → 冰箱备料 → 顾客入座点单 → 备菜投料 → 等到可出锅时段 → 出锅放传菜台 → 送到对应餐桌 → 结账、腾出桌位。

- 第一版只做少量固定菜谱，每道菜约一至两种主要材料；选菜后摆好所需材料，不要求逐刀切菜、自由调味或复杂物理翻锅。
- 火候分“未熟／可出锅／焦糊”，用进度和视觉变化明确提示；合格窗口留出反应时间，数值尚未确定。
- 合格窗口内都能交付，可另有更好口感的小区间；烧糊可以重做，消耗本份食材和时间，不无限追加处罚。
- 玩家前期自己兼顾后厨和上菜；后期服务员负责点单、送菜和收桌，厨师接手烹饪。厨师岗位及自动烹饪规则属于待细化建议，尚未确认实施。
- 首版限制同时烹饪的锅位，不增加洗碗、油烟、卫生、食材逐件切割等并行系统。
- 专用餐馆室内与普通零售分开；共用现有时钟、账本、采购、员工和存档。暂停及倍速下的火候与顾客等待规则需一并确定。

## 宠物用品店：保留，玩法以后再想

- 用户确认保留宠物用品店，但具体玩法留待之后讨论。
- 用户认为之前的“推荐用品＋现场试用＋熟客记忆”方案功能和文本负担偏大；不继续按该方案推进，也不把它当作已确认范围。
- 保留店型意向不代表默认确认任何新宠物资料、试用、美容、寄养或活体系统。

## 二手旧物店：带风险的收购与买后鉴定

### 本轮用户明确的方向

- 核心是带“赌”的成分：玩家猜卖家说的是真是假，据此判断值不值得收、以什么价格收，再决定卖出价；判断正确且进出价合适才能赚钱，判断失误可能亏损。
- 收购区与出售区分开，沿用此前方向。
- 卖家使用有限几套可循环说辞，不为每次交易编写新剧情，控制文本量。
- 有的人讲真话，有的人说假话；说辞可信度可以与人物性格关联，具体规则和概率尚未确定。
- **只有买下以后才能检查，收购前不提供揭示真实状态的鉴定。** 之前“收购前通电测试、根据检测结果决定是否收购”的助手建议被本轮方向替代。
- 收购后检查可发现：好货、瑕疵品、仿造品或完全损坏品。四类的价值、适用品类和出售规则待细化。
- 不要求制作大量鉴定动作、长对话和维修功能，先把猜测、出价、揭晓与盈亏做成完整循环。
- 这是设计确认，尚未改动经营代码或旧档。

### 最小经营循环

卖家带货到收购台 → 给出要价与一段说辞 → 玩家判断、出价或拒收 → 成交付款 → 买后检查揭晓状态 → 按真实状态估值、标价陈列 → 顾客购买，结算实际盈亏。

### 控制复杂度的建议（助手建议，待讨论）

- 说辞按类别少量复用，例如“自用闲置”“别人送的”“急着用钱”“不懂这个东西”；这些说辞既可能为真，也可能为假，不把某句台词固定成正确答案。
- 性格影响可信度的倾向，不建议简单规定某类人永远真、某类人永远假。性格线索如何让玩家了解仍待定，暂不新增长篇人物剧情或复杂记忆系统。
- 物品真实状态在卖家带来时确定，并随交易或存档保留；买后检查负责揭晓，避免反复检查重新抽取结果。
- 第一版检查可采用一次按钮加短暂等待，直接显示结果卡；不需要给每个品类制作独立通电、拆解或维修小游戏。
- 收购前只提供卖家要价、说辞及必要物品信息，不泄露真实状态或精确转售价。已知信息、可参考的行情范围和出价交互待定。
- 收购后的销售尽量复用陈列、定价和结账。真实状态影响价值和购买意愿；不是鉴定出好货就立即自动兑换利润。
- 仿造品按仿品状态转售还是不能上架、完全损坏品按残值处理还是无法出售，以及是否提供废品回收，均未确认。不得默认所有坏货都能保本回收。
- 第一版不捆绑维修、清洁、翻新、复杂议价或买家长对话系统。

### 待定数值与规则

首批物品种类、卖家性格线索、各状态概率、说辞与状态的关联、收购议价方式、各状态价值区间、坏货处置及员工代收规则均待后续讨论，不将举例直接当作实施参数。
