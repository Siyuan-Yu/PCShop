# 帧率与运算优化（2026-11-02）

## 2026-11-03：睡到次日的计算卡顿

睡眠通过主线程逐分钟推进世界。在当前湖城五店场景，睡约一天的剖析耗时5.90秒，其中居民更新5.54秒；主要重复工作是静止居民每分钟为上班出发判断重新构造完整路线。

现为通勤预计分钟数增加会话内缓存，键包括精确位置、目标地点和是否在地点内；位置或目标不同即重新计算，上限4096项，地图节点数变化时清空。实际出发仍创建独立路线，时间、NPC位置、营业和物流继续逐分钟推进，不跳过结算。缓存不写入存档。

同一初始存档、固定种子7、五家店，从08:31睡到次日08:00的对照：每分钟清空缓存以复现旧重复计算时5543.34毫秒，启用缓存633.04毫秒，耗时减少约88.6%。两次完整序列化存档完全一致。Unity 2022.3.6f1隔离工程EditMode相关回归44/44通过，包含睡眠、通勤、性能和三段主线。结果见[原始测试记录](validation/sleep-regression.xml)。这是测试场景的核心计算耗时，不是用户当前存档的实测，也不包含屏幕绘制和界面重建；未重新打包。

## 发现与处理

- **整张地图的树林被合进 6 个巨大网格。** 任意一角进入视野，整个网格都会参与对应绘制/阴影通道。改为按 192×192 的景观局部坐标分块，每块仍按相同材质合并；树木生成、位置、形状和颜色保持原算法，包围盒可以正常剔除远处几何。
- **柜台每 0.4 秒完整销毁重建，包括暂停时。** 普通柜台改成保留控件、原地更新营业数据、库存、等待时间和结账可用状态。队列成员、营业时间、员工状态、任务引导等结构改变才重建。餐馆/二手柜台按模拟分钟刷新，玩家操作仍立即刷新。
- **室内灯光每帧重写所有城市发光材质和路灯。** 改为时间、室内外状态、灯光集合变化时更新；同一分钟从室内返回街道也会立即恢复光照。
- **室内仍扫描整座城市的标签与行人显示。** 隐藏街景时暂停这些显示工作；居民的真实模拟继续运行。室外标签位置保持逐帧跟随镜头，文字/颜色每 0.25 秒检查，未入镜标签不提前创建。HUD 数字每 0.1 秒刷新。
- **家具每帧格式化整份布局字符串。** 改为字段快照比较，检测原对象被修改、增删、排序、品类设置和房间尺寸；没有变化就保留模型。
- **8 倍速时货架显示也按加速时间重复统计。** 改为每 0.25 秒真实时间同步；暂停时存取库存也能正常刷新。复用顾客与排队临时集合，普通门店跳过空的专用经营显示扫描。
- **每位居民每分钟重新创建一整份员工名册。** 改为每个模拟分钟建立一次员工/候选人索引。最近道路节点查询增加精确坐标缓存，上限 4096 项，节点增加时失效，不做坐标取整、不改变路线选择。

## Windows Player 实测

Unity 2022.3.6f1，Direct3D 11，RTX 3070，1280×720。固定种子 7，每场景预热 90 帧、采样 360 帧；关闭帧率上限与垂直同步，每次模拟固定推进 1/60 秒。每组从全新会话开始，不读取或写入玩家存档。测试场景含 90 个地点、60 名居民。

这是同机、固定负载的性能对照，不是玩家机器上的保证帧率。正常游戏仍保持原来的 60 FPS 目标。

| 场景 | 修改前平均帧耗时 ms | 修改后 ms | 修改前 P99 ms | 修改后 P99 ms |
|---|---:|---:|---:|---:|
| 街道暂停 | 5.05 | 2.20 | 6.16 | 3.68 |
| 街道 1 倍速 | 4.93 | 2.46 | 6.40 | 4.39 |
| 街道 8 倍速 | 5.08 | 3.06 | 6.68 | 6.50 |
| 店内暂停 | 2.24 | 1.75 | 7.46 | 2.78 |
| 店内 8 倍速 | 3.79 | 2.83 | 10.94 | 6.62 |
| 家中暂停 | 1.56 | 1.66 | 2.83 | 2.85 |

街道暂停时提交的三角形从约 **4577 万降至 120 万（约 -97%）**，包含绘制通道重复提交，不是场景资产的独立面数。Draw Call 从约 1808 增至 1853，是空间分块的权衡；大幅减少了无关几何处理。家中平均总帧时没有改善，虽然其画面同步代码由 0.50 ms 降至 0.09 ms；不据此声称所有场景帧率都提高。

店内 8 倍速的模拟运算平均由 0.54 ms/帧降至 0.34 ms/帧。每帧内存分配接口在此 Mono Player 返回 0，**该指标不可用，不视为零分配**。后续测试入口用 -1 标注不可用值。

另一次隐藏窗口的 1920×1080 尝试没有提交绘制（Draw Calls=0），已排除，不用于 FPS 结论。新增测试入口在未观察到绘制时返回失败码 2，防止误把被抑制渲染的运行当成高帧率。1080p 画面另由实际渲染截图检查。

## 验证与复现

- 相关 EditMode 回归：**95/95 通过**，覆盖柜台控件、家具、寻路、在岗服务、顾客存档、采购配额/星期排期、核心门店玩法和冰箱。
- 原版与优化版 Core 各运行单店、多店预设 **720 个游戏分钟**，最终资金、库存、订单、队列、居民任务/坐标/目的地/到达时间一致。辅助工具运行在 PowerShell 的 .NET 环境，其耗时用于辅助运算对比，不替代 Unity Player 帧率数据。
- 扩展 CityActivityTests 中，旧约会测试仍期待进入 Running，而修改前 Core 的独立复现同样得到 Cancelled /「场所已经打烊，尚未消费」。旧断言还假设餐厅 Y>40，当前湖城餐厅在负 Y 区域。这组不列入上述 95 项通过；另一条长循环约会测试被中止，未声称全项目所有测试通过。
- 新增 `GameSceneBuilder.PerformanceReviewFromBatch` 检查树林局部包围盒、暂停柜台控件保留及同一分钟室内外灯光切换，并渲染街道/家中/店内画面。

Player 复测参数：`PCShop.exe -screen-width 1280 -screen-height 720 -screen-fullscreen 0 -pcshop-benchmark <绝对报告路径>`。不要加 `-batchmode` 或 `-nographics` 测 FPS；检查报告每个场景的 `drawCalls` 必须大于 0。测试自动退出，不操作玩家存档。报告原始值与 XML 保存在 [验证目录](validation/39-performance-results.txt)。

Unity Profiler 中新增 `PCShop.Simulation`、`PCShop.Views`、`PCShop.UI` 三个采样点，便于后续针对大型存档继续查找瓶颈。
