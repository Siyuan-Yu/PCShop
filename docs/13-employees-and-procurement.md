# 员工管理、进货员与车辆（2026-10-31）

2026-11-01 归档更新：当前采购支持鲜花、生鲜、食品等货源；单项失败跳过并继续，受额度、现金、容量约束时尽量部分采购，结果保存未购原因。最新规则和编译验证边界见 [第 30 篇](30-update-2026-11-01.md)；本篇既有测试数字属于历史版本。

## 员工与工作安排（当前规则）

- 顶栏「员工」按门店分组，也可查看待安排人员。员工卡显示头像、姓名、岗位、职责与日薪，展开可查看效率、班次和次日调动。点击「聘用并安排工作」或「安排工作」，选岗位后可预览实际效果。
- 同一门店可安排多名同岗员工，受该店员工总容量限制。可跨店调动、换岗或设为待安排，实际到岗后才提供岗位效果。
- 进货员不代替收银值守。“安排进货”只在员工**当前**负责进货时显示；明天才调去进货的员工今天仍按现职工作。
- 装机订单由玩家手动处理，或交给已安排到装机岗位的员工。换岗保留工资、经验、班次和采购单。

| 岗位 | 使用的属性 | 选岗时显示的效果 |
|---|---|---|
| 收银员 | 动手能力 | 每单实际耗时，包含结账周转时间 |
| 装机员 | 动手能力、装机经验 | 每台实际耗时，装机经验继续缩短用时 |
| 进货员 | 智力 | 到货源后处理每个型号的用时，往返另计 |
| 销售员 | 魅力 | 购买意愿增加的百分点 |
| 厨师 | 动手能力 | 备料、下锅、出锅和清锅每步操作用时 |
| 服务员 | 体能 | 上菜和收桌每步操作用时 |
| 收购师 | 智力 | 判断二手物品真实成色的概率 |
| 饲养员 | 魅力 | 照料增加的宠物状态，每名最多负责两只 |
| 场馆值守员 | 出勤 | 实际到岗时可维持场馆营业 |

操作用时受属性和个人基础用时影响。选岗预览会列出具体分钟数以及与 50 点属性基准的差值。员工属性和岗位记录随存档保存。[本版完整归档](93-current-game-content-2026-11-09.md)

## 同店换岗与跨店安排

1. 在员工卡片点“安排工作”。
2. 先选做什么，再选在哪家店；或选“待安排”，暂不占店内岗位。
3. 首次安排、同店换岗今天生效；跨店时，目标岗位和目标门店**一起在次日生效**，今天仍留原店做原工作。
4. 生效前可以“取消明日安排”。存档保留目标岗位、目标店和生效日期，读档不提前调动。

待安排员工仍按原日薪领工资，统一计入工资合计和采购现金保留额，可再次安排工作或辞退。在途采购未结束不能立即换岗或待安排，防止提前释放车辆/丢失货物；可以安排次日跨店工作。

昨日工资在跨店安排前结算，不会在两家店重复发放。人员离开后原店订单和预留配件保留；没有可装机员工时重置员工工作倒计时，后续可继续处理。新安排的装机岗位不要求培训，会启用自动装机，按个人效率实际接单。

## 进货操作与分趟运输（更新于 2026-11-10）

在进货员卡片点「安排进货」。默认打开店型对应的实际批发市场，可再按商家、品类或关键词筛选。不同供应商的货可加进同一张清单，切换浏览商家时保留已选。目录覆盖配件、烟酒饮料水果、大米食材和家具货架。

选择运输方式后，系统自动估算计划货款、往返车费和货车运费。点「完成」保存。计划从次日开始按所选频率启动，可选工作日每天、周一三五或每周三，另受各供应商营业日限制。暂停或清空会停止续运和之后的定期计划，已付款的在途商品仍会入库。

每趟按清单顺序尽量采购，检查实际现金、仓位、货源额度、载重、市场营业和下班前返店时间。车辆装满后先返店卸货，再继续同一天的采购。单件或供应商起订量超过整车载重时会说明原因。停运前已买的货正常送达，其他部分按原排期下次重新计算。中途到货简短提示，最后一次到货或无法续运时弹出可滚动的结果。电子批发市场同型号统一报价，玩家和员工共用市场库存。配件和烟酒等进库存，米、食材和家具送当地纸箱或临时存放。

完整操作、兼容规则和最新验证见 [每日多货源采购](16-daily-multisource-purchasing.md)。招聘页保留未聘用候选人，也可再贴告示，次日追加新人；店内底部仅显示“离开店铺”。

## 运输与车辆占用

| 方式 | 车辆要求 | 装载与费用 |
|---|---|---|
| 步行 + 货车 | 不占自有车 | 员工步行往返，货物叫面包车送店，每车 200 千克 |
| 打车 + 货车 | 不占自有车 | 往返打车费 + 按车数计算的货车运费，每车 200 千克 |
| 小电驴 | 一台空闲小电驴 | 整趟最多 20 千克，员工自己运回 |
| 三轮车 | 一台空闲三轮车 | 整趟最多 80 千克，有违规罚款和扣车风险 |
| 自有小货车 | 一台空闲小货车 | 整趟最多 160 千克，按每台每天 ¥60 养护 |

- 车行可购买多台同类车，按钮显示“购买一台 / 再买一台”，每买一台扣一份车价。
- “员工”→“查看车辆与占用”显示各类车总数、空闲数、老板占用、哪位员工使用及扣押数；老板底栏切换车辆也遵守同一份数量限制。
- 员工出发时占一台自有车，返店后释放。老板当前选中的自有车占一台；想交给员工可先把自己的出行方式切回步行。
- 只有一台小电驴时，进货员使用期间其他人不能用；两台则可同时供进货员和老板使用。
- 在途采购保存员工、目的店、运输方式、到货与返店时间、已付款清单以及等待下一趟的商品。读档后继续采购，到货按趟入库，每趟单独记账。待采购件数计入补货计划覆盖，避免其他自动补货重复下单。
- 步行/打车模式中员工与货车可不同时间抵达，列表按员工返店状态显示，货物送达独立提示。前一趟人或货未结束时不能派下一趟。
- 在途员工/货物未完成时不能辞退进货员或退租目的店；正在被员工使用或被扣押的车不能出售。
- 配件送到出发时所在的那家店；计入该店在途库存和仓位，避免另一家店错误算作已经补货。在途配件也计入库存估值。
- 三轮车员工出差返程有 15% 的违规检查概率，罚款沿用现有 ¥200；被检查后按原扣车概率决定是否扣押，须去车行每台 ¥500 赎回。该首版参数仍需平衡。

## 叫货车快捷入口

底栏新增“叫货车”，直接打开原有货车装货单，选择货物与送达地址，不需要先打开手机。手机通讯录里的“货车司机老蔡”入口和原有搬货流程保留，两处使用同一套逻辑。

## 存档与代码

- `GameSession.Workforce.cs`：统一员工列表、次日调店、进货单报价与派出、员工/货物在途推进、车辆总数及占用。
- `GameUi.Employees.cs`：员工列表、调店选择、车辆占用和三步采购界面。
- `Employee` 保存稳定身份、待调岗位/门店/日期、个人装机和采购效率、采购计划与最近结果。旧员工读档生成身份，保留原有姓名、工资、班次和熟练度。
- `SaveData.idleEmployees` 保存待安排员工，工资照常结算；`SaveEmployee.hasTransferRole` 区分新旧调动格式，旧档没有目标岗位时沿用原岗位。
- `OwnedShop.Buyer` 保存本店当前负责进货的员工；主店和分店均有独立 `hasBuyer` 标记，防止 Unity JSON 把空字段变成未雇佣的零薪员工。
- `ownedVehicles` 数组允许同类多项，兼容旧档的一类一辆；新增扣押台数和在途采购字段。小轿车/小货车养护按总台数结算。
- 本次未改变已有店铺侧栏的暂停/继续规则，员工管理和采购弹窗按普通窗口自动暂停。
