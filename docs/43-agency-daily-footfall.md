# 中介展示每日经过人数，并按人数报价（2026-11-02）

租铺选址不再显示“地段客流×0.xx”和客流条，改成“预计每日经过约N人”，并显示最近地铁、最近住宅的可达道路距离及室内面积。签约核对页也重复展示人数，租金、押金、中介费和剩余现金继续直接显示金额。

## 人数与月租

估计的是普通一天经过店门口的客流，不等于进店人数、成交人数或画面中必须同时生成的NPC数量。营业时间、店型、名气、陈列、定价、值守和接待容量仍影响实际营业。

- 地铁使用所有站点中最近的可达道路距离，不再把老商圈锁定为第一个地铁站，也不按全图最远店铺归一化。
- 住宅同时计入具名住所和地图中旧居、公寓、豪华公寓、别墅填充建筑。按住宅类型估算住户密度，越近影响越大，密集住宅比稀疏住宅提供更多潜在客流。
- 大铺面的覆盖范围更大：小/中/大铺按48/108/216平方米对应1/2.25/4.5的面积权重。大小只在人数中计入一次，零售模拟不重复放大。
- 最近站和住所按道路距离计算，封闭湖桥不构成捷径；不可达来源不贡献“近距离”客流，界面显示无可达来源。
- 新挂牌月租为“预计每日经过人数×5元”，取消随机租金浮动和开局铺面的固定特例。预计人数更高，报价一定更高；同人数同报价。当前地图61个商铺约236—1484人/天，月租1180—7420元。

当前开局48平方米小铺：约299人/天，最近地铁150米、最近住宅124米，月租1495元。无中介折扣时，首月租金＋押金＋中介费合计4485元，万元开局付完余5515元。这是当前地图实际计算结果，不是写死的展示文案。

## 实际经营与存档

普通零售按同一人数决定基础进店机会；既有时段、店型、口碑、节假日和经营修正继续生效。餐馆与二手店按人数调整来访间隔，专用场馆的邀请机会也受人数影响；容量与实际到店条件继续约束接待。物业缺少现有租约/挂牌价时，也使用同一月租报价作为估值依据。

已签租约、提前签约、押金和既有产权价格不追溯修改。旧存档的未签挂牌首次加载时改用新报价，保存 `shopFootfallVersion=1` 后不会反复迁移；现有租约仍按原金额收租。调试接口显式指定报价时保留其测试用途，不属于自动市场报价。

估算按静态地图缓存，每个铺面只计算一次道路距离和住宅影响，界面刷新及每分钟营业查询复用结果。当前地图61间商铺首轮估算约129ms（本机EditMode一次记录，非帧率承诺），之后1万次重复查询复用同一结果；不新增每帧全图寻路或按预计人数生成大量模型。

## 数值维护

核心在 `ShopFootfall`：基础80人，地铁贡献 `220/(1+道路距离/180)`；住宅有效住户按 `住户数/(1+道路距离/180)^2` 汇总，再以 `200×有效住户/(有效住户+160)` 计算贡献；合计乘面积权重并取整。住宅楼住户估计为旧居24、公寓80、豪华公寓48、别墅8，住宅阵列按行列数计入。填充住宅通过最近道路节点连接，并计入建筑到节点的距离。

UI仅展示最终人数和直观距离，不要求玩家理解上述参数。后续平衡可调整客流及每人租金系数；新行情不应追溯修改已签租约。
