# 性能、材质加载及剩余失败复核

> 后续修正：复查发现本轮巡检名称里的“1x / 4x”是内部速度 1 / 4，对应玩家界面 **0.5× / 2×**，不是正常 1× / 4×。下面的原始 FPS 数据保留，但不能据此判断正常速度已达标。120 FPS 目标、测量口径修正与后续代码修改见 [160](160-120fps-and-deferred-recovery-2026-11-27.md)。

## 本轮结论

用户要求优先检查性能、剩余 bug、实际帧率及材质是否仍未加载。本轮在原有 `art/experiment` 工作区修复并验证，没有切换分支、生成发布包、提交或上传。保留原有未提交内容及用户编辑器；测试在隔离工程运行。

当前主要问题是长时间结算与部分转换的停顿，正常游玩镜头的平均绘制帧率有余量。不能用高平均 FPS 代替睡眠、读档的响应性验收。

## 已实施的优化

1. **NPC 重复查询。** 初始分段计时中睡眠约 5.91 秒，`TickCityPeople` 占约 5.30 秒。减少同一地点的重复字典查找；缓存固定街道的区域归属、固定居民定义、NPC 工作地点解析；非工作时间先排除，再查询场所营业与产权。工作地点缓存键包含定义中的工作／住址和当前住所，地点数变化使缓存失效。营业、空置、员工在岗、通勤、预约等动态状态仍逐分钟检查。
2. **过期地图缓存。** 主项目原派生缓存为版本 15，当前要求版本 16，布局 SHA256 也不一致，正式入口每次退回现场建图。本轮用 `CityMapBaker.RunBakeOnly` 重新生成版本 16，并替换本地派生缓存；旧文件保留在 `D:/tmp/pcshop-performance-20261127/bake-v16/previous-cache-v15`。没有改变布局或美术参数。
3. **测量入口。** 增加编辑器 Game View 巡检，记录真实帧间隔、绘制调用、转换耗时、可见材质与流式贴图状态。正式入口异步建图，先预热 4 秒，再采样至少 6 秒／60 帧；检查实际提交绘制。主动请求 PlayerLoop，避免后台约 10 Hz 节流污染 FPS。

地图缓存属于 `.gitignore` 内的 `Assets/Generated/CityBake/`，不是本轮版本化资源交付。换设备或布局版本更新后可在独立 Unity 工程执行 `CityMapBaker.RunBakeOnly` 重新生成；这是资产预生成，不是 Windows/WebGL 打包。现有发布构建入口也会执行预生成检查。本轮没有执行发布构建。

## 当前画面性能

Unity 2022.3.6f1，RTX 3070（Unity 报告图形内存 8,018 MB），1920×1080，正常镜头，关闭垂直同步及帧率上限，默认画面质量。每个场景时间设为第 15 天 10:00，按真实帧间隔推进模拟，普通速度约 6 秒推进 18 个游戏分钟。跨区位置为测试直接准备，不代表实际走过整个区域。没有满店、多店大存档或赛事满场压力测试。

| 取景 | 平均 FPS | P99 帧耗时 | 样本最长帧 |
| --- | ---: | ---: | ---: |
| 城郊首店外 | 163.5 | 8.60 ms | 16.13 ms |
| 社区中介附近 | 142.5 | 12.67 ms | 22.93 ms |
| 公园中介附近 | 137.4 | 17.58 ms | 19.11 ms |
| 花园中介附近 | 141.1 | 22.04 ms | 22.52 ms |

| 起步店室内 | 228.9 | 7.02 ms | 11.78 ms |
| 居家室内 | 312.4 | 4.88 ms | 7.19 ms |

P99 是 99% 采样帧不超过的耗时；60 FPS 的每帧预算约 16.67 ms。公园、花园仍有超过该预算的慢帧，不能宣称全程稳定 60 FPS。正式游戏默认目标帧率仍为 60，本表是解除上限后的编辑器样本，不能直接当作发行包或其他显卡的帧率。

转换单独计时，不混入预热后的 FPS：初次准备首店外约 138 ms，进入店内约 113 ms，进入家中约 14 ms，JSON 反序列化、重新接入会话并重建画面约 593 ms。最后一项包含测试里的 JSON 序列化，不包含磁盘读取存档。

新版地图缓存成功走 `loading_baked_map`，本次正式入口总耗时 4,275 ms，没有回退现场生成。此前旧缓存回退尝试记录 14,611 ms，但该尝试同时存在编辑器后台节流，**不能将两个数字直接计算成缓存的加速百分比**。

Unity 进程内引擎分配统计约 1.66–1.70 GB，图形驱动分配统计约 998–1,051 MB，贴图统计约 129–133 MB。这不是操作系统完整独占显存占用，也不是长期内存泄漏验收。没有根据这组样本削减树木、纹理分辨率或建筑细节。

## 材质加载检查

九个取景的可见渲染器中，空材质数、错误／不支持的着色器数均为 0。刚切换场景以及预热结束时，流式贴图待加载数均为 0；采样结束可见贴图没有未达到目标 mip 的情况。正式入口、四区域、赛场、室内和读档后的取景都输出了截图，抽查室外与室内没有出现粉色错误材质或明显未加载的表面。

该检查覆盖本次镜头，不能证明地图每个角落、每名 NPC、全部商品和所有事件 CG 都已验收。纯色表面和原有低细节造型不能仅凭“没有贴图”断定加载失败；本轮未将有效的纯色材质当作错误替换。

## 剩余问题与如何继续修

| 类别 | 已有证据 | 处理方式／状态 |
| --- | --- | --- |
| 睡眠、住院同步等待 | 查询优化后仍约 4.3–4.4 秒 | 高优先级。下一步应将长时间跳转做成有执行状态的分帧任务，保持逐分钟结算顺序，处理中禁止重复操作，并在安全状态处理存档。先解决画面与输入长时间不响应，再继续压缩计算量；本轮尚未完成这项调度改造。 |
| 读档及首次进室内停顿 | 会话重建约 593 ms，首次店内约 113 ms | 拆分存档恢复、人物／室内模型创建和 UI 重建计时；预热复用资源或分帧恢复，完成后再恢复交互。本轮未把读档停顿隐藏进平均 FPS。 |
| 花园少量慢帧 | P99 约 22 ms，4 倍速最长约 34 ms；花园约 2,205 次绘制调用 | 接着区分渲染线程、阴影、可见细节和模拟分钟峰值。可以做局部材质合批及剔除，不能把整城合成巨大不可剔除网格，或为提高 FPS 直接删树、改布局。 |
| 深夜餐饮预约 | 21:42、23:42、01:00 三个旧用例仍未通过 | 需继续核对场所时段、实际在岗服务和主动结束路径，尚未认定根因，不擅自改营业规则。 |
| NPC 工作／出行 | 赛场关闭时工作人员任务仍为 Working；一个长途测试期待 Taxi、实际 Walk | 分清工作人员班次与对外开放、距离校准后实际交通选择；需要单独复现，不能恢复旧测试期待作为修复。 |
| 其他经营失败 | 房产金额、贷款、员工运输、车辆和客流估算等仍在逐例清单中 | 按真实交易与到岗路径核实，优先查扣款、重复结算、货物丢失及经营阻塞；没有全部判为 bug，也没有全部判为旧测试。 |
