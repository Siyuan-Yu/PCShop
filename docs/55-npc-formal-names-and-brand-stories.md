# NPC正式姓名与品牌合作故事

日期：2026-11-03。承接KOL和季度展会系统，补充现有人物的可执行短故事，并把以昵称、职业称呼作为姓名的固定NPC改为正式姓名。正式固定人物仍为120人。

## 姓名与旧存档

- 40位固定人物补齐有姓有名的正式姓名；人物资料、对话标题、任务提示、联系人及源码中的叙事引用同步更新。原本已有完整姓名的人物保持原名。
- 原称呼保存在 `NpcNames.Familiar`，人物资料可看见，人物列表也支持用原称呼搜索。KOL的旧称呼可理解为网名／熟人称呼；正式资料使用本名。
- 不修改 `PersonId`、人物立绘资源ID、关系键、任务节点ID。旧存档中的联系方式、关系、居住地点、已听传记章节沿用原记录。既有历史消息不追溯重写。
- 随机招聘使用姓＋正常名字，例如“王明远、李玉珍”。旧动态员工的四类生成式昵称按原姓转换；雇员ID不变，其他姓名不随意重抽。已绑定固定NPC的雇员恢复为该NPC正式姓名。

## 四类可执行故事

入口：**经营 → 品牌 → 人物故事**。合作人物的普通对话中也有故事入口，样品准备页能前往对应门店。现场交谈须本人在场；远程交谈仍需聊天软件和已交换的联系方式。开始故事只表示认识，不自动交换联系方式。

| 故事 | 人物与触发 | 实际步骤与结果 |
|---|---|---|
| 第一次替你推荐 | 莫文宁，存在真实有效推广／代言合同 | 当面或手机商谈 → 到品牌门店选择商品、交出1件样品并选择价格用途／使用售后方向 → 至少3天后复盘。读取所选店铺的实际营业收入和当前库存；零成交也能诚实收束，且明确营业额不能全部归因于推广 |
| 把测试条件说清楚 | 乔雨桐，存在真实有效推广／代言合同 | 商谈适用范围 → 在实际门店准备1件样品、明确范围，或2件样品、至少等待1天补测 → 回访留下测试条件。不存在“花钱删除缺点”的选项，也不凭空宣称商品有缺陷 |
| 这次带一点新东西 | 模型品牌的陆栀／服装品牌的温岚，已报名一届展会 | 商谈展示愿望 → 在报名来源店确认设计展示／采购洽谈方向 → 完成该届接待及绑定的展后订单，再回访。沿用真实报名商品；不凭空制造新产品，也不重复扣报名样品。第一轮接待开始后不能倒改方向 |
| 名单上多一个名字 | 任帆，已报名一届展会 | 任帆谈起白明的展务愿望 → 实际完成本届接待与订单后，找到白明分享准备记录／简短清单 → 回任帆处复盘。介绍有明确经历依据，不自动替白明发订单或签合同 |

四类故事按品牌各记录一次，设计故事根据行业采用不同人物与对白。记录绑定具体合同或展会，不能拿其他品牌、其他届展会的订单冒充完成。故事不是新的街区晋升门槛。

### 结算与失败收束

- 样品从所选店铺真实现货扣除，不计作销售，不返还虚构利润；准备前展示数量并再次确认。库存不足、地点错误、无效选项不会扣货。
- 合作到期、提前解约、错过展会或订单逾期，可以联系原合作人交代结果。未做完准备和交付不发完成奖励；未到补测时间也不能通过解约伪造补测完成。
- 完成奖励是一次性的熟悉度与适用的商务交情小幅提升，及可回看的具体合作记忆。不会生成销售、免费库存或自动租铺资格。
- 展会、合同、运费与订单继续用既有业务规则结算；故事不会二次收取报名费或二次支付货款。
- `SaveData.brandStories` 保存接受时间、准备方案、源业务ID、门店、商品和结论。旧档缺字段初始化为空；进度复制不共享可变记录。
- 人物资料只追加已收束的合作经历，不提前泄露结果。重复复盘不重复加关系。
