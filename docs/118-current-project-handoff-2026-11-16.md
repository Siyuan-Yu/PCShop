## 城市、地图、物件与住宅

- 湖城包括城郊、社区、公园、花园四片区及十条街。区域按主线开放。地图、中介、资产、出行和活动使用实际地点与路网。新增街区有既有商户和 NPC 住户。商铺与住宅有不同室内尺寸。城郊散步地点、青湾垂钓场分别可去。见 [城市扩建](91-city-expansion-v15.md)。
- WASD 移动、F 交互、B 背包。支持步行、打车、通勤载具、地铁、底栏快捷前往；换导航目的地会更新路线。住宅与装饰商户标记简化，功能场所保留识别底色。游戏每月 30 天，普通倍率为 0.5／1／2／4，初始 1 倍。
- 中介按片区办理商铺、住宅，地图展示街道人流色带，选择房源看预计入店、户型、租购费用。同类店 40 米内按数量分流，商圈详情展示竞争。商业租金每周扣，租金取决于客流、区位、面积和行情。中介熟悉度影响中介费。住宅可同时租多套，退租时须保留住处，开局旧出租屋周租 ¥500。房产全款购买，可保有原住户并收租。资产里的地图用实际街区关系定位，区分已买、租用及其他物业。见 [物业](82-cash-only-properties.md) 与 [资产](84-assets-stores-and-property-map.md)。
- 家中有床、家具、背包、后仓、电饭煲和冰箱。开局现金 ¥15,000、20 千克米，先用电饭煲做第一顿饭。做好的饭可吃或放包里，背包里的饭可自动食用。电饭煲查背包和家中后仓，提供白饭、青菜、鸡蛋、豆腐、肉末焖饭。原始食材长期保存，外放熟食有保质期，冰箱可永久保存。批量入库保留成品食物，食材可按接收场所的规则存入。住院病倒过一天。气温、穿戴、天气和家中舒适度参与生活。

| 店型 | 可玩的业务 |

- 柜台看今日营业额、进店和流失，点击可看商品成交及离开原因。知名度影响客流，口碑影响购买意愿，两项无显示上限。柜台还可改名、调整营业时间、查商圈、查看缺少设施和下一步。新店默认 08:00–22:00。初次装修后若当天无法开业，入门任务引导回家使用睡觉流程。定价实时预览购买意愿，确认才生效，参考价最高 3 倍。
- 货架同时限制重量和件数，库存面板可按货架展开，后仓按紧凑明细显示。装修、设施采购、家具配送与实际摆放关联，缺设施时可指引采购或摆放。包与后仓间通过背包界面操作。见 [货架容量](44-shelf-item-capacity.md) 与 [经营核心](36-shop-core-gameplay-and-supplier-stock.md)。
- 采购订单使用实际货源与送达地点。默认按店型选批发源，手动能调整；送货优先匹配门店类型并记住有效目的地。电子、服装、模型及宠物批发周一至周五 09:00–20:00。定期采购可每天工作日、周一三五或每周三，支持固定数量和缺口补货。额度按供应商、具体商品、采购日共享，进货员跨店相互占用；自运可分趟，货车供员工进货使用。手机网购自有收货地点。见 [员工与采购](13-employees-and-procurement.md)。
- 员工管理按店展开，候选人显示工作相关属性。雇用、换岗、调店与排班采用实际门店和岗位规则。装机员限电脑店，厨师、服务员、收购师、饲养员按各店型安排。收银、装机、采购、销售、厨师、服务员、收购和饲养关联不同属性，角色选择时能看到效率；进货员有常驻安排入口，未安排会提示。打工也显示能力影响和额外收益。见 [打工](18-player-work-and-weekly-pay.md)。

## 财务、手机、统计和主线

- 顶栏有我的、背包、手机、任务、员工、日程、资产、采购等入口，部分按界面宽度和解锁状态收纳。手机可管理日程、通讯录、聊天、网购、订餐、证券与直播，日历以每天安排为主。右侧显示近期安排和贷款还款。未赴约弹窗显示关系变化，活动进行时避开新邀约弹出。说明适用 UI 状态见实际入口。
- 经济简报可看每期总收入、总支出、净收支、每日报表曲线及每家店的商品收入、进货、工资、租金等分类。物价页有品类走势和住宅／商铺的售价、周租，按期回顾。自动弹窗频率可选每周、两周、每月或关闭。明细现金流水保留逐笔实际交易。
- 银行全天开放。手动输入贷款金额，也可使用加减和预设，贷款按月单利并可提前结清。第一次现金为负会引导到银行。持债后的提醒显示近一次应还、剩余天数及现金缺口。银行存贷和全款物业分开。医院可支付看诊，现场有工作 NPC；年度住院保险报销与临时资金来自实际事件。见 [资金事件](112-money-events-101-110.md)。
- 手机证券是横向界面。交易所展开个股走势、持仓和成本、盈亏及公司信息。现货和做空交易有数量、手续费、保证金及现金条件。个股按 100 股一手，指数有独立单位。工作日全天可交易，行情按预定时间更新。自有品牌上市未开发，当前不作为中级升高级验收。见 [证券](90-stock-market-and-short-selling.md)。
- 引导从做饭到找中介、采购并摆放开店设施、首批进货、定价确认、首单、聘员工、购手机开通收款码和通勤车逐步开展。主线条件在引导完成后给出目标，城郊到社区、社区到公园、公园到花园分别跟随现行任务。中段展会验收会认可此前已达到条件的记录。见 [主线与片区开放](story-and-district-progression.md)。

## 人物、运动、品牌、展会与赛车

- 固定 NPC 有本名、头像、职业、实际地点、作息、住处、喜好、故事、属性和相处记录。资料、对话、店铺、品牌等共用头像。关系图、联系人、聊天与活动邀请复用人物身份。邀请需熟悉度达门槛，活动可按分类、成长属性及对方偏好筛选，赴约使用真实地点和时间；陪诊等紧急事件可立即出发。主角属性含饱腹、精力、健康、心情、压力、智力、魅力、动手能力和体能等。恋爱与伴侣继续走人物、同行、相处玩法。当前有 124 位固定 NPC 及动态备用头像，3D 角色尚未换风格，见 [117](117-npc-art-update-2026-11-14.md)。
- 消费、餐饮、KTV、酒吧、运动、户外、逛市场和展会有真实时长、价格和效果。篮球、高尔夫按现场蓄力、出手与成绩结算，曾玉试喝以实际调制、试饮和自然味觉反馈进行。摄影产生真实照片，照片保存在 `Application.persistentDataPath/Photos`。垂钓场全天可进，真实池塘选台、选饵、甩竿与遛鱼，20 种鱼可回收、赠送和放生。见 [消费](104-premium-venue-services.md)、[垂钓](105-fishing-system.md)、[现场活动](115-onsite-events-51-58-and-76.md)。
- 品牌可创建、改名、升级及绑定门店。同一个代言合同适用于品牌直播和展会。MCN 实地介绍并给业务名片后谈约，能比较魅力、智力和人气等。主播真实排班、使用可换主播和商品的直播场景，可查看、打赏、结算品牌贡献。季度展会有不同摊位、站台代言人、海报、展品实际扣减、进馆、现场选择和结算，支持联合多个品牌参展以及展后采购订单。企业竞标有试单和后续履约。另有每月电子展、原创展。见 [品牌、展会与竞标](54-brand-expo-tender-playable.md)、[联合参展](81-joint-multi-brand-exhibition.md)、[现有场景素材](75-existing-scenes-and-replaceable-showcase-art.md)。
- 完整版在玩家无欠款且现金超过 ¥100,000 时开放赛车，由许星澜发出邀请，按购买小电驴或三轮车、购买车位、车辆入库、完成一次驾驶的顺序引导。四区公共车库与赛场相邻。通勤车与本区的入库车辆分开，入库车才用于本区练习和比赛。车位购买 ¥10,000／位，各区可调车。货车只给店员采购。练习可 24 小时进，¥100／次。周一大赛、其余日按每三日小赛，碰上周一优先大赛。赛事到场时段为 09:00–18:00，小赛报名费／冠军奖 ¥1,000／¥10,000，大赛 ¥2,000／¥20,000。参赛可有真实 NPC 对手、名单、历次成绩、奖金和交情变化。
- 驾驶固定 1 倍。起步有醒目 3、2、1 倒计时，赛中有速度、油门和刹车反馈、手刹及失稳提示。W／S 加减速，A／D 转向，Shift 手刹，空格／Esc 暂停，R 复位罚时，右键调镜头，V 回正，Tab 全景。车辆外观和驾驶视角在实际赛道中使用，碰撞、罚时、车况和赛后结算真实记录。玩法入口见 `GameSession.Racing.cs`、`RaceSimulation.cs` 及 `GameUi.Racing.cs`。

## 随机事件及插图工作进度

保留的随机池有 120 项 C# 事件，使用原 01–126 的验收编号。102 并入 09，104／108／110 取消，125／126 是独立流程。主线与赛车入门不算入此次随机事件清单。事件使用真实库存、现金、工作时段、场所及 NPC 关系。作弊工具可按编号分批触发供人工验收。换机后要找事件，不需要重建事件库，直接按 [编号](98-random-event-index.md)、[各分支与条件](100-random-event-details.md)、[调度与验收入口](99-random-event-handoff.md) 继续。

首批插图已经放到 `Assets/Resources/EventCg`，UI 通过 `GameUi.EventCg.cs` 从实际事件读取背景、道具、人物和说明。包括门店检查、盘点少货、熟客介绍、学生团购、捡钱包、陈志衡见面／借款、表哥借还款及逾期、停电等。部分结果在同一场景中换道具或切换结果背景，期间到场及还款也使用对应画面。真实 NPC 优先按人物 ID 选站姿或坐姿透明图，缺专用图可使用人物头像。场景、人物和道具按事件状态组合，后续可沿用此结构补其他事件和分支。现有事件玩法全量和首批有插图的范围是两件事，新增插图从 `GameSession.Events.cs` 的现有映射查起。
