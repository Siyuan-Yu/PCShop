# 货架件数与承重双上限（2026-11-03）

轻商品不再仅靠低重量大量陈列。现有三档货架同时受件数与承重限制，任一先到上限就停止上架。

| 货架 | 件数上限 | 承重上限 |
| --- | ---: | ---: |
| 普通货架 | 20件 | 60千克 |
| 加固货架 | 30件 | 100千克 |
| 重型货架 | 40件 | 160千克 |

例如，一架普通货架最多展示20件轻模型或衣服；盒装显卡每盒4千克，仍只能展示15盒。件数按商品实际数量计算，多个型号共享上限，不是每个型号各放20件。

## 陈列、库存与旧存档

- 延续现有按品类汇总陈列的方式：同品类多架的重量与件数分别累加。普通架＋重型架合计60件、220千克；界面明确标为同类合计，不把整类库存写成单架库存。
- 同类通用展示台保留原有1—6件设置，数量与货架相加；普通架＋6件展示台合计最多26件，不再因存在货架而取消件数限制。电脑展示台原有机位规则不变。
- 超出的货继续留在不限容量的后仓。换品类、减少陈列容量和读旧存档都不会删货；卖出后仍自动从后仓补满剩余陈列名额。
- 顾客可买商品、调价清单与库存页继续读取同一陈列结果，限制实际生效，不只是修改文字。后仓商品不因为库存多就全部出现在货架上。
- 旧存档无需增加字段，读取家具目录后应用新上限。旧衣架、叠衣架和旧分品类货架ID继续映射普通货架，采用20件/60千克。

## 界面和代码

库存页同时显示已用/最大千克和已用/最大件数，未选品类的空架也显示上限。货架详情说明本架参数、同类陈列总量、剩余件数名额和后仓余货。购买家具时的说明也列出双上限。详情采用可换行文本，避免长说明挤在单行。

数值集中在 `FurnitureCatalog` 的 `ShelfItems` / `ShelfKg`，无需新增每帧运算。`GameSession.ApplyShelfCapacity` 汇总双上限，`ShelfPlanner.Fill` 生成实际陈列；无限承重的内部调用也必须遵守显式传入的件数限制。未传件数的低层兼容接口保留原有行为，正式店铺由会话层传入有限件数。
