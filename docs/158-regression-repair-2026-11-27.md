## 本轮确认的生产问题

1. **读档让在岗 NPC 错误离岗**：JSON 把可空标识写成空字符串，商店来访恢复将其误认成已失效的真实来访，改成返程状态。规范化 NPC 的可空标识，保留在岗状态及地点。新增读档回归，并验证 20 种鱼的捕获、留存、读档与回收完整链路。
2. **数量控件初始化空引用**：Unity 布局重建触发滑条回调时，数字输入框尚未赋值。初始化期间不处理编辑回调，窗口关闭后也不应用修改。员工采购、家具购买及市场购买的原始报错用例已复测。
3. **等待中的主线邀请读档丢失**：没有当前主线节点时，空字符串被当作无效旧节点，导致清空待发邀请及期限。改为仅在确有节点标识时执行对应迁移。等待三天、睡眠延期、读档与通知一次性已验证。
4. **旧货市场读档生成虚假的待领取物品**：空嵌套对象经 JSON 恢复为默认 `UsedItem`。加载时清除没有有效编号的占位对象，保留真实待领取物品。旧货线索及有效物品保存测试已验证。
5. **音响调试预约被无人值班规则阻挡**：音响助理参加自己的工作预约后不再属于普通值班名单，导致活动不能开始。只对本人实际在其工作场所主持的 `social_49` 预约认可服务资格；普通散客、主持人离场不豁免。开始、读档继续、完成支付 ¥1,500、重复结算拒绝及提前离场不支付已验证。

生产变更位于 `SaveData.CityLife.cs`、`GameUi.Quantities.cs`、`GameSession.Districts.cs`、`GameSession.OldMarketHunt.cs`、`GameSession.VenueBusiness.cs`、`GameSession.VenueServices.cs`。这些文件中部分已有此前开发的未提交修改，不把整个文件差异归为本轮修复。

## 接下来必须继续的工作

1. 未审清的失败继续按原始堆栈复核，不批量修改期待值，也不把 UI 文案或层级变化直接算作玩家故障。
2. 优先复核贷款与买卖房产金额、运输和员工车辆、餐馆价格与购买意愿、客流估算与实际来客差异，以及社交预约到场。它们直接影响开店和经营，不能把这些失败统称为旧 UI 测试。
3. 住院恢复测试预期第 3 天、实际第 2 天，在比较完整存档之前即失败。睡眠和昏倒恢复的缓存前后状态一致已通过，住院场景尚不能作同样结论。
4. UI 剩余断言包括过时文案、富文本标签、配色和窗口层级；另外还有人物脚底与动作、道路美术结构、NPC 资料数量等检查。需要结合现行设计逐项判断，不以旧测试期待覆盖已确认的美术和 UI。员工“同岗位已有一人就应拒绝”断言与现行 `AdditionalEmployees` 支持多人同岗冲突，应继续验证总编制、不覆盖原员工与读档，而非恢复一岗一人限制。
5. 完整游戏性验收仍需完成真实新档的开店、首单、招聘与跨区流程。报价采样、调试预置、自动经营机器人不能冒充真人完整体验。

## 已做检查与边界

本轮包含真实 Unity 组件及按钮回调的测试，但尚未新增人工鼠标／键盘实玩或视觉截图验收。开局预算采样采用正式新档参数（¥15,000、真实地图、无店、做饭教学），只输出租赁、必需家具及从住处出发的交通报价；余额尚未扣运输、进货和生活费，不能作为开店实际利润。

## 游戏性审查的判断原则

- 当前缺口优先是稳定性和反馈清晰度，不默认增加更多经营子系统。公司深度继续遵守 [156 的范围收敛](156-company-equity-and-control-2026-11-27.md)：有限门店、轻量 NPC 公司、已有部门和股权玩法即可。
- 应重点实玩检查“按下开工但世界因另一项教学暂停”“预约时看似可约，到场时无人服务”“公司收到钱但个人钱包没变”等情况是否有足够清楚的就近反馈。修好逻辑不自动等于玩家理解了原因。
- 对餐饮、钓鱼、社交等操作密度，应记录真实操作数与等待时间后判断是否减步骤；暂不据机器人通过率宣称好玩或需要新增大量功能。
- 开店后引导包含招聘、手机、收款码、小电驴、银行和第二间店。应实玩验证是否出现连续催办、主目标不清楚；优先调整提示顺序与可延后事项，不追加新的公司管理层级。
- 本机双镜像并行测试下，现有睡眠／恢复模拟记录约 3.55–5.83 秒（缓存优化路径）。停止其他本轮测试后，单独睡眠复测仍为 5,720.31 毫秒，清空缓存基线为 26,889.25 毫秒，完整持久化状态一致。用户原有编辑器仍保留运行，该值不是发行包性能测量。住院场景另有上述日期断言失败，不能将其状态一致性也算作通过。应优先检查长时间跳转的响应性与可见等待反馈。

## 开局游戏性初步观察

三组正式新档参数采样（种子 7、41、914）均为初始现金 ¥15,000、起步铺位签约 ¥5,000、每周租金 ¥2,000。家具用正式目录原价，余额未扣进货、运输、生活费，未计任何收入。

| 店型 | 必需家具 | 签约及家具后余额 |
| --- | ---: | ---: |
| 电脑、服装、模型店 | ¥900 | ¥9,100 |
| 餐馆 | ¥3,789 | ¥6,211 |
| 二手旧物店 | ¥2,000 | ¥8,000 |
| 宠物店 | ¥1,580 | ¥8,420 |

餐馆在进货前就比电脑店少 ¥2,889 的现金缓冲；这提示需要比较首次开店难度，但还不能据此断定餐馆亏损或必须降价。应实际记录首单时间、前三天净现金与是否被迫反复打工，再决定是否调整开局。

从新档住处按默认交通报价到城郊中介为 98 个游戏分钟，到家具城为 116 分钟，到起步铺位为 90 分钟。这是三条独立单程报价，不是完整开店路线，也不是现实分钟。开店前若反复往返，可能让经营之前的跑腿占比过大。优先考虑现有任务串联、目的地就近提示和购齐清单，先不改变布局或追加交通系统。

从当前内容量看，近期不需要增加大量功能。更有价值的是：让玩家知道当前只需完成哪一步；明确缺岗、教学暂停、预约阻挡的原因；区分公司入账与个人钱包；减少相同采购、运输流程的重复确认。以上为待实玩验证的优化方向，本轮没有擅自修改节奏、数值或界面风格。
