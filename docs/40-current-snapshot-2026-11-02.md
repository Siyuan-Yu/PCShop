- 归档时核对全部241个运行时代码文件，与生成该包的隔离工程完全一致。另核对28个配置文件，湖城数据、主场景与项目设置一致；URP资产仅有Unity构建生成的 `m_Prefilter*` 字段差异，其余渲染设置一致。文档中的后续剧情设计不代表已加入游戏。
- 源码、配置、Unity meta、工具、文档、验证报告和实际截图进入 Git。按现有 `.gitignore`，`Builds/`、`Library/`、`Logs/` 等产物/缓存不进入源码仓库；本篇记录本地发行包，不声称已创建 GitHub Release 或上传二进制附件。
- 游戏正常目标帧率仍为60；只有显式性能测试参数会取消上限。旧 WebGL 包不代表此版本，Steam 接入与正式发行未完成。

## 2. 城市、生活与既有经营底座

当前配置为湖城 V13：90个实体地点、1046个道路节点、10个街区标识、4家片区中介、84栋填充住宅（旧居19、公寓18、豪华公寓26、别墅21）。旧地点与旧道路节点身份保留，住所、商铺及交通使用同一真实配置；自营店与家保留独立室内。

南北端最短完整道路为3528单位，按当前步行标定为1440游戏分钟。三段跨区长通道分别约546.95、449.89、525.86单位；两座湖桥目前是封闭景观，不进入导航或手动通行走廊。湖面、岸线、山地、树林、庭院和建筑使用程序化景观；检查覆盖全图连通、旋转后的建筑占地、建筑/道路互不侵占、平地落点和不落入湖面。生成器从 `tools/data/city-layout-v8.json` 重新生成，避免累积扭曲；校验见 `tools/check-lake-city.py`。

保留开局出租屋与¥10,000、租铺装修、实体走路与交通、实际在岗营业、日结工资/加班、店内装机、独立店铺资产、配送和采购历史、城市人物/邀约/场馆、天气穿衣、睡眠与健康、手机/账本、贷款、合同、创作者与投资等既有系统。当前经营总览区分销售、生活、资产、融资及内部转账；净现金变化不冒充利润。完整入口与旧系统规则见 [内容总览](10-current-content.md)。

后仓容量不限，家与各店独立；至少一个纸箱提供B/F存取入口，多箱共用本处后仓。货架实际陈列和运输承重仍有限制；未上架商品不能直接售卖。小/中/大店分别最多8/12/20个货架、4/6/10名员工，旧档超额资产保留但不能继续超额新增。库存页区分已陈列与后仓，定价页只列实际陈列商品，调价确认保存实际金额。营业时间使用整点下拉，支持跨午夜和全天营业；旧档非整点时间保留到玩家主动修改。

## 3. 五类自营店核心

新开店与主售选择为电脑、模型、服装、二手、餐馆。花店、生鲜店、旧食品零售退出新选项，但旧档资产和城市消费/采购地点保留，不强制删除。宠物店方向保留，玩法未定，尚未实施。

| 电脑 | 六类三档、三代共54种配件；第31/91天发布新品，落后一/两代参考价为78%/55%；兼容原装机、配件销售与整机展示。已确认单品售价不随行情强制变动。 |

| 服装 | 约90%顾客只选应季款；两段年度供给事件分别涨35%/50%，库存不会因换季自动消失。 |

二手店每台展示台4个位置，最多暂存20件未售旧物；12位卖家、3类性格、4套循环说辞避免大量文本。收购师智力影响判断准确率（30%＋智力×0.6%，最高90%），可设置日预算、单件上限与风险倾向，实际在岗才代管，鉴定不直接发利润。

餐馆有青菜/鸡蛋/肉末炒饭，基础18/22/28元，可停供或调整菜单倍率。每份耗0.25千克米和1份食材；厨师负责投锅出锅，服务员负责上菜收桌，老板可手动操作。暂停冻结火候，倍速使用同一时钟；付款、扣料和旧物状态随存档保存，不能重复结算。有未处理专用订单、卖家或旧物时须先处理再转型/退租/搬店。详见 [店型实现](36-shop-core-gameplay-and-supplier-stock.md)。

普通零售仍允许实际陈列的混售；专用餐馆/二手按各自循环经营。随机事件绑定实际门店和陈列品类，电脑情节不无条件套到其他业态。店内员工页展示本店员工、待安排及调入预留；实际在店员工有身份、模型、岗位和交谈入口，同岗多人使用不同站位。

## 4. 采购额度与周历安排

限量属于“具体商家＋具体型号＋每个采购日”，由全部自营店、员工和自采共享；同型号在另一商家独立计数。例如A某显卡20件，可分给三份同日计划6/4/10件；B同型号10件可另外安排。交情影响折扣等关系效果，不增加物理供货。

配置清单时实时扣除其他已保存计划的星期份额，保存再次校验；编辑自身不重复占用，暂停/减少计划释放份额。配置不扣钱或实货；真实采购再扣，运输到货不重扣。固定数量须每个选定日都可分配；“最大”按每个星期的剩余分别分配，并在执行时保护其他未执行计划的份额。

频率只保留每天、周一三五、仅周三，保存后从次日起生效。批发档口、模型/服装批发周末休息；普通生活零售按原营业时间。错过日期不会换到错误的星期补跑；旧每三天计划迁移到一三五。

每商家每SKU稳定限量范围：配件/模型10—25、服装30—75、食材40—100、普通批发20—50、员工家具5—12。部分配件档口有交叉供应，可比较独立价格和额度。现金、运输、起订量、临时紧缺、商品发布和实际库存仍共同限制采购；1788及直供维持各自规则。

兼营零售/批发的常规商品批发最低为零售份数10倍，不能混款凑数；米零售0.25千克、批发袋0.5千克，故5袋/2.5千克起订。少量生活购买走零售价。清单按顺序部分采购，收据保存实际买到的货、费用、时间和退回余款。详见 [星期共享分配](38-supplier-model-allocation-and-weekdays.md)。

## 5. 冰箱与居家工作台

家与店内已摆冰箱中的食品永久保存，容量仍按冰箱档次/台数限制；取出后按剩余保质期继续过期，不恢复成新食物。冰箱外、背包、后仓、在途食品正常计时。每日推进保留冰箱批次的剩余天数，存读档不额外加保鲜天数，旧冷藏字段兼容保留。详见 [永久冷藏](35-permanent-fridge-storage.md)。

家庭经营大屏¥28,000、160千克，家具城购买配送后在家可用。总览、经营、投资、联系人四页连接真实人物状态、账本、库存、人员、采购、定价、订单、资产、投资与联系接口。选择远处分店不移动玩家，也不视为在岗；手工装机/搬货等仍需到场。

生活托管可设置已有饭食优先、外卖档次/日预算、整点睡醒、已有衣物天气换装、后仓食物与每日消耗品取用。真实扣款、消耗批次与预算状态保存去重，缺少设施/资金/库存时提示；待处理事件不被强行睡过去。大屏当前按拥有和在家判定，不做住宅扩容、实体安装与靠近按F启用，编辑器免购买开关不向发行版提供作弊权限。详见 [居家工作台](37-home-workbench.md)。

## 6. 性能与验证边界

树林由全地图大网格改为空间分块，保留景观；普通柜台复用控件、原地更新数字，结构改变才重建。隐藏街道不更新其标签/行人显示；灯光和家具按实际变化更新，货架按真实时间同步；居民每模拟分钟共用员工索引，最近节点使用有界精确坐标缓存。未降低模拟分钟频率或删减经营结算。

## 7. 已确认设计与未实施事项

[剧情总纲、人物支线与四区晋升](story-and-district-progression.md)是本次一并上传的设计决定：从城郊、社区、公园到花园，通过三次引荐和真实合作进入经营圈，人物长期支线、居民日常及可选投资再起共同推进。旧电脑路线不再作为所有店型必须遵循的总主线。

这份设计并未实现完整新剧情/四区晋升条件/创业员工独立开店等长期内容，也不等于封锁公共道路或免费赠店。宠物店、住宅扩容及大屏实体安装、完整界面翻译、统一360/365天长线日历、完整Steam发行流程尚未完成；花店玩法未继续开发。既有功能、已确认设计、待定条件分别记录，后续制作以专题中的实现映射为准。
