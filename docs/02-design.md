# 设计文档 v0.1（创业人生模拟，工作名 PCShopSell）

> 状态：草案。标注 `[默认]` 的是我们尚未明确确认、先按此推进的假设，随时可改。

## 1. 一句话定位

一款 2D、UI 驱动的**创业人生模拟**：从一个靠"手工干活省钱"的小生意起家，逐步雇人、扩张、跨行业，最终建成自己的商业园区。贯穿全程的是**人脉与关系网**（含签约主播、朋友、恋人）和**行情判断**。

### 差异化（按优先级）
1. **成长路径**：每个行业都从"自己动手"开始，靠熟练度换效率，之后花钱买时间（雇人），最后进入管理和资本阶段。
2. **关系即资源**：人脉能换情报、价格、订单、资金，也会因你的成功而变化（人气越高越难留、越难谈恋爱）。
3. **行业有各自的核心张力**，不是换皮；行业之间有联动，形成生态。
4. **终局园区**：把几个行业整合成"电脑乐园"（吃、住、车、电竞、电脑）。
5. 行情判断（硬件价格受币圈、AI 需求、新品周期等虚构宏观因子影响）。

### 不是什么
- 不是"货架摆放"式零售模拟。
- 不是纯 MCN/主播经营游戏。玩家不扮演主播，主播是签约对象。
- 不做 3D。

## 2. 核心体验曲线（所有行业通用的成长阶梯）

| 阶段 | 身份 | 玩法重心 | 关键设计 |
|---|---|---|---|
| L1 手操期 | 个体经营者 | 自己动手干活（装机、摊饼、验车…） | **时间是最稀缺资源**；手操省钱或赚得多；熟练度提升后更快更好 |
| L2 雇人期 | 小老板 | 雇第一个员工，花钱买时间 | 员工有性格和成长，影响质量；玩家腾出时间做采购/行情/社交 |
| L3 管理期 | 店长 | 多员工、分店、排班、仓储、账期 | 现金流压力；管理比手操收益高 |
| L4 帝国期 | 集团老板 | 跨行业、签约主播、投资、人脉运作 | 关系网和资本成为主要玩法 |
| L5 园区期 | 园区主 | 建设并运营整合园区 | 终局内容，综合所有行业 |

**手操永远保留：** 即使后期雇了人，玩家仍可亲自上手（品质更高或应对特殊订单），但不强制。

## 3. 行业规划（控制数量，1.0 目标约 6 个）

每个行业由 **数据模板 + 少量专属模块** 构成。每个行业必须有独特的"核心张力"和"手操玩法"。

| 行业 | 核心张力 | 手操小游戏（轻量 2D） | 雇人后 | 联动 |
|---|---|---|---|---|
| 电脑硬件（含装机） | 行情判断、囤货时机、账期 | 拖拽配件到主板，检查兼容性，计时 | 装机员；玩家专注行情和采购 | 主播带货影响价格；供货给电竞馆 |
| 小吃摊 → 面馆 | 选址、天气、时段人流、证照风险、食材损耗 | 摊饼/煮面，火候与节奏 | 帮工、厨师 | 主播探店；园区餐饮 |
| 花店 | 节日需求暴涨、易腐败、预订 | 插花搭配 | 花艺师 | 送花影响恋爱/关系好感 |
| 二手车商（后期） | 估价、信息不对称、砍价、翻新 | 验车找瑕疵、谈判 | 评估师、销售 | 和"买车/地位"系统联动；园区车辆区 |
| 网吧/电竞馆（中后期） | 上座率、赛事、设备折旧 | 简化为配置和排期，不做手操 | 网管 | **直接采购你的硬件**；园区核心 |
| 民宿/酒店（后期） | 季节性、评价、房态 | 简化为布置和定价 | 前台、保洁 | 园区住宿 |

`[默认]` 1.0 不超过上表规模；其他行业（潮玩、数码回收、美发、健身房、烘焙等）作为后续更新。

## 4. 园区（终局）

- 玩家在后期购入一块地，建设"电脑乐园"。
- 园区由已解锁的行业"落地"为园区内的店铺和设施：电脑商城、电竞馆、餐饮街、民宿/酒店、车辆区（二手车展销、停车）。
- 园区的设计目标：
  - 行业之间互相导流（住客去电竞，电竞选手去餐饮…），玩家为此做布局和招商决策。
  - 园区口碑、管理、安保、活动成为新的经营层。
- `[默认]` 园区在 1.0 做成"布局加招商加运营指标"的轻量版，不做自由建造。

## 5. 横向系统（跨行业共用）

### 5.1 关系网
- 所有 NPC（供应商、客户、员工、主播、朋友、恋人、同行、官员/银行等）共用一套关系数据：好感/信任、立场、记忆。
- 关系可兑换：情报、优惠价、订单、融资、危机援助。
- 恋爱是关系的一种，需要好感和"地位匹配"等条件，有经营后果。`[默认]` 离开/变心可挽回但代价高；恋爱对象可以是签约主播或非签约人物，前者带"公私混淆"代价。

### 5.2 主播/MCN
- 玩家不扮演主播；签约主播后可以"资源投入"（推广预算、流量、礼物等）。
- 主播核心属性：**人气、好感/忠诚、野心**（后续再加压力、合同等）。
- 人气上升带来：带货和代言价值增加，同时身价、野心、挖角风险上升，好感衰减加快。
- 代言费随人气上涨；存在性价比最优区间。
- 可以发展为 MCN 公司（L4 以后）。

### 5.3 地位与车
- 玩家有"地位/形象"属性（资产、公司规模、车、人脉）。
- 车影响通勤效率（省时间）和谈生意/谈判效率（豪车加成），也影响与高人气主播的关系匹配。

### 5.4 行情与投资
- 价格由虚构宏观因子驱动：币圈热度、AI 需求、新品周期、库存缺货、政策/汇率、股市情绪。
- 玩家通过新闻、研报、人脉情报做不完整判断。
- 股票等投资作为 L3 以后的辅助玩法。`[默认]`

## 6. 底座架构（技术）

所有玩法模块都建立在同一套底座上，通过注册数据和规则接入，**互相之间不直接调用**。

| 底座 | 职责 |
|---|---|
| 时间系统 | 日历、每日时间预算、行动占用时间 |
| 账本 | 统一收支、资产负债、现金流 |
| 人物与关系 | NPC 数据、关系值、记忆标记 |
| 事件系统 | 数据驱动：条件、选项、后果 |
| 属性与修正 | 玩家/员工/店铺属性，加成和减益的统一计算 |
| 行业模板 | 商品、成本、客流、员工岗位、升级项的数据配置 + 专属模块钩子 |
| 价格与行情 | 宏观因子 → 品类价格 |
| 存档 | 全状态序列化（通过存档接口，平台可替换） |
| 平台抽象 | 成就、存档、支付、广告、分享做成接口 |

- 代码分层：`Core`（纯 C#，不引用 UnityEngine，可测试）、`Game`（Unity UI 与场景）。
- UI 以代码生成为主，不依赖可视化拖拽。

## 7. 平台与资源规范

- 主目标：Steam（Windows），横屏。`[默认]`
- 预留：iOS/Android、微信小游戏（Unity 官方转换方案，限制见下）。
  - 微信小游戏：主包不超过 4MB，代码包总计不超过 30MB；Unity 堆建议不超过约 500MB；单个资源请求建议 2~5MB 内。
- 为移植预留的约束：
  - UI 不依赖鼠标悬停/右键/复杂快捷键，布局不写死分辨率。
  - 美术用图集和压缩纹理，控制分辨率；角色立绘按需加载。
  - 音频：BGM 短循环、单声道，同时音频数量受控。
  - 资源按 AssetBundle/Addressables 分批加载，避免首包过大。
  - 存档、成就、支付通过接口隔离。

## 8. 合规与美术

- 所有品牌、型号、平台、人物原创或虚构；不影射真人；不照搬竞品 UI/角色/文案。
- AI 美术：登记到 `docs/asset-log.md`；统一风格并人工修整；Steam 内容调查如实披露预生成 AI 内容；不使用实时生成 AI 内容。
- 角色立绘数量受控（首批 3~5 位原创角色）。
- 恋爱和主播内容尺度克制；国内发行相关的合规要求另行核实。

## 9. 垂直切片

### VS1（第一个可玩版本，30~60 游戏日）
- 底座：时间、账本、关系、事件、存档（最小版）。
- 行业：**电脑硬件**（手装机 + 简版行情）与 **小吃摊**（选址/天气 + 手操）。
- 成长：L1 手操 → L2 雇第一位员工。
- 横向：1 位签约主播（人气/好感/野心三属性、一次代言）、1 辆车（效率/形象影响）。
- 目的：验证 (a) 行业模板架构是否成立；(b) 手操到雇人的转变是否有手感；(c) 关系与经营是否互相影响。

### VS2
- 加入花店（节日需求、恋爱联动）、更完整的关系与事件内容。

### 后续
- 二手车商、网吧/电竞馆、民宿、园区、MCN 公司、投资。
